## 같은 범위로 뽑기

전후를 견줄 두 장은 같은 범위, 같은 축척, 같은 해상도로 뽑는다. 그래야 픽셀 크기가 같아 겹쳐 보기의 슬라이더와 차이가 켜진다([output §겹쳐 보기](../steps/60-output.md#겹쳐-보기---나란히-슬라이더-차이)).

- 화면 캡처보다 도구의 내보내기를 쓴다. 범위와 해상도가 고정되고 다시 뽑아도 같다. 명령줄 내보내기가 있으면 그것이 가장 낫다(예: KiCad 의 `kicad-cli pcb export svg`, `kicad-cli sch export svg`)
- 도면은 보일 층과 영역을 고정한다. 전후에서 층 설정이 다르면 바뀌지 않은 것도 바뀐 것처럼 보인다
- 3D 렌더는 카메라 위치, 화각, 출력 크기를 고정한다
- 내보내는 명령이나 설정을 보고서 폴더에 남긴다. 고친 뒤 다시 뽑을 때 그것만 돌린다
- 이전 상태는 기준 커밋의 파일에서 뽑는다. 저장소를 건드리지 않게 `git show <기준>:<경로> > /tmp/before.<확장자>` 나 worktree 로 꺼낸다

## 표시

좌표를 눈대중으로 넣지 않는다.

- 도구 안에 선택 강조나 하이라이트 기능이 있으면 그것을 켜고 뽑는다. 강조가 대상에 정확히 붙는다
- 없으면 `grid_overlay.py` 로 좌표 격자를 얹어 위치를 읽고, `annotate.py` 로 박스와 번호를 그린다. 두 스크립트의 헤더에 쓰는 법이 있다
- 이미지에는 번호만 두고 설명은 캡션으로 뺀다. 도면은 글자가 작고 촘촘해 라벨이 거의 항상 무언가를 덮는다
- 전후 두 장의 표시는 같은 번호를 같은 대상에 준다

## 근거

도면 값을 그림 옆에 적는다. 부품 번호, 넷 이름, 치수, 층 이름, 규칙 검사(DRC, ERC) 결과 줄이다. "선폭을 넓혔습니다"보다 "VBUS 0.3mm -> 0.8mm" 한 줄이 강하다.

## 확인

```bash
python3 -c "from PIL import Image; import sys; [print(p, Image.open(p).size) for p in sys.argv[1:]]" images/*.png
```

- 전후 짝의 크기가 같은가. 다르면 같은 범위로 다시 뽑는다
- 표시가 맞는 대상에 붙었나. 축소된 그림에서 박스가 옆 부품으로 밀리지 않았나
- 작은 글자가 페이지에서 읽히는 해상도인가. 안 읽히면 그 영역만 확대해 한 장 더 싣는다
