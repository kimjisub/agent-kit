# 값과 출력

**로드 시점 - Step 1 에서 재료가 쿼리 결과, 명령 출력, 로그, 측정값일 때.** 그것을 표나 차트로 그리는 법은 [bottlenecks §차트, 비율 띠](../catalogs/bottlenecks.md#차트-비율-띠).

| 부모(SKILL.md 절차) | 이 문서 |
|---|---|
| 1 재료 | 원본째로 남기기, 숫자를 페이지로 옮기기 |
| 4 확인 | 이 문서 끝의 확인 절 |

## 원본째로 남기기

- 결과를 `data/` 에 원본 형식 그대로 둔다(csv, json, txt). 화면에 찍힌 표를 옮겨 적은 것은 원본이 아니다
- 어떤 명령이나 쿼리로 뽑았는지 같은 이름으로 남긴다(`data/orders.sql` 과 `data/orders.csv`). 페이지의 근거 칸에도 적는다
- 언제 뽑았는지 시각을 적는다. 운영 데이터는 시간이 지나면 다른 값이 나온다
- 데이터는 읽기만 한다. 사례를 만들려고 바꾸는 것은 사용자 확인 뒤다(SKILL.md 정책)
- 운영 데이터와 시연, 개발 데이터를 섞지 않는다. 어느 쪽인지 페이지에 적는다

## 숫자를 페이지로 옮기기

- 페이지의 숫자와 차트는 원본 파일에서 스크립트로 만든다. 손으로 옮기면 한 자리씩 틀린다([build §새 부품을 만들 때](../steps/40-build.md#새-부품을-만들-때))
- 셀 수 없으면 셀 수 없다고 쓴다. 비슷한 값을 짐작해 넣지 않는다
- 비율에는 분모를 함께 적는다. "73%" 보다 "1,819건 중 1,328건(73%)"이 읽힌다
- 로그와 긴 출력은 전부 싣지 않는다. 논점인 줄만 근거 칸에 두고 전체는 `<details>` 로 접는다

## 확인

- 페이지의 숫자 두세 개를 원본 파일에서 다시 세어 맞는지 본다
- 차트의 축과 단위, 기준 시각이 적혀 있나. 막대가 0 에서 시작하나
- 합계가 있으면 부분의 합과 맞나
