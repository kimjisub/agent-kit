## 범위 고르기

이번 작업이 시작되기 직전 커밋을 기준으로 잡는다.

```bash
git log --oneline -30
git diff --stat <기준>..HEAD
```

- 여러 세션이 같은 저장소를 다루면 내 작업과 남의 작업이 섞여 있다. `git log --author` 나 파일 경로로 걸러 내가 손댄 것이 시작되기 직전을 잡는다
- 아직 커밋하지 않은 변경을 보일 때는 워킹트리에 남의 변경이 섞였는지 `git status --short` 로 먼저 보고, 내 파일만 경로로 지정한다(`git diff -- <경로들>`)
- 생성 파일, 잠금 파일(`*.lock`, `package-lock.json`), 빌드 산출물은 뺀다. 줄 수만 크고 읽을 것이 없다

## 구간 고르기

`--stat` 결과를 놓고 병목에 걸린 파일과 구간만 고른다. 전부 실으면 받는 사람이 핵심을 직접 찾아야 해서 diff 를 붙여 넣은 것과 다를 바 없다.

- 동작이 바뀐 구간을 먼저 고른다. 이름 바꾸기, 포맷, import 정리만 바뀐 파일은 파일별 줄 수 표에 한 줄로 둔다
- 바뀐 줄 앞뒤의 같은 줄은 `--context`(기본 3) 만큼만 남는다. `diff-html.py` 는 구간 사이에 건너뛴 줄을 「n줄 같음」 한 줄로 보인다. 한 구간이 40줄을 넘으면 논점인 경로만 따로 뽑아 다시 그린다
- 같은 패턴을 여러 파일에 똑같이 적용했으면 대표 하나만 싣고 「같은 변경 n곳」으로 센다

## 의도 붙이기

diff 는 무엇을 바꿨는지만 말한다. 왜 바꿨는지는 그 구간 위에 한 줄로 단다. 출처는 커밋 메시지, 요청 원문, 대화에서 정한 것이다. 출처가 없는 의도를 지어 붙이지 않는다.

- 리팩터처럼 동작이 같아야 하는 변경이면 같은 입력에 같은 출력이 나온다는 근거(테스트 이름과 결과, 비교한 출력)를 함께 둔다
- 고른 방식과 버린 방식이 있으면 [bottlenecks §의도 대조](../catalogs/bottlenecks.md#의도-대조) 로 나란히 둔다
- 문서(Markdown, 기획서) 변경은 줄 단위보다 바뀐 단어가 보여야 읽힌다. `diff-html.py` 가 짝지어 바뀐 줄 안의 단어를 칠한다

## 저장해 둘 것

```bash
git diff <기준>..HEAD -- <경로들> > data/change.diff
git diff --stat <기준>..HEAD > data/change.stat
```

기준 커밋 해시와 경로를 페이지의 근거 칸에 적는다. 받는 사람이 같은 diff 를 다시 뽑을 수 있다.

## 확인

- 줄 번호가 실제 파일의 줄과 맞나. 고른 구간이 기준 커밋 이후의 것인가
- 접힌 구간에 논점인 줄이 들어가 있지 않나
- 의도 한 줄이 그 구간의 실제 변경과 같은 것을 말하나
