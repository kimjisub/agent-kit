# 병목과 수단

**로드 시점 - Step 0 에서 병목을 고를 때, Step 3 에서 고른 수단을 지을 때.** 골라 쓰는 목록이다. 어느 수단이든 지을 때 지킬 공통 규칙은 [build](../steps/40-build.md) 에 있다.

## 병목 표

왼쪽 열에서 읽는 사람이 막히는 자리를 고르고, 오른쪽 열의 수단을 후보로 삼는다. 한 페이지에 병목이 여럿이면 수단도 여럿이다.

| 막히는 자리 | 글로 쓰면 이렇게 된다 | 푸는 수단 |
|---|---|---|
| 어디 얘기인지 모른다 | "설정 화면 두 번째 표의 셋째 열" | 실제 화면에 테두리와 번호, 화면 지도 한 장 |
| 무엇이 바뀌었는지 안 보인다 | "A 를 B 로 바꾸고 C 를 뺐습니다" 열 줄 | 전후 겹쳐 보기, diff |
| 관계와 구조가 안 그려진다 | "X 가 Y 를 부르고 Y 는 Z 에 쓴다" | 구조도, 흐름도, 호출 순서도 |
| 순서와 시간을 못 따라간다 | 단계 나열, 시각이 섞인 로그 | 타임라인, 단계 재생 |
| 조건이 바뀌면 어떻게 되는지 상상이 안 된다 | "켜지면 이렇고 꺼지면 저렇고, 둘 다면..." | 조작 장치, 상태 대조 표 |
| 크기와 비율이 안 느껴진다 | "1,819건 중 73%" | 차트, 비율 띠 |
| 너무 많아 갈피를 못 잡는다 | 글머리표 40줄 | 묶은 요약과 펼치기, 걸러 보는 표 |
| 무엇을 고르고 고르면 어떻게 되는지 모른다 | "A 안과 B 안이 있습니다" | 선택지 비교와 결정 블록 |
| 왜 이렇게 했는지 안 보인다 | "여러 가지를 고려해" | 의도 대조 |
| 믿어도 되는지 모른다 | "확인했습니다" | 근거 칸 |

병목이 표에 없으면 같은 질문을 한다. 읽는 사람이 머릿속에서 무엇을 다시 그리고 있나, 그것을 대신 그려 주면 무엇인가. 답이 수단이다.

## 수단

### 실제 화면에 테두리와 번호

떠 있는 화면이면 찍기 직전에 요소를 글자나 셀렉터로 찾아 테두리와 번호를 그 자리에 그린다(`shot.mjs`, `mark.js`). 이미지 위에는 번호만 두고 설명은 캡션으로 뺀다. 브라우저 밖 이미지는 `grid_overlay.py` 로 좌표를 읽어 `annotate.py` 로 그린다. 쓰는 법은 [screen §화면 안에서 그리는 표시](../variants/screen.md#화면-안에서-그리는-표시) 와 [drawing](../variants/drawing.md).

### 화면 지도 한 장

화면이 넷을 넘으면 그림마다 어디서 온 것인지 말해 주는 지도 한 장을 앞에 둔다. 왼쪽에서 오른쪽이 깊이, 위아래가 같은 깊이의 다른 기능이다. 그리는 법은 [document §화면의 자리와 깊이](../steps/20-document.md#화면의-자리와-깊이).

### 전후 겹쳐 보기

같은 대상을 같은 범위와 축척으로 뽑은 두 장이면 `.pair[data-compare]` 로 나란히, 슬라이더, 차이를 오간다(`compare.js`). 픽셀 크기가 다르면 겹쳐 보기가 꺼지니 같은 범위로 다시 자른다. 쓰는 법은 [output §겹쳐 보기](../steps/60-output.md#겹쳐-보기---나란히-슬라이더-차이).

### diff

바뀐 코드, 문서, 설정을 보일 때. 받는 사람이 코드를 읽는 사람이거나, 바뀐 것이 화면에 드러나지 않을 때 맞는다. 코드를 안 읽는 사람에게는 화면 전후가 먼저이고, diff 는 근거로 접어 둔다.

```bash
git diff <기준>..HEAD -- <경로들> > data/change.diff
python3 scripts/diff-html.py --diff data/change.diff --side --into index.html --id change   # 페이지의 <!--diff:change--><!--/diff:change--> 사이에 넣는다
python3 scripts/diff-html.py old.md new.md > data/doc-diff.html                            # 두 파일을 바로 견준다
```

- 전부 싣지 않는다. 병목에 걸린 파일과 구간만 싣고, 나머지는 파일별 줄 수 표 한 장으로 둔다. 범위를 고르는 법은 [change](../variants/change.md)
- 구간마다 위에 왜 바꿨는지 한 줄을 단다. diff 는 무엇을 바꿨는지만 말한다
- 좌우 대조(`--side`)는 줄이 짝지어 바뀐 경우에, 한 줄 diff 는 줄이 더해지거나 빠진 경우와 좁은 화면에 맞는다

### 구조도, 흐름도, 호출 순서도

관계가 셋을 넘으면 글로는 안 그려진다. 코드나 문서를 읽어 확인한 관계만 그린다.

- HTML 과 CSS 의 상자와 선, 또는 손으로 쓴 SVG 를 페이지에 넣는다. mermaid 같은 라이브러리는 미리 그려 SVG 로 넣는다(CDN 금지)
- 상자가 일곱을 넘으면 나눈다. 바뀐 것과 논점인 것만 색을 주고 나머지는 회색으로 둔다
- 전후가 있으면 같은 배치로 두 장을 그려 겹쳐 보기에 올린다. 상자 자리가 같아야 바뀐 선이 보인다
- 상자에 파일이나 함수 이름을 달고, 근거가 되는 파일과 줄을 캡션에 적는다

### 타임라인, 단계 재생

순서가 논점이면 한 줄 타임라인으로 보이고, 단계마다 화면이나 상태가 바뀌면 단계 재생을 만든다.

- 단계 재생은 이전, 다음 버튼과 방향키로 넘기고, 지금 단계를 강조하고 나머지는 흐리게 둔다
- 처음 상태는 전체 개요다. 인쇄에서는 모든 단계를 펼친다
- 단계마다 실제 로그나 화면을 근거로 붙인다. 시각이 있으면 그 시각을 그대로 쓴다

### 조작 장치

"이 값이 바뀌면 어떻게 되나"가 논점일 때. 토글, 슬라이더, 입력칸을 두고 결과를 그 자리에 그린다.

- 결과는 실제 로직에서 온다. 로직을 JS 로 옮겼으면 옮긴 코드의 출처를 적고, 옮길 수 없으면 실제로 돌려 미리 계산한 결과 표에서 고른다
- 처음 상태는 논점이 가장 잘 드러나는 값으로 둔다
- 경계값(0, 최대, 마감 직전과 직후)에서 결과가 실제와 같은지 Step 4 에서 확인한다

### 상태 대조 표

상태가 몇 개로 끊기면 조작 장치보다 표 한 장이 낫다. 행이 상태, 열이 그 상태를 정하는 값과 그때 보이는 것이다. 칸마다 그 상태의 실제 화면 썸네일을 넣으면 더 빨리 읽힌다. 상태를 만드는 법은 [axes §상태축](../variants/axes.md#상태축---조건-a---조건-b).

### 차트, 비율 띠

숫자가 셋을 넘거나 비교가 논점이면 그린다.

- 막대가 열 개 아래면 CSS 폭(%)으로 그린다. 그보다 많거나 선 그래프면 SVG 로 그린다
- 막대는 0 에서 시작한다. 단위와 기준 시각을 축이나 캡션에 적는다
- 값은 재료 파일에서 만든다([data](../variants/data.md)). 막대 옆에 숫자를 함께 적어 인쇄에서도 읽히게 한다

### 묶은 요약과 펼치기, 걸러 보는 표

항목이 많으면 원인이나 성격으로 묶어 묶음마다 한 줄 요약을 세우고, 세부는 `<details>` 로 접는다. 항목이 수십 개이고 받는 사람이 자기 것만 찾으면 표 위에 검색칸과 열 정렬을 단다. 표는 `.tw` 로 감싼다.

### 선택지 비교와 결정 블록

받는 사람이 정해야 하면 선택지마다 그림과 장단을 두고 결정 블록으로 받는다. 쓰는 법은 [output §결정 받기](../steps/60-output.md#결정-받기).

### 의도 대조

"왜 이렇게 했나"가 논점이면 고른 안을 혼자 두지 않는다. 버린 안과 나란히 놓고, 가른 기준(제약, 요청 원문, 측정값)을 축으로 한 표를 둔다. 요청 원문을 인용하고 그 옆에 대응한 결과를 두면 의도가 결과로 이어지는 것이 보인다.

### 근거 칸

어느 수단이든 옆에 둔다. 저장된 값과 화면 값, 파일과 줄, 명령과 출력을 고정폭으로 나란히 적는다(`.evidence`). 확인 못 한 것은 "(코드 근거)", "(확인 못 함)"으로 단다.
