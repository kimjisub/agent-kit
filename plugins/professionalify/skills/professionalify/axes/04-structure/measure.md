## 측정 방법

```bash
# 내부 식별자 참조: 대문자 1~2자 + 숫자. 업계 표준 이름(S3, PM2, GA4, A4, P1)은 걸린 줄을 보고 뺀다
grep -noE '\b([A-Z]{1,2}-?[0-9]{1,3})\b' <file> | sort -t: -k3 | uniq -c -f2 | sort -rn | head -30
# 개조식 비율
total=$(grep -vc '^\s*$' <file>)
bullets=$(grep -c '^\s*[-*0-9]\+[.)]\?\s' <file>)
tables=$(grep -c '^|' <file>)
echo "불릿+표 $(( (bullets + tables) * 100 / total ))%"

# HTML이면 정의 목록과 표도 개조식으로 센다
grep -oE '<(dl|table|ul|ol)[ >]' <file> | sort | uniq -c
grep -oE '<p[ >]' <file> | wc -l                             # 단락 수와 비교

# 같은 사실의 장 간 반복. 문단, 목록, 표 행 단위로 겹침을 계산한다
python3 axes/04-structure/scripts/section-overlap.py <문서.html> [<런북.html>]
# 중복 메시지 (핵심 키워드를 문서에서 뽑아 넣는다)
for kw in "공급가 1,000만" "사전 검증" "단일안" "런타임 하나"; do
  echo "$kw: $(grep -c "$kw" <file>)회"
done

# 쪽 안내 문장 (문서 안 다른 자리를 가리키는 말)
grep -nE '[0-9]+(~[0-9]+)?쪽(에|을|의)|아래에 (정리|있)|뒤에서 (다룹|설명)|앞서 (말씀|설명)' <file>

# 헤더 형태
grep -nE '^#+ .*(는가|니다|하나|것|길|일|이유|[었았했]나|[가-힣]나|인가|까|다)( \(.*\))?$' <file>     # 문장형, 의문형 헤더 ("왜 만들었나", "무엇인가", "하루가 어떻게 바뀌나")
grep -nE '^#+ .*(무엇|어떻게|왜|언제|어디|누가)' <file>                  # 의문사가 든 헤더. grep 이 놓친 어미가 있어도 여기서 걸린다
# grep 은 어미 목록에 없는 형태를 놓친다. 결과와 별개로 grep -nE '^#+ ' <file> 로 헤더 전체를 뽑아 눈으로 한 번 읽는다
# 표 열 제목 (구분선 바로 위 행). 의문사와 서술형 어미를 잡는다
awk 'prev ~ /^\|/ && $0 ~ /^\| *---/ {print prev} {prev=$0}' <file> | grep -nE '무엇|어디|어떻게|언제|왜|누가|나 *\||것 *\|'
grep -c '^### ' <file>                                       # H3 수
grep -E '^## ' <file> | wc -l                                # H2 수

# 표 컬럼 수 분포 (같은 수가 반복되면 인공 균형 후보)
grep '^|---' <file> | awk -F'|' '{print NF-2}' | sort | uniq -c

# 문서 묶음의 순서와 깊이
ls <dir>                      # 01 이 개요인가. 폴더 깊이가 2 를 넘는가
```

발화 재현은 장마다 논지를 한 줄로 적어 본 뒤 문단마다 그 논지에 기여하는지 O와 X로 표시해 센다. X가 붙은 문단이 하나라도 있으면 그 장은 받아적기로 쓴 것이다.

진행 중계와 자리값은 grep으로 안 잡힌다. 한 곳이 걸리면 문서의 모든 문단에서 첫 문장과 마지막 문장을 읽어 같은 형태를 전부 찾는다. 인용이나 목록, 그림 앞뒤가 특히 몰리는 자리다.

자리값은 grep으로 안 잡힌다. 리드와 첫 화면의 문장을 하나씩 지우고 읽어, 읽는 사람이 할 일이 달라지는지 본다. 안 달라지면 그 문장은 뺀다.

정의 순서는 grep으로 안 잡힌다. 도메인을 모르는 독자를 가정하고 처음부터 읽으며, 문장마다 전제로 쓰인 말(용어, 제품, 서버, 절차 이름)이 그 앞에서 설명됐는지 본다. 걸린 말을 목록으로 적고, 첫 등장 위치와 정의 위치를 나란히 둔다. 정의가 뒤에 있거나 용어집에만 있으면 걸린 것이다.

위계는 grep으로 안 잡힌다. 처음 1쪽만 읽고 "OK / NOT OK를 정할 수 있는가"를 묻는다. 못 정하면 평탄한 것이다.

## 채점 (0~20)

| 점수 | 기준 |
|---:|---|
| 20 | 불릿+표 30% 이하, 중복 메시지 0, 표지 1쪽으로 결정 가능, 문장형 헤더 0 |
| 15 | 불릿+표 35~45% 또는 중복 1~2회 또는 문장형 헤더 1~2개 |
| 10 | 불릿+표 50~60% 또는 중복 3회 이상 또는 위계 평탄. 미디엄 옵션 권장 |
| 5 | 불릿+표 60% 이상 또는 광범위한 중복. 구조 재설계 필요 |
| 0 | 본문 거의 다 불릿과 표. 단락 부재 |

근거는 비율과 횟수로 적는다. "불릿+표 41%, '런타임 하나' 3회, 문장형 헤더 26개".

## 오탐 주의

- **자리값 검사는 문장을 통째로 지워 보는 것이지 겹치는 어절을 덜어내는 것이 아니다.** 버튼 라벨이나 제목과 말이 겹쳐 보여도, 그 문장이 독자에게 주는 것(무엇을 할 수 있는지, 범위가 어디까지인지)이 다르면 자리값이 있다. 2026-09-18 실측: 메일 첫 화면의 "발표와 Q&A 전체의 전사본은 PLAUD에서 보실 수 있습니다"를 버튼("PLAUD 전사본 보기")과 겹친다고 보고 상태 서술로 바꿨더니 사용자가 "이전 문장이 더 나아 보이는데"로 되돌렸다. 버튼은 동작 이름이고 문장은 범위를 약속한다. 둘은 겹치지 않았다.
- **새 신호를 넣은 직후에는 적용할 자리를 찾으려는 편향이 생긴다.** 그 회차에 그 신호로 고친 것이 하나뿐이면 고치기 전에 한 번 더 지워 보고 판단한다.

- 견적, 일정, 체크리스트, 책임 매트릭스, 진짜 병렬 항목은 표와 불릿이 맞다. 비율만 보고 단락으로 바꾸지 않는다.
- 중복 grep의 키워드는 손으로 고른다. 문서를 한 번 읽고 핵심 메시지 셋에서 넷을 뽑아 그 구절로 센다. 2026-09-18 실측: 방향성 문서에서 "envelope" 21회는 용어라 중복이 아니고, "런타임 하나" 1회, "세 번째 복제본" 1회가 메시지였다. 용어 빈도와 메시지 반복을 가른다.
- 항목이 실제로 셋이면 셋이다. "셋입니다" 선언문만 문제다.
- 고유명사 헤더("IoT Hub")와 관용 명사("결정 요청")는 문장형 헤더가 아니다.
- 회의록, CHANGELOG처럼 시간순 로그인 문서는 위계가 평탄한 것이 정상이다.
