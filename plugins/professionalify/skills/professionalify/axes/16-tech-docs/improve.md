# 축 16. 기술 문서: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

한 문서(또는 절)에 한 종류. 독자의 상황(배운다, 끝낸다, 찾는다, 이해한다)이 종류를 정하고 종류가 어투와 구조를 정한다. 2인칭, 현재형, 능동태. 첫 명령 앞에 전제, 명령 뒤에 기대 결과. 예시는 돌려 보고 넣는다.

## 처방

**종류를 가른다.** 섞인 절을 종류별로 떼어 제자리에 둔다.

| 종류 | 골격 | 어투 |
|---|---|---|
| tutorial | 끝에 만들어지는 것 -> 전제 -> 단계 1..N (각 단계에 명령 + 보여야 할 결과) -> 다음에 배울 것 | "이제 ~합니다. ~가 보입니다." 선택지 없음 |
| how-to | 목표 -> 전제 -> 단계 1..N -> 확인 방법 -> 흔한 실패와 대응 | "~하려면 ~하세요." 배경 설명 없음 |
| reference | 일관된 항목 구조(이름, 타입, 기본값, 설명, 예) x 전부 | 사실만. "~입니다." 의견 없음 |
| explanation | 문제 -> 선택지 -> 결정과 이유 -> 결과와 한계 | "~때문에 ~로 했습니다." 명령 없음 |

**README 골격.** 짧게 넷을 다 담되 절로 가른다.

```
# <이름>
한 줄: 무엇을 하는 것인가

## 5분 안에 돌려 보기          (tutorial, 5단계 이하)
## 설치                        (how-to)
## 사용법                      (how-to 목록 또는 reference 링크)
## 설정                        (reference: 표)
## 어떻게 동작하나             (explanation, 짧게 + 설계 문서 링크)
## 문제가 생기면               (how-to: 흔한 실패)
```

**전제를 첫 명령 앞에.** 버전, OS, 권한, 선행 설치, 네트워크(VPN 등)를 표로.

| 전 | 후 |
|---|---|
| (바로) `kubectl get nodes` | 전제: 사내 VPN 연결, `~/.kube/config`에 `prod-admin` 컨텍스트, 인증서 만료 2027-04-10. 그다음 `kubectl --context prod-admin get nodes` |

**명령 뒤에 결과.** 성공하면 무엇이 보이는지.

```bash
kubectl --context prod-admin get nodes
# 5개 노드가 Ready로 나옵니다. Connection refused면 VPN을 확인하세요.
```

**플레이스홀더를 표시한다.** `<box_id>`, `{site}` 형식으로 통일하고 첫 등장에 설명.

**2인칭 현재형 능동태.**

| 전 | 후 |
|---|---|
| 사용자는 설정 파일을 수정할 수 있다. | 설정 파일을 수정하세요. |
| 파일이 생성됩니다. | 명령이 `state.db`를 만듭니다. |
| 이 옵션은 ~될 것입니다. | 이 옵션은 ~합니다. |

**흔한 실패와 대응.** how-to와 tutorial 끝에. 에러 문구 그대로 + 원인 + 조치.

**용어 통일.** 같은 것은 같은 이름. 문서 첫 절에 용어표 하나("Edge: 현장 수집기. 회의에서는 박스, DCU라고도 부름").

**버전과 갱신일.** 문서 머리 또는 frontmatter에 "기준 버전 v0.2, 갱신 2026-09-18".

**링크.** 상대 링크와 앵커를 검사기로 돌린다. 절 제목을 바꾸면 앵커가 죽는다.

**CLI --help.** reference다. 한 줄 설명, 사용법, 옵션 표(이름, 인자, 기본값, 설명), 예시 둘. 문구는 축 12(동사구, 원인+행동).

**스킬 문서.** `skill-authoring`의 골격(목적, 핵심 원칙, 정책, 전제, 절차, 산출)을 따른다. 이 축은 그 문서가 절차(how-to)와 원칙(explanation)을 섞지 않았는지만 본다.

## 흔한 실수

- 설치 가이드에 아키텍처 설명을 넣는다. 설치하려는 사람은 그것을 건너뛰고, 건너뛰다 단계를 놓친다.
- tutorial에 "A 또는 B"를 넣는다. 배우는 사람은 고를 근거가 없다. 하나로 정해 주고 다른 길은 how-to로.
- 예시를 머리로 쓴다. 돌려 보면 옵션 이름이 바뀌어 있다.
- 전제를 문서 끝 "참고"에 둔다. 첫 명령에서 막힌 사람은 끝까지 안 간다.
- 결과를 안 쓴다. 성공했는지 실패했는지 독자가 모른다.
- 절 제목을 고치고 앵커를 안 고친다.
