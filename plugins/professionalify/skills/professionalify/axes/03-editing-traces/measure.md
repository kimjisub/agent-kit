# 축 3. 편집 흔적: 측정

**로드 시점: 측정과 검증 단계에서.** 켜지는 조건과 왜는 `axis.md`, 고치는 법은 `improve.md`.

## 신호 (7유형)

| 유형 | 어떻게 보이나 | 심각도 |
|---|---|---|
| 1. 삭제 자리 메모 | `~~기존 안~~ (삭제)`, `<!-- 이 단락 제거함 -->`, `(이 항목은 더 이상 유효하지 않음)` | S1 |
| 2. 변경 내역 본문 기재 | `v2에서 추가:`, `(2026-05-25 수정)`, `기존 표를 아래와 같이 갱신`, `(수정됨)` | S1 |
| 3. 옛것과 새것 병치 | `기존에는 5명이었으나 이제 3명이다`(3명만 중요한데), `원래 A로 했다가 B로 변경` | S2 |
| 4. 수정 작업 보고 | `요청하신 대로 ~를 반영했습니다`, `이 섹션을 보강했습니다`, `아래 내용을 추가했습니다` | S1 |
| 5. 화해 잔여물 | `(이미 정함)`, `(확정)`, `TODO`, `(논의 필요)`가 본문 곳곳에 | S2 |
| 6. 안 읽고 쌓은 중복 | 앞 절이 이미 말한 것을 모르고 "정리", "추가 분석" 절을 새로 만들어 반복 | S2 (축 4와 겹침) |
| 7. 포맷 부스러기 | 내용 없는 고아 헤더, 반쯤 바뀐 참조(`features/`를 `planning/`으로 바꾸다 한 곳만 남김), 빈 `---`, 연속 빈 줄 | S3 |

## 측정 방법

```bash
grep -nE "삭제\)|제거함|더 이상 유효하지|~~" <file>                       # 1
grep -nE "v[0-9]+에서|\(수정됨\)|수정\)|갱신|추가:|기존 .*를 아래와 같이" <file>  # 2
grep -nE "기존에는|원래 .*였으나|였다가 .*로 변경|이전에는" <file>            # 3
grep -nE "반영했습니다|보강했습니다|추가했습니다|요청하신 대로" <file>          # 4
grep -nE "\(확정\)|\(이미 정함\)|TODO|\(논의 필요\)|\(미정\)" <file>          # 5
grep -nE "^## (정리|추가 분석|보충)" <file>                                # 6 후보
awk 'BEGIN{b=0} /^\s*$/{b++; if(b>=3) print NR": 연속 빈 줄"} !/^\s*$/{b=0}' <file>   # 7
grep -nE "^#+ " <file> | awk -F: 'NR>1 && $1-prev<=2 {print prev": 고아 헤더 후보"} {prev=$1}'  # 7
```

3유형은 grep이 후보만 준다. 대비 자체가 정보인지(회의록의 번복 기록, CHANGELOG) 눈으로 가른다.

## 채점

steps/scoring.md의 별도 차원이 아니다. 1, 2, 4유형이 하나라도 남으면 톤 일관성에서 5점, 5, 7유형이 남으면 디테일 정확성에서 3점을 뺀다. 6유형은 축 4 중복 메시지로 센다.

## 오탐 주의

- CHANGELOG, 릴리스 노트, 회의록의 "이전 결정 번복", ADR의 "기각된 대안"은 대비가 본문이다. 흔적이 아니다.
- frontmatter의 `supersedes`, `updated`는 이력의 정해진 자리라 흔적이 아니다.
- 진짜 미정을 정해진 한 곳에 `미정` 하나로 둔 것은 흔적이 아니다. 흩뿌린 것이 흔적이다.
- 비교표의 "전 / 후" 열은 대비가 콘텐츠일 때(개선 사례 문서) 맞다.
