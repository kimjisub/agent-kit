# 축 9. 다이어그램: 사례

**로드 시점: 개선 중 처방의 실제 모양이 필요할 때.** 규칙은 `improve.md`가 정본이고 여기는 사례만.

## 우리 사례

### 측정 실측 (2026-09-18, IoT 제품 방향성 문서 mermaid 2개)

노드 23, subgraph 5, 엣지 10개 중 라벨 없는 것 7. 닫는 펜스 다음에 그림을 읽는 문장이 없다. 처방: 라벨 없는 7개 중 프로토콜이 다른 것(MQTT, HTTP, gRPC)에 라벨을 붙이고, 그림 아래에 "Link는 Edge에만 붙고, Edge는 Hub 또는 Hub Cloud 중 하나에만 붙는다"처럼 그림이 말하려는 한 문장을 둔다.

### ASCII 그림을 mermaid로 (2026-09-18, IoT 제품 방향성 문서 6절)

전: 텍스트 박스 그림. 화살표에 라벨이 있었지만 경계가 없고 Link(PCB)가 빠져 있었다.

```
[현장]                          [적재]                         [소비자]
센서 / PLC / 카메라 / ESP32                                     AI 에이전트 (MCP)
      v
IoT Edge --- 전송 --->  IoT Hub  --- 제공 --->   건별 앱
```

후: mermaid flowchart. subgraph 셋(현장, Hub, 소비자), 요소마다 두세 줄(이름, 무엇, 기술), 화살표마다 라벨("envelope (MQTT QoS1 / HTTP)", "경량 페이로드 (MQTT)", "command, shadow desired"), 실선은 데이터, 점선은 제어. Link를 두 경로(Edge 경유, Hub 직결)로 그렸다.

남은 문제: 범례 subgraph가 없다. 실선과 점선의 뜻이 그림 밖 본문에만 있다. 다음 수정에서 넣는다.

### 제품 라인도 (같은 문서)

두 번째 mermaid는 다른 층이다. 데이터 흐름이 아니라 제품 관계(Link, Edge, Hub, Hub Cloud, OS 예약)와 그 위의 건별 앱. 한 그림에 넣지 않고 둘로 가른 것이 층 분리다. 각 상자에 저장소 이름과 이름 변경 방향(iot-os -> iot-edge)을 적어 기술 독자용 Container 층으로 맞췄다.

### 이름 변경 뒤 그림 (같은 문서)

Core -> Hub, OS -> Edge로 바꾼 뒤 mermaid 안의 이름도 같이 바꿨다. `grep -c "Core"`가 1(이름 표)인 것으로 확인했다.

### 구성도 항목을 명사구로 (2026-09-28, 인수인계 서버 구성도)

React Flow 로 그린 서버 구성도 일곱 보기에서 보기 설명 여섯이 질문형("누가 쓰고 무엇에 기대나"), 노트 마흔여 줄과 백업 표 칸 열다섯이 `-다` 로 끝났다. 따옴표 안 한글을 서술어와 의문형 끝으로 grep 해 65개를 찾아 고쳤다. 조사 끝까지 넓힌 두 번째 검사에 25개가 더 걸렸지만 전부 `경로`, `결과`, `필요` 같은 명사라 남겼다. 머리말 부제("조회해 그렸다"), 범례("사용한다", "사람이 손으로"), 영역 부제("WARP 또는 Tailscale 로만 닿는다")처럼 노트가 아닌 자리에도 같은 신호가 있었다.

### ERD 를 관계 수 중심으로 (2026-10-13, 인수인계서 4.7)

처음에는 Prisma 스키마를 파싱해 graphviz 로 컬럼까지 그렸다. "속성은 안 보여줘도 되는데 몇대 몇 관계인지를 설명하는게 중요해"를 듣고 컬럼을 뺐지만 자동 배치가 남아 "시각적으로 좀 아쉬운데?"가 돌아왔다. 연결 테이블 8개를 선 이름으로 접고, 좌표를 정해 직각선과 버스선으로 다시 그리고, 범례와 관계 표를 붙였다. 생성기는 스키마를 읽어 좌표를 정하는 작은 스크립트였다.

## 모범 원본

- C4 model 공식 사이트의 Context / Container 예시(Internet Banking System). 상자마다 [타입], 이름, 설명 세 줄이고 화살표마다 라벨과 프로토콜.
- Structurizr DSL로 만든 다이어그램. 범례가 자동으로 붙는다.

## 반례

- 화살표에 라벨이 없는 아키텍처 도. "A -> B"가 A가 B를 부르는지 B가 A를 부르는지 모른다.
- 색으로 "우리 것"과 "고객 것"을 나눴는데 범례가 없는 그림. 흑백 인쇄에서 같은 회색이 된다.
- Context 그림에 Redis, Kafka, Postgres가 다 들어간 것. 경영진은 그 층을 안 읽는다.
