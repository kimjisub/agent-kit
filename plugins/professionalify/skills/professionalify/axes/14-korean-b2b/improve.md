# 축 14. 한국 B2B와 공공 양식: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

정직한 미확정 표기, 명확한 책임 경계, 사전에 합의된 변경 트리거. 이 셋이 자기 PR보다 큰 신뢰를 만든다. 모르는 것을 안다고 쓰지 않고, 누가 무엇을 안 하는지를 쓰고, 돈이 더 드는 경우를 먼저 말한다.

## 처방

**표지와 기밀 조항.** 표지 하단에 박스 또는 단락으로.

```
[기밀 유지 및 저작권 관련 사항]

본 문서는 계약 체결 이전 단계에서 기술 검토를 목적으로 제공된 자료이며,
문서에 포함된 모든 내용에 대한 저작권 및 지적재산권은 ○○○ 유한책임회사에 있습니다.

수신자는 본 문서를 제공 목적 외로 사용할 수 없으며, 사전 서면 동의 없이
제3자 제공, 복제, 수정, 활용 등을 할 수 없습니다.
```

**위계 기호.** 로마숫자(대분류) -> H1, 아라비아(중분류) -> H2, □ -> 굵은 라벨 + 콜론 또는 H3, ○ -> 불릿, - -> 하위 불릿. 한국 문서 시각감을 지키려면 □, ○를 그대로 써도 된다.

**개조식 종결.**

| 평이체 (메일) | 개조식 (제안서) |
|---|---|
| 사전 답사를 완료했습니다 | 사전 답사를 완료한 상태임 |
| Phase 0 연구를 통해 확정합니다 | Phase 0 연구를 통해 확정함 |
| 별도 견적 산정 후 변경 계약을 진행합니다 | 별도 견적 산정 후 계약 변경 |

한 문서 안에서 하나로 간다.

**책임 분담.**

> 본 프로젝트의 SW, AI 알고리즘 개발은 고객사가 전담하며, 개발사는 현장 전력 및 통신 인프라를 중심으로 HW 시스템 구축을 담당함 (선박 및 해상 구조물 구축 제외).

> 현장 출장 시 선박 임차 등 현지 물류 조율은 고객사가 담당하며, 개발사는 엔지니어링 인력을 파견함.

"A는 ~ 전담, B는 ~ 담당"과 괄호 안 제외 항목이 핵심이다. 약칭 정의는 축 2 improve.md.

**Phase 0 미확정 표기.**

> 아래 항목은 Phase 0 연구를 통해 구체적인 방식, 규격, 부품이 결정되는 설계 변수임. 현 시점에서는 확정된 개발 명세가 아닌 검토 대상 요소임.
> - 방수, 방식 대응 방식 및 외함 소재, 규격
> - 전원 시스템 구성 및 배터리 용량, 규격, 교체 주기
> - 무선 통신 방식 선정 (현장 실측 및 안정성 검증 후 결정)

단계별 확정은 "세부 규격은 Phase 0 연구를 통해 확정함".

**추가 비용 발생 기준.**

| # | 사유 | 처리 방식 |
|---|---|---|
| 1 | 사이트 추가 | 별도 견적 산정 후 계약 변경 |
| 2 | 추가 출장 (발주처 요청, 귀책) | 출장 인건비(할증 포함) 추가 청구 |
| 3 | 요구사항 변경 (장비 구성, 통신 방식, 설치 위치) | 공수 산정 후 변경 견적서 발행, 서면 승인 후 진행 |
| 4 | 기술 범위 이탈 | 별도 협의 |
| 5 | 자연재해 피해 | 보험 적용분은 보험 처리, 초과분은 별도 협의 |
| 6 | 현지 행정 (통관, 관세) | 실비 별도 정산, 업무 처리는 현지 회사 지원 |
| 7 | 장기 운영지원 연장 | 별도 견적 |

**시나리오별 예산.** 자금 소스별로 A(B2G 지원사업, 완전판), B(TIPS, 민간 투자, PoC만), C(대출, 자체자금, 단일 사이트)를 한 표에.

```
| 시나리오 | 총 예산 | 제안가 | 용역 범위 |
| A안 (B2G 10억) | 10억 원 | 1.8~1.9억 | Phase 0~3 |
| B안 (TIPS 5억) | 5억 원 | 0.9~0.95억 | Phase 0~2 (2사이트) |
| C안 (대출 3억) | 3억 원 | 0.54~0.57억 | Phase 0~2 (1사이트) |
```

제안가는 발주처 예산의 18~19%로 일관되게. "예산을 잡아먹는 회사"가 아니라 "사업의 한 파트너" 포지션.

**직접비와 간접비.** 견적표에 행으로 넣는다.

| 항목 | 비율 | 의미 |
|---|---|---|
| 예비비 | 10~12% | 기상, 통신, 장비 손상 등 비정형 비용 |
| 프로젝트 관리 간접비 | 5% | 일정 관리, 고객 보고, 문서화 |
| 법인 보험료 | 2% | 산업별 (해상 작업 상해보험, 사이트 안전보험, 영업배상책임) |
| 기술료 | 2% | 도메인 설계 노하우 |
| 행정, 계약 처리비 | 1% | 계약서 검토, 세금계산서, 통관 |

**표 구성.** 견적표 `항목 / 금액 / 비고`(비고는 진짜 컨텍스트만). 시나리오 요약 `시나리오 / 총 예산 / 제안가 / 범위`. 타임라인 `기간 / 발주처 단계 / 개발사 Phase / 산출물 / 비고`, 기간은 Q1, Q2 분기.

**협의 요청 사항.** 문서 끝에 "감사합니다" 대신.

- 예산 시나리오 확정: A, B, C 중 진행 방향이 확정되는 시점에 정식 계약 절차를 개시함
- 계약서 초안 교환: 표준 용역 계약서 초안을 제출하며, IP 귀속과 범위 외 추가 청구 조항을 사전 합의 후 확정함
- 착수일 협의: Phase 0 착수 시점, 사전 답사 일정

**자기 PR 절제.** "당사의 풍부한 경험과 노하우를 바탕으로" -> "현장 답사는 2026년 4월에 완료된 상태임". "차별화된 솔루션을 제공하여" -> "본 안건은 ○○ 표준 용역 계약서를 기반으로 진행함".

## 흔한 실수

- 개조식과 평이체를 섞는다. 도입부는 "~합니다", 본문은 "~함".
- 추가 비용 기준을 적으면 발주처가 불안해할 거라고 빼 버린다. 반대다.
- 시나리오를 셋 만들면서 범위 차이 없이 가격만 다르게 한다. 범위가 달라야 한다.
- 간접비를 직접비에 숨긴다. 따로 행으로 보이는 쪽이 신뢰를 얻는다.
- 협의 요청 사항을 적고 나서 그 아래 "감사합니다"를 또 붙인다.

## 검증

- `measure.md`의 "있어야 할 문구" grep이 전부 1 이상인지, "없어야 할 문구"가 0인지 본다.
- 종결어미가 하나인지 본다.
- 시나리오 표에서 제안가 / 총 예산 비율이 일정한지 계산한다.

## 공공기관 한 장 보고서

결재선의 읽는 시간이 짧다. 한 장에 용건, 이유와 근거, 사후 조치를 두괄식 개조식으로 담는다.

```
제목: ○○ 추진 계획 보고

□ 용건
  ○ ○○를 ○월 ○일까지 추진하고자 함
□ 이유 및 근거
  ○ (배경) ...임
  ○ (현황) ...로 확인됨
  ○ (필요성) ...가 요구됨
□ 사후 조치
  ○ ○월 ○일 착수, ○월 ○일 중간 보고
  ○ 소요 예산 ○○원 (○○ 예산 항목)
```

원칙은 셋이다. 결론이 첫 블록에 온다. 모든 줄이 "~함 / ~임 / ~됨" 명사형으로 끝난다. 숫자와 날짜는 구체적이고 "빠른 시일 내", "적극 검토"는 쓰지 않는다. 표와 그래프는 근거 블록 안에 한 개까지.

기업 제안서와 다른 점은 자기 회사 소개와 책임 분담이 없다는 것이다. 보고자와 결재자가 같은 조직이라 신뢰 신호가 아니라 결정 속도가 목적이다.
