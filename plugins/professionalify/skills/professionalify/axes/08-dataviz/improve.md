# 축 8. 데이터 시각화: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

색은 마지막에 정한다. 형태를 먼저 고르고, 색에 역할(범주, 순차, 발산, 상태)을 주고, 검증기를 돌리고, 마크를 얇게, 라벨은 골라서, 격자는 물러나게. 데이터가 아닌 잉크는 지운다. 차트 하나에 주장 하나이고 제목이 그 주장이다.

## 처방

**형태를 바꾼다.**

| 전 | 후 |
|---|---|
| 12개월 매출을 파이로 | 선 차트, x축 월 |
| 5개 제품 점유율을 막대 5개 세로로 | 가로 막대, 크기순 정렬 |
| 값 하나("가동률 99.2%")를 게이지로 | 숫자 타일, 옆에 전기 대비 |
| 두 척도(매출, 건수)를 이중 축으로 | 차트 둘을 위아래로, 또는 둘 다 지수화(기준 시점 = 100) |
| 계열 9개 선 차트 | 소형 다중(3x3), 또는 상위 4 + "기타" |
| 척도가 다른 계열을 한 축에 | 합계는 크게 하나, 부분은 소형 다중으로 각자 축. 잉크 하나, 범례 없음, 선 끝에 마지막 값 |
| "91건 중 A 8건, B 10건, C 9건" 을 문장으로 | 크기순 가로 막대. 문장은 그 막대가 말하는 결론 한 줄만 |
| "p95 820ms 에서 310ms, p50 300ms 에서 140ms" 를 문장으로 | 항목마다 전 점과 후 점(dumbbell), 옆에 바뀐 비율. 단위가 다른 지표는 그림을 나눈다 |
| 버전 넷의 지표를 문장으로 이어서 | 선 차트, x 축 버전, 바뀐 시점에 사건 표시 |

**이중 축을 푼다.** 같은 x축을 공유하는 차트 둘을 세로로 쌓는다. 관계를 보이려면 산점도(x = 매출, y = 건수). 둘 다 추세만 중요하면 각각 기준 시점을 100으로 지수화해 한 축에.

**막대를 0에서 시작한다.** 차이가 작아서 안 보이면 막대가 틀린 형태다. 점 차트(dot plot)로 바꾸고 축 범위를 좁힌다. 축이 잘렸음을 명시한다.

**색에 역할을 준다.**
- 범주(정체): 고정 순서의 팔레트. 항목이 늘어도 기존 항목 색은 안 바뀐다. 9번째부터 "기타".
- 순차(크기): 한 색상, 밝음에서 어두움. 무지개 금지.
- 발산(극성): 두 색상 + 중앙 중립 회색. 중앙에 색상 금지.
- 상태: 좋음, 경고, 심각, 위험 네 색은 예약. 계열에 안 쓴다. 아이콘과 라벨이 같이.

**검증기를 돌린다.** 눈으로 색약 안전을 판단하지 않는다. 실패한 쌍은 팔레트 램프에서 다음 단계로 옮겨 다시 돌린다. 6~8 범위는 무늬나 라벨 같은 보조 인코딩이 있을 때만.

**잉크를 뺀다.** 3D, 그림자, 그라데이션, 배경색, 테두리, 진한 격자를 지운다. 격자는 옅은 회색 가로선만. 축선은 데이터 잉크보다 옅게. 데이터 라벨은 최대, 최소, 마지막 값처럼 골라서.

**라벨과 범례.** 계열 2개 이상이면 범례. 4개 이하면 선 끝에 직접 라벨도. 한 계열은 범례 없이 제목이 이름. 텍스트는 텍스트 색(검정 계열)이고 계열색은 옆의 작은 마크가 든다.

**제목을 주장으로.** "월별 매출" -> "3분기부터 매출이 전년 대비 감소". 부제에 무엇을 쟀는지(단위, 기간, 출처).

**축과 단위.** 축 라벨에 단위. y축 눈금은 3~5개. x축 시간은 잘리지 않은 구간, 잘랐으면 왜 그 구간인지 부제에.

**접근성.** 색약과 흑백 인쇄를 위해 범례 + 직접 라벨 + (필요 시) 무늬. 표 보기(같은 데이터를 표로)를 제공. 다크 모드는 색을 뒤집는 것이 아니라 같은 램프에서 다크 표면에 맞춰 다시 고르고 검증기를 다시 돌린다.

**대시보드.** 한 화면에 한눈에. 스크롤 없음. 가장 중요한 것이 왼쪽 위. 필터는 한 줄로 차트 위에. 게이지와 파이는 안 쓴다. 숫자 타일에는 값 + 전기 대비 + 스파크라인.

**실행.** HTML/SVG로 렌더할 것이면 여기서 그리지 않고 `dataviz` 스킬을 부른다. 그 스킬이 형태 -> 색 -> 검증 -> 마크 -> 호버 -> 접근성 -> 렌더 확인 순서로 만든다. 이 축은 결과를 `measure.md`로 다시 잰다.

## 흔한 실수

- 색부터 고른다. 형태와 위계가 안 잡힌 채 색으로 구분하려 한다.
- 이중 축을 "공간 절약"으로 정당화한다. 두 척도를 한 그림에 넣으면 어떤 상관이든 만들 수 있다.
- 막대 축을 잘라 작은 차이를 크게 보인다. lie factor 위반이고 읽는 사람이 눈치채면 나머지 차트도 의심한다.
- 검증기 대신 "이 정도면 구분된다"로 넘어간다. 색약은 인구의 8%다.
- 데이터 라벨을 전부 켠다. 숫자가 필요하면 표를 같이 준다.
- 대시보드에 차트를 12개 넣는다. 한 화면이 아니면 대시보드가 아니다.

## 검증

- `measure.md`의 비타협 규칙 체크리스트를 차트마다 다시 본다.
- 팔레트 검증기를 라이트와 다크 모드 둘 다 PASS까지 돌린다.
- 렌더된 것을 스크린샷으로 열어 라벨 겹침, 잘림, 넘침을 본다.
- 제목이 주장인지, 부제에 단위와 기간이 있는지 본다.
