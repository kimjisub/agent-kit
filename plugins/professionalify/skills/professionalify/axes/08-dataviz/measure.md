# 축 8. 데이터 시각화: 측정

**로드 시점: 측정과 검증 단계에서.** 켜지는 조건과 왜는 `axis.md`, 고치는 법은 `improve.md`.

## 신호

| 신호 | 어떻게 보이나 | 심각도 |
|---|---|---|
| 이중 축 | 한 그림에 y축이 둘. 척도가 다른 두 계열 | S1 |
| 0에서 안 시작하는 막대 | 막대 길이가 값에 비례하지 않음. lie factor > 1 | S1 |
| 형태 오선택 | 시계열을 파이로, 비율을 막대 하나로, 값 하나를 차트로 | S1 |
| 3D, 그림자, 그라데이션 | 데이터가 아닌 잉크 | S2 |
| 진한 격자 | 격자선이 데이터 선과 같은 굵기 | S2 |
| 무지개 순차색 | 크기를 무지개로. 순서가 안 읽힘 | S1 |
| 척도가 다른 계열의 겹침 | 한 y축에 계열 여럿. 한 계열의 큰 점프(대출 −1억, 보증금 +1억)가 나머지를 띠 하나로 눌러 버림 | S1 |
| 범주색 순환 | 9번째 계열에 새 색을 만듦. 필터로 계열이 줄면 색이 바뀜 | S1 |
| 색만으로 구분 | 범례 없고 직접 라벨 없이 색만. 색약과 흑백 인쇄에서 사라짐 | S1 |
| 모든 점에 숫자 | 데이터 라벨이 전부 켜져 있음 | S2 |
| 파이 차트 | 조각 5개 이상, 또는 비교가 목적 | S2 |
| 게이지 | 값 하나를 반원 게이지로. 숫자 하나면 됨 | S2 |
| 축 라벨과 단위 부재 | 무엇을 재는지 없음 | S1 |
| 제목이 주제 | "월별 매출"처럼 무엇인지만. 무엇을 봐야 하는지 없음 | S2 |
| 잘린 시간축 | 추세 차트가 유리한 구간만 | S1 |
| 상태색 오용 | 빨강, 노랑, 초록을 "계열 4"로 씀 | S2 |
| 글로 쓴 수치 | 차트 없이 문장 하나에 단위 붙은 숫자가 셋 이상("91건 중 8건, 10건, 9건", "820ms 에서 310ms, 300ms 에서 140ms"). 읽는 사람이 크기와 차이를 머리로 그린다 | S2 |

## 측정 방법

먼저 차트가 되어야 할 문장을 찾는다. 한 줄에 단위 붙은 숫자가 셋 이상인 줄이다. 코드, 날짜, 경로 안의 숫자는 빼고 읽는다.

```bash
grep -nE '([0-9][0-9,.]*[ ]?(%|ms|초|분|시간|일|건|개|명|원|배|MB|GB|줄|회)[^0-9]*){3,}' <file>
```

show 페이지면 렌더러가 같은 신호를 `✗ text:` 로 낸다(`kit/prose.mjs`).

차트마다 아래 순서로 판정한다.

**형태.** 이 데이터의 일이 무엇인가.

| 데이터의 일 | 맞는 형태 |
|---|---|
| 크기 비교 (몇 개 항목) | 가로 막대, 크기순 |
| 시간에 따른 변화 | 선 (계열 4개 이하, 척도가 비슷할 때만), 그 이상이거나 척도가 갈리면 소형 다중 |
| 부분과 전체 | 100% 누적 막대. 파이는 조각 3개 이하일 때만 |
| 분포 | 히스토그램, 박스플롯 |
| 두 변수 관계 | 산점도 |
| 값 하나 | 숫자 타일 (차트 아님) |
| 극성 (기준 대비 위아래) | 발산 막대, 중앙 0 |
| 격자 (두 범주 x 값) | 히트맵 |

**비타협 규칙 체크리스트.** 하나라도 어기면 S1.

- [ ] y축이 하나다
- [ ] 막대는 0에서 시작한다
- [ ] 범주색은 고정 순서이고 순환하지 않는다 (9번째는 "기타"로)
- [ ] 순차색은 한 색상의 밝기 단계, 발산색은 두 색 + 중립 회색 중앙
- [ ] 계열 2개 이상이면 범례가 있고, 4개 이하면 직접 라벨도 있다
- [ ] 상태색(좋음, 경고, 심각, 위험)은 계열색으로 안 쓰고 아이콘과 라벨이 같이 있다
- [ ] 텍스트는 텍스트 색(계열색 아님)
- [ ] 격자와 축은 데이터보다 옅다

**색 검증.** HTML/SVG면 눈으로 판단하지 않고 `dataviz` 스킬의 `scripts/validate_palette.js`를 돌린다. 색약 Delta E 8 이상이 목표, 6~8은 보조 인코딩이 있을 때만, 정상 시각 15 미만은 실패.

```bash
node <dataviz 스킬 경로>/scripts/validate_palette.js "<hex,hex,...>" --mode light
node <dataviz 스킬 경로>/scripts/validate_palette.js "<hex,hex,...>" --mode dark
```

**렌더 확인.** 검증기는 색만 본다. 스크린샷을 열어 라벨 겹침, 잘림, 넘침을 눈으로 본다.

## 채점 (0~20)

steps/scoring.md의 "디테일 정확성"에 들어간다. 비타협 규칙 위반이 하나라도 있으면 10점을 넘지 못한다.

| 점수 | 기준 |
|---:|---|
| 20 | 형태 맞음, 비타협 규칙 전부 통과, 검증기 PASS, 제목이 주장 |
| 15 | 사소한 것 1~2건 (격자 굵기, 라벨 과다) |
| 10 | 비타협 규칙 위반 1건 또는 검증기 WARN |
| 5 | 이중 축 또는 0 아닌 막대 또는 무지개 |
| 0 | 차트가 데이터를 왜곡함 |

근거는 차트 번호와 규칙으로. "그림 2 이중 축, 그림 4 파이 7조각".

## 오탐 주의

- 선 차트의 y축은 0에서 시작하지 않아도 된다. 막대만 0이다.
- 로그 축은 lie factor 위반이 아니다. 축에 명시돼 있으면.
- 파이 3조각 이하, 부분과 전체가 목적이면 허용.
- 스파크라인(축 없는 작은 추세선)은 축 라벨 부재가 정상이다.
- 상태색을 상태에 쓴 것은 맞다. 계열에 쓴 것만 문제.
