# 축 10. 레이아웃과 타이포그래피: 측정

**로드 시점: 측정과 검증 단계에서.** 켜지는 조건과 왜는 `axis.md`, 고치는 법은 `improve.md`.

## 신호

| 신호 | 어떻게 보이나 | 심각도 |
|---|---|---|
| 본문 크기 이탈 | 인쇄 10pt 미만 또는 12pt 초과, 웹 15px 미만 | S1 |
| 행간 이탈 | 글자 크기의 120% 미만(빽빽) 또는 145% 초과(흩어짐). 한국어는 150\~170%가 적정 | S1 |
| 행 길이 이탈 | 영문 45자 미만 또는 90자 초과, 한국어 35자 미만 또는 55자 초과 | S1 |
| 한글 어절 중간 줄바꿈 | 브라우저 기본값은 한글을 글자 단위로 끊어 "감사합니\|다", "없습\|니다"처럼 어절 한가운데서 줄이 바뀜. HTML, PDF, 화면 전부에서 생김 | S1 |
| 이른 줄바꿈 | 다음 어절이 들어갈 자리가 남았는데 줄이 바뀜. 본문의 `text-wrap: pretty`/`balance`, 문단에만 준 `max-width`가 흔한 원인 | S2 |
| 인쇄에서 사라지는 요소 | 점, 막대, 칸처럼 뜻을 가진 요소를 CSS `background`로 그림. 브라우저 인쇄와 PDF 저장은 기본으로 배경을 빼서 화면에는 있고 인쇄본에는 없음 | S1 |
| 글꼴 혼용 | 본문에 글꼴 셋 이상. 제목과 본문이 어울리지 않는 조합 | S2 |
| 위계 단계 과다 | 제목 크기가 넷 이상. H1과 H2가 구분 안 됨 | S2 |
| 여백 부족 | 문단 사이가 행간과 같음. 절 사이가 문단 사이와 같음 | S2 |
| 강조 혼용 | 한 문단에 볼드, 밑줄, 색, 이탤릭이 같이 | S2 |
| 강조 장치 과다 | 한 쪽에 상자, 색 테두리, 배경색 태그, 코드 칩, 색 점, 알약 칩 같은 장치가 네 종류 이상. 눈이 먼저 볼 곳을 정하지 못하고 꾸민 문서로 읽힌다 | S2 |
| 꾸밈 장식 | 내용과 상관없는 바탕 격자나 점 무늬, 상자 그림자, 강조 발광, 그러데이션, 블록이 떠오르는 등장 움직임, 대문자와 넓은 자간의 고정폭 꼬리표, 라벨과 제목을 옆으로 세운 2단 절 머리, 화면 폭을 채우는 큰 제목. 기기의 어두운 모드를 따라 받는 사람마다 다른 색으로 보이는 것도 여기다. 표준 문서가 아니라 꾸민 화면으로 읽힌다 | S2 |
| 도구 사이의 모양 차이 | 같은 사람이 내는 두 종류의 산출물(화면 페이지와 PDF 문서, 보고서와 슬라이드)이 서로 다른 시기의 모양이다. 한쪽은 흰 바탕과 가는 선, 다른 쪽은 색 띠와 대문자 꼬리표와 색 바탕 상자 | S2 |
| 양쪽 정렬 + 하이픈 없음 | 단어 사이가 늘어나 강이 생김 | S3 |
| 과부 행과 고아 행 | 문단 첫 줄만 쪽 끝에, 마지막 줄만 쪽 머리에. 제목이나 절 머리말만 쪽 끝에 혼자 남음 | S3 |
| 페이지 여백 부족 | 인쇄물 여백 20mm 미만 | S2 |
| 표와 그림이 쪽에 걸침 | 한 쪽에 들어가는 표나 그림이 두 쪽에 나뉨. 쪽보다 긴 표는 나뉘는 것이 맞고, 그때는 다음 쪽에 머리줄이 없거나 표가 통째로 다음 쪽에 밀려 앞 쪽 아래가 비면 신호 | S2 |
| 화면 폭 분기가 인쇄에 걸림 | `@media (max-width: ...)` 를 `screen` 없이 걸어 둠. A4 본문 폭(여백 20mm 면 약 640px)이 휴대폰 분기점(720px 안팎)보다 좁아 종이에 휴대폰 모양이 나옴. 쌓인 단, 메뉴 버튼 자리의 빈 위 여백 | S2 |
| 종이에서 사라지는 내용 | 접힌 `<details>`, 탭 뒤, 펼치기 버튼 뒤의 내용과 바깥 링크의 주소가 인쇄본에 없음. 화면에서는 눌러 열지만 종이에서는 못 연다 | S2 |
| 쪽 번호와 쪽 머리 없음 | 여러 쪽 인쇄본에 쪽 번호가 없고 둘째 쪽부터 무슨 문서인지 안 보임. 한 장만 복사하거나 섞이면 순서와 출처를 잃음 | S3 |
| 밑줄 링크 아닌 것 | 밑줄이 강조로 쓰임 | S3 |
| 밑줄 빈칸 | 채울 자리를 `______`, `_.__` 로 표시. 글자 높이와 겹쳐 잘 안 보이고 자리 수를 세게 하며, 무엇을 채우는 칸인지 모름 | S2 |
| 비어 보이는 쪽을 장식으로 채움 | 첫 쪽이나 절 끝이 비자 요약 상자, 키워드 띠로 채움. 뒤와 같은 말을 반복함 | S3 |

## 측정 방법

한글 줄바꿈은 CSS를 먼저 보고, 렌더해서 센다.

```bash
grep -nE "word-break:\s*keep-all" <css 또는 html>        # 0이면 신호
NODE_PATH=<playwright 경로> node scripts/hangul-breaks.js /abs/path/file.html   # 어절 중간 줄바꿈 수, 0이 목표
NODE_PATH=<playwright 경로> node scripts/early-wraps.js /abs/path/file.html     # 자리가 남는데 끊긴 줄 수, 0이 목표
grep -nE "text-wrap:\s*(pretty|balance)" <css 또는 html>   # 제목 밖에 있으면 신호
grep -c "print-color-adjust" <css 또는 html>                  # 0이고 뜻 있는 background가 있으면 신호
# 배경 없이 인쇄해 본다: Playwright page.pdf({ printBackground: false }) 로 뽑아 화면과 비교
grep -nE "@media[^{]*max-width" <css 또는 html> | grep -v screen   # 나오면 인쇄에도 걸리는 폭 분기
grep -c "<details" <html>; grep -c "details-content\|counter(page" <css>   # details 가 있는데 펴는 규칙이 없으면, 쪽 번호가 0 이면 신호
```

HTML/CSS면 값을 읽는다.

```bash
# 본문 크기, 행간, 글꼴
grep -nE "font-size|line-height|font-family" <css 또는 html> | head -20
# 최대 폭 (행 길이 제어)
grep -nE "max-width|width:.*(ch|em|px)" <css 또는 html> | head
# 제목 크기 단계 수
grep -oE "h[1-6]\s*\{[^}]*font-size:\s*[0-9.]+(px|rem|em|pt)" <css> | sort -u | wc -l
```

행 길이는 렌더해서 센다. 본문 한 줄의 글자 수를 세 줄 평균. 한국어는 공백 포함 35\~55자.

인쇄용 HTML 은 `@media print` 의 루트 글자 크기를 pt 로 바꿔 본다(px x 0.75). 화면용 px 값(예: 9.8px)을 그대로 쓰면 7.4pt 라 본문 크기 이탈이다. `docs` 의 a4 레이아웃은 본문 10pt 다.

PDF와 슬라이드는 렌더 결과를 눈으로 본다.
- 팔을 뻗은 거리에서 본문이 읽히는가 (슬라이드는 회의실 뒤에서)
- 절 사이 여백이 문단 사이 여백보다 큰가
- 제목 단계가 한눈에 몇 개인가 (셋 이하)
- 한 문단에 강조 수단이 몇 종류인가
- 표가 쪽에 걸쳤는가. 긴 표면 쪽마다 머리줄이 있는가
- 쪽마다 번호가 있고, 접힌 것이 펼쳐져 나왔는가

## 채점 (0\~20)

steps/scoring.md의 "디테일 정확성"에 들어간다.

| 점수 | 기준 |
|---:|---|
| 20 | 네 수치 전부 범위 안, 위계 셋 이하, 여백 단계 있음, 강조 한 종류 |
| 15 | 수치 하나 경계 근처 |
| 10 | 수치 하나 이탈 또는 위계 넷 |
| 5 | 수치 둘 이상 이탈. 읽기 피로 |
| 0 | 본문이 읽히지 않음 |

## 오탐 주의

- 마크다운 원본은 대상이 아니다. 렌더러(에디터, GitHub, 위키)가 조판을 정한다.
- 코드 블록은 고정폭이라 행 길이 규칙에서 뺀다.
- 표 안 글자는 본문보다 작아도 된다(90%까지).
- 슬라이드 본문은 18pt 이상이 기준이고 인쇄물 기준을 쓰지 않는다.
- 한국어 행간은 영문 기준(120\~145%)보다 넓어야 한다. 150\~170%를 이탈로 보지 않는다.
