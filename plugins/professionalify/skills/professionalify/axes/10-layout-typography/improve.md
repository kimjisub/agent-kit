# 축 10. 레이아웃과 타이포그래피: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

네 가지(크기, 행간, 행 길이, 글꼴)를 먼저 맞추고 나머지는 그 위에. 여백은 그룹을 만드는 도구다. 위계는 셋까지. 강조는 한 종류. 값은 스케일에서 고르고 매번 정하지 않는다.

## 처방

**네 수치.**

| 항목 | 인쇄 | 웹/HTML | 슬라이드 |
|---|---|---|---|
| 본문 크기 | 10~12pt | 16~20px | 18pt 이상 (24 권장) |
| 행간 | 영문 120~145%, 한국어 150~170% | 같음 | 130~150% |
| 행 길이 | 영문 45~90자, 한국어 35~55자 | 같음 (max-width 60~70ch 또는 640~720px) | 한 줄 25자 이하 |
| 글꼴 | 본문 하나 + 제목 하나 (같아도 됨) | 같음 | 같음 |

한국어 본문은 Pretendard 또는 Noto Sans KR, 코드는 고정폭 하나. 영문 혼용 시 한글 글꼴에 라틴 글리프가 포함된 것을 쓴다.

**HTML 기본값.**

```css
body { font-family: Pretendard, -apple-system, sans-serif; font-size: 17px; line-height: 1.65; }
main { max-width: 68ch; margin: 0 auto; padding: 0 24px; }
h1 { font-size: 2rem; } h2 { font-size: 1.5rem; } h3 { font-size: 1.2rem; }
p + p { margin-top: 1em; } h2 { margin-top: 2.5em; } h3 { margin-top: 1.8em; }
```

**여백을 단계로.** 문단 사이 1em, 소절 사이 1.8em, 절 사이 2.5em. 절 사이가 문단 사이보다 크면 구조가 눈에 보인다.

**위계를 셋으로.** H1(제목), H2(절), H3(소절). H4 이하는 볼드 소제목이나 단락 첫 구절로 대신한다. 크기 비율은 1 : 0.75 : 0.6 정도.

**한글은 어절 단위로 끊는다.** HTML과 PDF 템플릿의 `body`에 기본값으로 넣는다. `keep-all`은 한글을 어절(띄어쓰기) 단위로만 끊고, `overflow-wrap`은 파일명이나 URL처럼 띄어쓰기 없는 긴 문자열이 상자를 넘지 않게 한다. 제목만 `balance`로 줄 길이를 맞춘다.

```css
body { word-break: keep-all; overflow-wrap: break-word; line-break: strict; }
h1, h2, h3 { text-wrap: balance; }
```

**인쇄에도 남게 그린다.** 뜻을 가진 점, 막대, 색 칸은 CSS 배경이 아니라 SVG 도형이나 테두리로 그리고, `body`에 `print-color-adjust: exact`(와 `-webkit-` 접두사)를 둔다. 확인은 배경을 끈 PDF로 한다.

본문에 `text-wrap: pretty`나 `balance`를 걸지 않는다. 마지막 줄을 채우려고 앞 줄을 일찍 끊어서, 자리가 남는데도 줄이 바뀐다. 리드 문단에 따로 준 `max-width`도 같은 증상을 만든다. 넣은 뒤 `scripts/early-wraps.js`로 "다음 어절이 들어갈 자리가 있는데 끊긴 줄"이 0인지 본다.

CSS를 못 쓰는 자리(캔버스, 이메일 클라이언트 일부)는 JS로 어절을 `<span style="white-space:nowrap">`로 감싼다. 넣은 뒤 `scripts/hangul-breaks.js`로 0인지 확인한다.

**빈칸은 이름 붙은 회색 칸.** 채울 자리는 항목 이름(HEX, 서체 이름) 옆에 옅은 회색 칸으로 그린다. 형식은 이름이 알려 주고 자리 수는 규격 예시가 알려 준다. 이름만으로 뜻이 안 통하면(명도 대비) 그 항목이 이 문서에 필요한지부터 묻는다(축 6 "관행에서 옮겨 온 항목").

**빈 쪽은 다음 절을 당겨서.** 쪽이 비어 보이면 요약이나 장식으로 채우지 않고 다음 절을 끌어올린다. 고정 쪽 나눔(`.page`)으로 짠 문서면 쪽 묶음을 다시 짠다.

**강조 하나.** 본문 강조는 볼드 하나. 밑줄은 링크에만, 이탤릭은 한국어에서 안 쓴다(글꼴에 없거나 기울여 놓아 흉하다). 색은 상태나 링크에만.

**정렬.** 본문은 왼쪽 정렬. 양쪽 정렬은 하이픈 처리가 되는 조판(LaTeX, InDesign)에서만.

**쪽 나눔.** 표와 그림은 `break-inside: avoid`. 쪽보다 긴 표를 감싼 그림에는 걸지 않는다. 통째로 다음 쪽에 밀려 앞 쪽 아래가 빈다. 긴 표는 줄(`tr`)에 avoid 를 걸고 `thead { display: table-header-group }` 으로 머리줄을 쪽마다 되풀이한다. 제목과 절 머리말 뒤에 쪽이 바뀌지 않게 `break-after: avoid`. 과부와 고아는 `orphans: 2; widows: 2`. 쪽에서 갈리는 카드는 `box-decoration-break: clone` 으로 조각마다 테두리를 닫는다.

**인쇄 여백.** A4 기준 상하좌우 20~25mm. 제본하면 안쪽 30mm.

**화면용 HTML 을 브라우저 인쇄로 내보낼 때.** 폭 분기는 `@media screen and (max-width: ...)` 로 화면에만 건다. 쪽 번호는 `@page { @bottom-right { content: counter(page) " / " counter(pages) } }`, 둘째 쪽부터의 쪽 머리는 `@top-left` 에 문서 제목을 두고 `@page :first` 에서 뺀다. Chrome 131 이상이 그리고, 인쇄 창의 머리글과 바닥글을 켜도 브라우저의 주소와 날짜 대신 이것이 나온다. 접힌 `<details>` 는 `details::details-content { content-visibility: visible }` 로 펴고, 종이에 안 나와야 할 것은 `.no-print` 로 뺀다. 바깥 링크는 `a[href^="http"]::after { content: " (" attr(href) ")" }` 로 주소를 적되 글이 곧 주소인 링크는 뺀다. 버튼, 메뉴, 떠 있는 도구는 숨긴다. 화면에서 쓰던 옅은 테두리(#e4e4e4)는 종이에서 거의 안 보이니 인쇄에서 한 단계 진하게(#cfcfcf 안팎) 둔다. 확인은 PDF 를 뽑아 쪽마다 본다. 좁은 열이 한 글자씩 꺾이면 `overflow-wrap: anywhere` 를 칸 전체에 건 것이다. 칸에는 `break-word` 를 걸고 `anywhere` 는 코드와 경로에만 건다.

**슬라이드.** 본문 24pt, 제목 32~40pt, 한 줄 25자 이하, 여백 10% 이상. 회의실 뒤에서 읽히는가로 판단.

**PDF 만들 때.** `docs` 스킬(이 키트)이 Chrome headless로 렌더한다. 위 CSS 기본값은 그 a4 레이아웃(`layouts/a4/style.css`)에 들어 있다.

**인쇄할 HTML 은 화면에서도 쪽으로 보이게 한다.** A4 로 나갈 문서를 긴 한 장으로 두면 읽는 사람은 어디서 쪽이 끊기는지 인쇄해 봐야 안다. 쪽마다 `.page`(210mm x 297mm, `overflow: hidden`) 상자로 나누고 쪽 번호를 단다. 인쇄에서는 `@page { margin: 0 }` 과 `.page { break-after: page }` 로 같은 나눔을 쓴다. 쪽마다 어떤 내용이 들어갈지 미리 정하고, 넘침은 `scrollHeight > clientHeight` 로 재서 화면에 붉은 테두리로 띄운다. 헤드리스 브라우저의 `--dump-dom` 으로 넘친 쪽을 셀 수 있다. 넘치면 글자를 줄이지 말고 내용을 덜거나 다음 쪽으로 옮긴다.

**빽빽한 이력서와 보고서는 글자, 행간, 덩어리를 같이 연다.** 본문 9pt 대, 행간 1.5 대에 판단 칸 하나에 서너 문장이 이어지면 읽히지 않는다. 본문 10pt, 행간 1.7, 블록마다 배경 상자와 여백을 주고, 결정이 여럿 섞인 칸은 한 줄에 하나씩 목록으로 푼다.

**문서는 굵기를 아껴 쓴다.** 제목, 숫자, 이름, 번호를 모두 800 이상으로 두면 어디가 중요한지 사라지고 문서가 광고지처럼 보인다. 본문 400, 강조 600, 제목 700 까지만 쓴다. 절 제목은 크게 키우지 말고 작은 회색 라벨(8~9pt, 600, 자간 약간 넓게)에 얇은 선을 붙인다. 묶음은 채운 상자와 색 원 번호 대신 얇은 선과 여백으로 나누고, 번호는 옅은 두 자리 숫자로 둔다. 색은 흑백을 기본으로 하고 포인트 색은 한 자리(번호나 직함)에만 쓴다. 숫자는 `font-variant-numeric: tabular-nums` 로 맞춘다.

**HTML 문서는 표준 문서 모양 하나로.** 흰 바탕, 검은 글, 강조색 하나, 한 단. 단은 그림이 들어가는 폭(라벨 12px 를 지키는 폭, 대개 960px)으로 두고 글줄만 720px(한국어 한 줄 45자 안팎)로 묶는다. 제목은 셋(28/21/17px), 굵기는 700 까지. 라벨과 꼬리표는 본문 글꼴로 쓰고 고정폭은 코드와 경로에만 쓴다. 그림 상자는 흰 바탕에 가는 테두리이고, 핵심은 굵은 테두리, 뜨거운 경로는 강조색 선 하나다. 표는 바깥 테두리 없이 머리 밑 선과 줄 선만 쓴다. 격자 바탕, 그림자, 발광, 등장 움직임, 대문자 꼬리표, 2단 절 머리는 넣지 않는다. 기기의 어두운 모드도 따르지 않는다(`color-scheme: light` 와 밝은 토큰을 고정).

**장식은 만드는 도구에서 걷는다.** 페이지 생성 kit, 문서 템플릿, 테마처럼 산출물을 찍어 내는 도구가 장식을 기본으로 달고 있으면, 산출물 하나를 고쳐도 다음 산출물에 그대로 다시 나온다. 도구의 기본 CSS 를 표준 문서 모양으로 바꾸고, 테마를 고르게 하는 안내(레지스터, 스킨)도 함께 걷는다. 외부에서 가져온 kit 이면 원본은 두고 그 위에 얹는 CSS 에서 덮는다. 고친 뒤에는 시스템을 어두운 모드로 두고 넓은 화면, 좁은 화면, 목차가 붙는 페이지를 각각 찍어 본다. 같은 사람의 산출물을 찍는 도구가 둘 이상이면(화면 페이지 kit 과 PDF 문서 템플릿처럼) 한쪽을 고칠 때 나머지도 같은 모양으로 고친다. 한쪽만 고치면 받는 사람은 고치지 않은 쪽 문서를 "예전 것"으로 읽는다.

## 흔한 실수

- 정보를 더 넣으려고 글자를 줄인다. 글자를 줄이는 대신 내용을 뺀다(축 4).
- 행간을 줄여 쪽수를 맞춘다. 읽기 속도가 떨어져 결국 더 오래 걸린다.
- 제목마다 크기를 다르게 해서 여섯 단계가 된다.
- 강조하려고 볼드 + 색 + 밑줄을 겹친다. 강조가 사라진다.
- 넓은 화면에서 본문이 화면 폭을 다 쓴다. 한 줄 120자가 되면 다음 줄을 못 찾는다.

## 검증

- 렌더 결과에서 본문 한 줄 글자 수를 세 줄 세어 평균이 범위 안인지 본다.
- CSS 값(크기, 행간, max-width)이 표와 맞는지 grep한다.
- 제목 단계 수를 센다.
- 쪽에 걸친 표가 없는지 PDF를 넘겨 본다.
