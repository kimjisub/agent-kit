# 축 13. UI 구성: 사례

**로드 시점: 개선 중 처방의 실제 모양이 필요할 때.** 규칙은 `improve.md`가 정본이고 여기는 사례만.

## 우리 사례

### show 페이지의 결정 블록과 보내기 자리 (2026-10-22)

전: 「추천」 선택지가 처음부터 골라져 있었고, 고르는 것밖에 할 수 없었고, 결정에 그림을 넣을 자리가 없었다(넣어도 렌더 순서 때문에 파일에 안 들어갔다). 목차 패널에는 스크롤로 차는 「지나간 절」 막대와 체크, 「표시 지우기」 가 있었고 보내기는 화면 오른쪽 아래에 떠 있었다. 후: 아무것도 고르지 않은 채 열리고 「추천」 은 꼬리표뿐, 끝에 「직접 쓰기」, 질문 아래 설명 그림과 선택지 그림 카드, 목차 패널 맨 아래에 감시 표시와 「보내기 (n)」. 출처 이 키트의 `plugins/show/skills/show/kit/ask.*`, `report-nav.js`, `reply.js`.

### show 페이지의 의견과 질문 UI (2026-10-21)

구절을 고르면 고정폭 글씨의 「의견」 「질문」 상자 둘이 제목 위에 겹쳐 떴다. 팝오버는 위치 줄이 고정폭이었고 「취소」 「저장」이 같은 테두리 버튼이었다. 저장해도 본문에 흔적이 없었고, 「답 묶기」 검은 버튼, 처리 상태 알약, 알림이 화면 아래 세 자리에 따로 떴다. 대화상자는 보낼 마크다운을 고정폭으로 펼쳐 두었다. 사용자 "드래그로 의견, 질문 이것도 조금 더 디자인을 잘 해줘. 너무 별로다. 그리고 claude 가 응답을 감시하는지도 작은 인디케이터 띄워주면 좋을 것 같고". improve.md 의 「본문 위에 뜨는 주석 UI」와 「보내기 전에 받는 쪽이 듣는지 보인다」대로 다시 짰다. 감시 표시는 서버가 그 페이지의 `wait` 와 `watch` 연결 수를 세어 낸다.

### 측정 실측 (2026-09-18, 옛 IoT 대시보드 src)

| 신호 | 값 | 판정 |
|---|---:|---|
| 인라인 간격 값 | 20, 10, 40, 12, 30, 16px 여섯 종 | Tailwind 스케일과 인라인 px가 공존 |
| Tailwind 임의 값 `-[Npx]` | 17종 | 스케일 밖 값. 대부분 4의 배수로 스냅 가능 |
| 글자 크기 | text-sm 333, text-xs 124, text-lg 63, text-base 6 | 본문이 14px. 스케일 이탈이 아니라 기본값 이동 |
| 색 hex | 43종 | 팔레트 없음. 상태색 3 + 회색 5 + 강조 1로 줄일 수 있다 |
| border | 491 | 구분을 선에 의존. 여백과 배경색으로 대체 후보 |

처방 순서: 색을 팔레트로 모으고(43 -> 10 내외), 임의 값을 스케일로 스냅하고, border를 그룹 단위 배경으로 바꾼다. 세 가지 모두 시각 결과를 스크린샷으로 확인해야 한다.

### Hub 대시보드 초안 (가정, 2026-09-18 방향성 문서 10.2절 기준)

Hub는 GUI가 핵심이 아니지만 상태 화면 하나는 있다. 이 축으로 설계하면 이렇게 된다.

위에 숫자 타일 넷: 마지막 수신 시각, 오늘 수신 envelope 수(전일 대비), 저장소 사용률, HA 상태. 그 아래 왼쪽에 context 트리(site / area / asset), 오른쪽에 선택한 asset의 최신값과 24시간 스파크라인. 필터(site, kind, 기간)는 타일 위 한 줄. 주 행동은 없다(조회 화면). 삭제와 설정은 메뉴 안. 1440x900에서 스크롤 없음.

### 터미널 대시보드의 좁은 화면 (2026-09-28, 사용량 대시보드 TUI)

전: 목록과 그래프를 나란히 세울 폭이 안 되면 그래프 상자가 통째로 사라졌고, 탭 줄이 그 상자 안에 있어 상세, 일정, 판정, 기록, 설정, 도움말에 닿는 표시가 없었다. 80x24에서 단축키 줄은 `[x…` 로 잘렸다. 100x30에서 탭 줄은 `[사용량] 1/8` 로 줄었다.
후: 좁으면 상자 하나에 탭 줄을 늘 두고 목록을 "계정" 탭으로 넣었다. 탭 줄은 `< 사용량 소비 [상세] 일정 >` 처럼 창을 옮기고, 단축키 줄은 두세 줄로 접힌다. 사용량, 소비, 상세 탭 아래에 "대상 2 claude@... (위아래로 변경)". 상세는 PgUp, PgDn. 60x20에서 모든 탭을 키와 클릭으로 확인했다.

### 레거시 대시보드 (iot-dashboard, React)

측정 결과: 간격 값이 17종(4, 5, 6, 8, 10, 12, 13, 14, 15, 16, 18, 20, 24, 30, 32, 40, 48), 글자 크기 9종, 버튼이 전부 primary 파랑. 흑백 스크린샷에서 카드 제목과 값이 같은 무게였다.

처방: 간격을 4의 배수 8단계로 접고, 글자 크기를 5단계로, 카드 안에서 값을 24px 굵게, 라벨을 13px 회색으로. 버튼은 화면당 primary 하나.

### 폼 그룹핑 (레거시 장치 등록 화면)

전: 라벨과 입력 칸 사이 16px, 입력 칸끼리 16px. 어느 라벨이 어느 칸인지 헷갈렸다.
후: 라벨과 칸 6px, 칸끼리 24px, 절(기본 정보 / 통신 설정) 사이 40px. 테두리 상자 없이 여백만으로 그룹이 보인다.

## 모범 원본

- Refactoring UI의 전/후 도판. 같은 화면을 위계, 간격, 색 순서로 고치는 과정.
- Linear, Vercel 대시보드. 회색 스케일 + 주색 하나, 테두리 최소, 여백으로 그룹.
- Stephen Few의 대시보드 예시(Information Dashboard Design 2판). 한 화면, 숫자 + 스파크라인, 게이지 없음.
- Laws of UX (lawsofux.com). 근접성, 피츠, 힉, 밀러 각각 한 쪽.

## 반례

- 모든 카드에 테두리 + 그림자 + 배경색. 깊이가 위계 없이 전부에.
- 버튼 다섯 개가 같은 파랑. 주 행동이 없다.
- 대시보드에 차트 12개, 스크롤 세 화면. 가장 중요한 지표가 두 번째 화면에.
- 회색 텍스트 #AAAAAA를 흰 배경에. 대비 2.3:1.
