# 축 2. 톤과 디테일: 측정

**로드 시점: 측정과 검증 단계에서.** 켜지는 조건과 왜는 `axis.md`, 고치는 법은 `improve.md`.

## 신호

| 신호 | 어떻게 보이나 | 심각도 |
|---|---|---|
| 너무 격식 | "본 제안은 ~ 위함입니다", "~할 수 있도록 노력하겠습니다", "양해 부탁드립니다", "~하겠사오니" | S2 |
| 너무 구어 | "~ 들여다봤습니다", "~ 거의 정리됐고", "~할게요", "~네요", "~하시면 됩니다" 반복 | S2 |
| 조직이 안 쓰는 용어 | 쓰는 사람이 들여온 업계 말("딜", "파이프라인 오너")이 그 조직의 문서와 회의에는 없는데 문서 전체의 기본 단위로 쓰인다. 읽는 사람은 처음 보는 말을 배워야 하고 조직 사람은 어색하게 읽는다. 조직 정본 자료(컬처덱, 용어집)에서 그 말을 세어 0이면 신호 | S2 |
| 대상을 낮추는 어감 | 도구나 팀의 목적을 "~가 일을 더 잘하게 만들려고"처럼 쓰면 그 대상이 지금 일을 못한다는 뜻이 따라온다. "~를 위한 업무 도구", "~가 ~를 더 잘 풀도록 지원한다"처럼 돕는 쪽을 주어로 쓴다 | S2 |
| 지시·결재 어투 | 대등한 외부 협업자(외주, 파트너)에게 위에서 시키는 말투. 개조식 명령("쓰기 전에 공유하고 확인받기", "~할 것"), 의무("~해야 합니다", "~있어야 합니다"), 허락("벗어나도 됩니다", "바꿔도 됩니다", "써도 됩니다"), 결재("확인을 받아 주세요"). 읽는 사람에게 무례하게 읽힘 | S1 (외부) |
| 종결어미 혼용 | 한 문서에 "~합니다"와 "~함"이 섞임. 제안서 개조식과 메일 평이체 혼재 | S1 |
| 표 칸과 괄호 속 한다체 | 본문은 "~합니다"인데 표 칸, 목록, 괄호 속 보충 설명이 "~한다", "~이다"로 끝남. 표 칸을 개조식으로 보고 놔두면 문서 안에서 어체가 둘이 된다. 명사구 종결("원천 기록", "기본 경로")은 혼용이 아니다 | S1 |
| 과장 | "운영 영향 0", "완전 독립", "100% 보장", "절대 안전", "모든 리스크 해결", "즉시 대응" | S1 (법적) |
| 약어 | 첫 사용에 풀어쓰기 없음. SOW, MoU, KPI가 설명 없이 등장. 같은 개념을 약어와 한글로 번갈아 씀 | S2 |
| 내부 조어 | 우리 문서에서만 정의한 이름이 독자에게 그대로 나감. 단계·기법·산출물의 코드네임("프로브를 다시 돌립니다", "앵커가 1,209명입니다"). 판정은 하나 — 독자가 우리 문서를 안 읽고도 그 말을 아는가 | S1 |
| 구현 용어로 쓴 평가 | 결과를 판단할 도메인 전문가가 읽을 평가 · 판정 문서가 파일명, 필드명, 도구 내부 이름(`intent.md`, `cycles.plan`, 게이트, 프로브)으로 쓰여, 「이 정도로 일했구나」를 읽어 낼 수 없다 | S1 |
| 관계 이름 불일치 | 대상을 다른 분야의 관계 이름으로 부름. 구독해 쓰는 SaaS 와 도구를 「거래처」(매입과 매출이 오가는 상대), 사내 도구를 「협력사」로 부르는 식. 판정은 하나 — 읽는 사람이 그 대상을 평소에 뭐라고 부르는가 | S2 |
| 번호 식별자 | 항목에 문서가 매긴 번호(`R41`, `P13`, `Q5.3`)를 붙이고 본문이 그 번호로 서로 부름. 번호의 뜻은 번호를 매긴 자리에서만 풀린다 | S2 |
| 기호 | `§`, `★`, `✓`, `→`, 이모지가 본문 산문에 | S2 |
| 법인격 표기 불일치 | "(주)A사가 B에게". 한쪽은 약식, 한쪽은 없음. 도입부에 약칭 정의 없음 | S1 |
| 작성자 시점 이탈 | 작성자가 직접 수행하거나 아는 사실을 외부 조사자처럼 “~로 기록돼 있다”, “문서상 ~다”, “~한 것으로 보인다”로 서술한다. 작성자가 말하는 사실에 편집자의 자료 열람 시점과 불필요한 유보를 덧씌운다 | S2 |
| 필자의 3인칭 과거 회고 | 필자가 자기 이름을 주어로 "~자리도 홍길동이었습니다", "홍길동이 맡던 범위에는"처럼 과거를 돌아보는 문장. 받는 사람에게 필요한 것은 "이 자리를 이어받는다"인데 문장이 필자를 향한다 | S2 |
| 사람 호칭 혼용 | 한 문서에서 같은 사람을 "홍길동", "길동님", "홍길동님"으로 번갈아 부름. 소개하는 자리가 아닌 본문에 성과 이름이 호칭 없이 나옴 | S2 |
| 시간 표기 혼용 | `2026-05-11`과 `5월 11일`과 `5/11`이 한 문서에. "5월 말까지" 같은 모호한 마감 | S2 |
| 숫자 표기 혼용 | `1,000만 원`과 `10000000원`. VAT 포함 여부 불명. `10 %` 공백 | S2 |
| 자기 PR 어조 | "풍부한 경험을 바탕으로", "차별화된 접근", "최고 수준", "전문성을 발휘하여" | S2 |
| 클로징 | "감사합니다.", "검토 후 의견 주시면 감사하겠습니다.", "언제든 연락 주세요." 누구에게, 무엇을, 언제까지가 없음 | S1 |
| 요구의 말 흐림 | 요구사항을 "어렵다면 ~만이라도", "가능하면", "최소한"으로 흐림. 무엇이 필수인지 읽는 사람이 정하게 됨 | S2 |

## 측정 방법

```bash
# 종결어미 혼용. 셋 중 둘 이상이 0이 아니면 혼용이다
echo "입니다체: $(grep -cE '(니다|세요)[.)]?$' <file>)  한다체: $(grep -E '[가-힣]다[.)]?$' <file> | grep -vcE '니다[.)]?$')  함/임: $(grep -cE '(함|임)\.?$' <file>)"

# 지시·결재 어투 (외부 협업자에게 보내는 문서)
grep -nE '받기|확인을? 받|해야 합니다|있어야 합니다|(써|바꿔|벗어나)도 됩니다|할 것[.)]?$' <file>

# 과장
grep -nE "운영 영향 0|완전 독립|100%|절대|모든 리스크|완벽한|즉시 대응" <file>

# 기호. 목록에 든 몇 글자가 아니라 자판 밖 문자 전부를 잡는다 (영문 자판과 한글 두벌식에서 바로 칠 수 없는 글자)
grep -nP '[^\x00-\x7F\p{Hangul}\x{20A9}]' <file>

# 법인격
grep -nE "\(주\)|주식회사|유한책임회사|유한회사|합자회사" <file>
grep -c "이하 \"\|이하 '\|hereinafter" <file>      # 약칭 정의 존재 여부

# 시간 표기
grep -oE "[0-9]{4}-[0-9]{2}-[0-9]{2}" <file> | wc -l
grep -oE "[0-9]{1,2}월 [0-9]{1,2}일" <file> | wc -l
grep -nE "말까지|초까지|중으로" <file>               # 모호한 마감

# 숫자
grep -nE "[0-9]{5,}원|[0-9] %" <file>              # 콤마 없는 큰 수, 퍼센트 공백

# 화자 시점 후보: 단어 자체는 오류가 아니다. 작성자·출처·확인 범위를 문맥으로 판정한다.
grep -nE "기록돼|기록되어|문서상|기록된|것으로 보|추정" <file>

# 자기 PR
grep -c "풍부한 경험\|차별화\|최고 수준\|독보적\|전문성을 발휘" <file>

# 클로징 (마지막 5줄)
tail -5 <file> | grep -nE "감사합니다|연락 주세요|의견 주시면"
```

체크리스트로 보는 것:
- 도입부에 모든 당사자의 정식 법인격과 약칭("이하 고객사 / 개발사")이 있는가
- 표지, 계약서 제목, 서명란, 법적 책임 조항, 인보이스에는 풀 법인격이 남아 있는가
- 마지막 줄에 누구에게, 무엇을, 언제까지가 있는가

## 채점 (0~20)

톤 일관성과 디테일 정확성은 steps/scoring.md에서 별개 차원이다. 이 축의 측정이 두 차원에 나눠 들어간다.

톤 일관성:

| 점수 | 기준 |
|---:|---|
| 20 | 종결어미 일관, 거리감 적정, 친절 설명 없음 |
| 15 | 일부 혼용이 있으나 의도 명확 (인용문의 구어체 등) |
| 10 | 다수 혼용. 종결어미와 격조 불균형 |
| 5 | 구어체, 격식체, 메일체 섞임 |
| 0 | 톤 일관성 부재 |

디테일 정확성:

| 점수 | 기준 |
|---:|---|
| 20 | 약칭 정의, 법인격, 기호, 과장, 시간, 숫자 표기 전부 OK |
| 15 | 1~2개 잔존 (시각 표기 혼용 등) |
| 10 | 3~4개 잔존 |
| 5 | 5개 이상 |
| 0 | 통일 부재 |

## 오탈 주의

- 로그·타인의 기록을 실제로 인용하거나 원인·현재 상태를 확인하지 못한 경우에는 출처와 유보를 유지한다. 작성자가 아는 사실과 편집자가 새로 추정한 내용을 구분한다.
- 인용문 안의 구어체("두셔도 되고 저희 클라우드를 쓰셔도 됩니다")는 인용이라 맞다.
- 영업 시뮬레이션이나 슬랙 원문을 그대로 옮긴 절은 그 어조가 정보다.
- PoC, API, MQTT 같은 산업 표준 약어는 풀어쓰지 않는다.
- 내부 회의 자료는 법인격 약칭 정의가 없어도 된다. 외부 발송 문서에서만 S1이다.
- `->`(ASCII)는 기호가 아니다. `→`(U+2192)만 문제다.
