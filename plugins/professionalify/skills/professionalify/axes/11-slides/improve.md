# 축 11. 슬라이드: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

한 장에 주장 하나. 제목이 주장, 본문이 증거, 대본은 노트로. 결론이 앞에, 행동 유도가 끝에. 슬라이드는 발표자의 말을 돕는 그림이지 문서의 요약이 아니다.

## 처방

**제목을 주장으로.** 두 줄 이내 문장.

| 전 | 후 |
|---|---|
| 시장 현황 | Industrial DataOps 시장은 2034년까지 연 14.6% 성장 추정 |
| 기술 아키텍처 | Edge가 수집하고 Hub가 쌓는다. 앱은 그 위에 건별로 |
| Q3 실적 | 3분기 매출이 전년 대비 12% 줄었다 |
| 경쟁사 분석 | 대형 공장은 HighByte가 잡고, 연 ○○만원 아래는 비어 있다 |

**불릿을 증거로.** 불릿 목록을 하나의 그림으로 바꾼다.

| 불릿이었던 것 | 증거 형태 |
|---|---|
| 수치 나열 | 막대 또는 숫자 타일 (축 8) |
| 단계 나열 | 흐름도 (축 9) |
| 비교 나열 | 2x2 또는 비교표 (3행 이하) |
| 사례 나열 | 사진 또는 스크린샷 하나 + 캡션 |
| 원인 나열 | 인과 도식 |

불릿이 정말 병렬 항목이면 3개까지, 각 항목 한 줄.

**대본을 노트로.** 본문의 문장을 발표자 노트로 옮기고 슬라이드에는 키워드 셋과 그림만.

**한 장을 둘로.** "그리고", "또한", "한편"이 있으면 장을 나눈다. 장수가 늘어도 발표 시간은 같다.

**순서.** 첫 장 제목, 둘째 장 결론(무엇을 정해 달라는지), 셋째부터 근거, 마지막 장 행동 유도(결정 요청, 다음 단계, 연락처). 배경은 근거 안에서 필요한 만큼만.

**장수.** 발표 시간(분) 이하. 10분이면 10장 이하. 부록은 세지 않는다.

**표.** 3행 이하만 슬라이드에. 그 이상은 핵심 행만 남기고 전체 표는 부록.

**글자.** 본문 24pt 이상, 한 장 120자 이하, 한 줄 25자 이하 (축 10).

**템플릿.** 로고와 배경은 화면의 10% 이하. 페이지 번호는 작게 모서리에.

**문서형 슬라이드.** 읽히는 덱이면 제목 주장 + 본문 2~3문단 + 그림 하나. 축 4의 두괄식과 MECE를 장 순서에 적용한다.

## 흔한 실수

- 문서를 그대로 슬라이드에 붙인다. 슬라이드는 다른 물건이다.
- 제목을 주장으로 바꾸고 본문은 그대로 불릿 여섯 개다.
- 증거를 넣으려고 표 10행을 그대로 넣는다.
- 결론 장을 "결론"이라는 제목으로 마지막에 둔다. 결론은 둘째 장이고 마지막은 행동 유도다.
- 장수를 줄이려고 한 장에 주장을 둘 넣는다. 장수는 문제가 아니다.

## 검증

- `measure.md`의 장별 세 질문을 다시 돌린다.
- 불릿 4개 이상인 장이 0인지 센다.
- 제목 중 주장 문장의 비율을 센다.
- 둘째 장에 결론이, 마지막 장에 행동 유도가 있는지 본다.
