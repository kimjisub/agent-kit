## 우리 사례

### IoT 제품 방향성을 슬라이드로 옮긴다면 (가정, 2026-09-18 문서 기준)

문서 16절을 슬라이드로 만들면 이렇게 된다. 10분 발표, 10장.

| 장 | 제목 (주장) | 증거 |
|---|---|---|
| 1 | IoT 플랫폼 방향 (제목) | |
| 2 | 레거시를 접고 Edge + Hub로 간다. 오늘 정할 것은 첫 도메인 | 결정 요청 한 줄 |
| 3 | 지금 기존 플랫폼은 고객 1명에 서버 12대가 돈다 | 실측 표 3행 (사용자, 디바이스, CPU 4.5%) |
| 4 | 산업 IoT 플랫폼이 아니라 데이터 인프라를 판다 | 포지션 문장 하나 |
| 5 | 연 ○○만원 아래 시장이 비어 있다 | 가격 기준선 막대 (HighByte, UMH, 우리) |
| 6 | Edge가 모으고 Hub가 쌓는다 | mermaid 구조도 (Container 층) |
| 7 | 데이터 타입은 kind 하나 추가로 끝난다 | kind 표 6행 |
| 8 | 두 대로 HA가 된다 | 액티브-백업 도식 |
| 9 | 코드는 고객사 플랫폼 포크에서 시작한다 | 세 코드베이스 비교 3열 x 4행 |
| 10 | 다음 주까지 첫 도메인과 포크 시점을 정한다 | 담당자와 기한 |

문서의 16절이 10장으로 접혔고, 열린 질문 10개는 부록으로 갔다.
