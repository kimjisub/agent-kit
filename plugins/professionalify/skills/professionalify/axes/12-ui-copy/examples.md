# 축 12. 화면 문구: 사례

**로드 시점: 개선 중 처방의 실제 모양이 필요할 때.** 규칙은 `improve.md`가 정본이고 여기는 사례만.

## 우리 사례

### 측정 실측 (2026-09-18, 옛 IoT 대시보드 ko.json 237개)

| 신호 | 값 | 처방 |
|---|---:|---|
| 범용 버튼 "확인", "취소" | 3 + 16 | "확인"은 그 다이얼로그의 동작으로("팀 삭제"). "취소"는 그대로 |
| 에러 문구 | 8건 전부 "X 삭제에 실패했습니다." | 원인과 다음 행동이 없다. "권한이 없어 팀을 삭제하지 못했습니다. 조직 관리자에게 요청하세요"처럼 |
| 어투 | 하세요 36, 합니다 4, 해요 0 | 혼재 없음. 명령형 안내가 기본이라 그대로 |
| 같은 값 복제 | "팀 추가" 24개 키 | 한 키로 모아야 한 번에 고친다 |
| 빈 상태 | "조회된 조직이 없습니다." | 왜 비었는지와 첫 항목을 만드는 길이 없다. "아직 조직이 없습니다. 조직 추가로 시작하세요" |

`src` 전체 grep은 "합니다" 138건을 냈고 그중 134건이 생성된 API 클라이언트 주석이었다. i18n 파일이 있으면 그것만 본다.

### Hub CLI와 MCP 도구 설명 (2026-09-18, IoT 제품 방향성 문서 10.2절)

`iothub cmd busan/tank-1/pump set speed=60 --confirm`처럼 명령이 동사이고 대상이 경로다. MCP 도구 `send_command(path, capability, value, dry_run?)`는 설명에 "dry_run으로 검증만, 실제 전송은 명시적 승인"을 넣어 에이전트가 누르기 전에 무슨 일이 일어나는지 안다. 버튼 규칙이 CLI와 도구 설명에도 같다.

### 레거시 대시보드의 에러 (iot-dashboard)

전: API 실패 시 "오류가 발생했습니다." 토스트 하나.
후(제안): "장치 목록을 불러오지 못했습니다. 서버가 응답하지 않습니다. [다시 시도]". 요청 ID를 토스트 아래 작은 글씨로.

### 화면 밖 설명 (화면에 있는 것만 말한다는 원칙의 원형)

전: 프로필 편집 화면에 "이름과 소속은 프로필에서 고칩니다"라는 안내 문장. 사용자는 이미 프로필 화면에 있다.
후: 문장 삭제. 이름과 소속 칸이 그 화면에 있으니 설명이 필요 없다. 없다면 링크 하나.

### 사용법을 늘어놓은 터미널 화면 (2026-09-30, 사용량 대시보드 TUI)

도움말 탭 밖에 조작 안내와 사용법 21곳이 있었다. 설정, 판정, 기록, 도움말 머리글의 키 안내, 대상 줄의 "(위아래로 변경)", 상세 탭의 "사용  c 로 확인 창을 열어 ..." 와 "기한 규칙  로그인 때 정해짐, 갱신으로 연장 안 됨", 토글 알림의 기능 설명, 빈 상태의 "(조회가 쌓이면 표시)". 지우거나 줄여 남은 것은 확인이 걸린 순간의 셋("u 한 번 더", "한 번 더 누르면 종료", 확인 창의 버튼)이다. 리셋 크레딧처럼 막아야 하는 조작은 설명 대신 3단계 확인 창으로 막았다.

### 터미널 대시보드의 명사형 정리 (2026-09-28, 사용량 대시보드 TUI)

라벨, 기록 항목, 상태, 설정 설명을 명사구로, 도움말 설명문을 `~합니다`로 바꿨다. 옛 표현 29종(갱신함, 창 열음, 붙는 중, 사이클, 쿨다운, 여유차, 아껴둘 ...)을 grep으로 세어 109건에서 화면 노출 0건이 됐다(남은 26건은 코드 주석). 도움말의 `~다.` 종결은 50건에서 0건. 한 기능에 이름이 둘이던 것이 셋 나왔다: 창 미리 열기(사이클), 재전환 간격(전환 쿨다운, 쿨다운), 전환 기준과 전환 여유(전환 임계, 여유차). 기록 파일에 이미 쌓인 옛 문구는 그대로 두고 새 기록부터 바뀌었다.

### 점검 보고의 은유 라벨 (2026-10-06, 하네스 환경 점검 스킬)

비개발자가 읽는 점검 보고를 쉬운 말로 만든다며 API 키를 "열쇠", VPN 을 "통로", DB 스키마 버전을 "판", Exa 검색을 "외부 발굴"로 불렀다. 사용자가 "외부 발굴 열쇠"를 보고 무엇인지 몰랐다. 보고 라벨과 그 라벨을 옮겨 쓰는 판정, 수리 문서에서 "열쇠" 30여 곳, "판"과 "통로" 10여 곳을 실제 이름으로 바꿨다. 남긴 곳은 스크립트 주석과 변경 이력처럼 사용자에게 안 보이는 자리다.

### 어투 통일 (레거시 모바일 앱)

"장치가 연결됐어요"(토스트)와 "연결에 실패했습니다"(에러)가 한 화면에 있었다. 전부 "~했습니다"로.

## 모범 원본

- NN/g Error-Message Guidelines. 심각도별 표면(인라인, 토스트, 배너, 모달), 원인과 행동, 사용자 탓 금지.
- Google Material Design "Writing" 가이드. 2인칭, 현재형, 앞에 중요한 말, 마침표 규칙.
- Apple HIG "Writing". 동사구 버튼, 짧게, 일관되게.
- Mailchimp Content Style Guide. 어투를 상황(성공, 실패, 대기)별로 정한 예.

## 반례

- "정말 삭제하시겠습니까? [확인] [취소]". 무엇이 지워지는지, 되돌릴 수 있는지 없고 버튼이 "확인"이다.
- "데이터가 없습니다 😢". 이유도 행동도 없고 이모지가 있다.
- "저희가 지금 확인하고 있어요!". 1인칭, 해요체, 느낌표. 사람이 답하는 것으로 읽혀 사용자가 기다린다.

### 개인 재무 화면의 풀어 쓴 라벨 (2026-09-21)

읽히게 만든다고 절 제목을 질문으로, 열 머리를 의문사로 썼다. "달마다 얼마 썼나", "어디에", "가진 것 / 갚을 것 / 차이", "낸 횟수 / 지금까지 / 마지막". 지적을 받고 다섯 화면의 이름 자리 60여 곳을 "월별 지출", "지출 항목", "자산 / 부채 / 순자산", "납부 횟수 / 누적 금액 / 최근 결제일"로 바꿨다. 빈 상태 문장과 버튼 동사구는 남겼다. 쉬운 말과 명사구는 부딪히지 않는다. "장부 잔액"은 "기록상"보다 어렵지 않고 옆 열 "확인 잔액"과 짝이 맞는다.
