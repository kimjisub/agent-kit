# 축 12. 화면 문구

## 정의

화면 안의 글이 사용자가 다음에 무엇을 할지 정하게 해 주는가. 버튼, 라벨, 플레이스홀더, 헬프 텍스트, 에러, 빈 상태, 확인 다이얼로그, 토스트. 사용자는 하던 일이 있고 이 문장은 그 사이에 끼어든다.

## 켜지는 조건

웹, 앱, 대시보드, CLI 출력, 설정 화면의 문구를 쓰거나 고칠 때 켠다. 문서, 메일, 슬라이드는 끈다. 화면 구성(배치, 위계, 간격)은 축 13이고 여기는 글자만.

## 왜

사용자는 인터페이스를 읽지 않고 훑는다. NN/g의 버튼 규칙은 "누르면 무슨 일이 일어나는가"를 라벨이 답하는 것이고, "예/아니오"보다 동사구("삭제", "초대 보내기")가 실수를 줄인다. 라벨은 무엇을 넣는 칸인지 의심 없이, 플레이스홀더는 예시 값이지 지시가 아니고, 에러는 심각도에 맞는 표면(토스트, 배너, 모달)에 원인과 다음 행동을 담는다. 화면에 없는 것을 설명하는 문장은 사용자를 화면 밖으로 보내고, 앱이 1인칭으로 말하면 사람인지 자동인지 판단이 하나 더 붙는다. 어투가 한 화면에서 갈리면 어느 것이 공식인지 사용자가 정해야 한다.

출처: NN/g Error-Message Guidelines, "3 I's of Microcopy"(Inform, Influence, Interact), 버튼 라벨 연구(동사구 vs 예/아니오). Google Material과 Apple HIG의 writing 가이드(2인칭, 현재형, 앞에 중요한 말). output style S6(화면에 있는 것만, 조작 자리는 그 조작으로, 에러는 원인과 다음 행동, 어투 하나).

## 경계

- 배치, 위계, 간격, 색은 축 13.
- 문서 안 UI 스크린샷의 캡션은 축 2.
- 에러 메시지 안의 식별자와 추적 정보 설계는 기술 문서(축 16)와 겹친다. 여기는 사용자가 읽는 문장.
- CLI의 `--help` 텍스트는 축 16(reference 문서)과 여기가 같이 본다.

## 읽기 순서

`measure.md`의 요소별 점검(버튼 동사구, 라벨 명사구, 플레이스홀더 예시, 에러 원인+행동, 어투)을 화면마다 돌린다. 개선은 `improve.md`의 요소별 처방. 전/후는 `examples.md`.

변경 이력 파일(`intent.md`)이 있으면 거기에 이 축의 변경 이력이 있다.
