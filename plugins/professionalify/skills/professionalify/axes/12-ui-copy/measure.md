# 축 12. 화면 문구: 측정

**로드 시점: 측정과 검증 단계에서.** 켜지는 조건과 왜는 `axis.md`, 고치는 법은 `improve.md`.

## 신호

| 신호 | 어떻게 보이나 | 심각도 |
|---|---|---|
| 버튼이 "확인", "예", "OK" | 누르면 무슨 일이 일어나는지 라벨에 없음 | S1 |

| 사용법을 화면에 상주 | "위아래: 항목 선택  Enter: 수정", "(위아래로 변경)", "c 로 확인 창을 열어 ... 사용", 토글 알림에 기능 설명을 덧붙임. 조작 순간이 아닌데 조작법이 늘 떠 있음 | S2 |
| 1인칭 앱 | "제가 저장했어요", "저희가 확인 중이에요" | S2 |
| 어투 혼재 | 한 화면에 "~합니다"와 "~해요" | S1 |
| 호칭 | "고객님", "회원님", "귀하" | S3 |
| 느낌표와 이모지 | "저장됐어요!", "🎉" | S2 |
| 확인 다이얼로그 정보 부족 | 무엇이 같이 지워지는지, 되돌릴 수 있는지 없음 | S1 |
| 앞에 중요한 말 없음 | "다음 단계로 진행하시려면 먼저 ..."처럼 핵심이 문장 끝 | S2 |

| 쉬운 말로 풀려다 은유를 지어냄 | API 키를 "열쇠", VPN 을 "통로", 스키마 버전을 "판", 특정 제품의 검색 기능을 "외부 발굴"로 부름. 읽는 사람이 실제 대상과 짝지을 수 없고, 발급 페이지나 설정 화면에 적힌 이름과도 달라 찾아갈 수 없음 | S1 |
| 한 기능에 이름이 둘 이상 | 같은 기능이 단축키 줄, 상태 줄, 기록, 설정, 도움말에서 다른 이름("사이클"과 "창 미리 열기", "전환 임계"와 "임계") | S1 |

## 측정 방법

문구를 뽑아 표로 만든다.

```
| 화면 | 요소 (버튼/라벨/에러/빈 상태/확인) | 현재 문구 | 품사 (동사구/명사구/문장) | 문제 |
```

코드에서 뽑을 수 있으면 뽑는다.

```bash
# React/Vue/HTML 버튼 텍스트
grep -rnoE '<(button|Button)[^>]*>[^<]{1,40}<' src | grep -oE '>[^<]+<' | sort | uniq -c | sort -rn | head -30
# 이름 자리(제목, 열 머리, label)가 서술어나 의문사로 끝남. 빈 상태 title의 "~없습니다."는 문장이 맞으므로 뺀다
grep -rnoE '(<h[1-4][^>]*>|<th[^>]*>|label[=:] ?")[^<"]*(나|까|는가|은가|한다|됨|음|있다|없다|것|에|서)[<"]' src | grep -v 없습니다 | head -30
# 확인/예/OK 버튼
grep -rnE '>(확인|예|OK|Yes|No|아니오)<' src | head
# 에러 문구
grep -rnE "(오류가 발생|잘못된|실패했습니다|Error occurred|Something went wrong)" src | head
# 플레이스홀더가 지시문
grep -rnoE 'placeholder="[^"]*(입력|선택|하세요)[^"]*"' src | head
# 어투 혼재
echo "합니다: $(grep -rhoE '[가-힣]+합니다' src | wc -l)  해요: $(grep -rhoE '[가-힣]+해요' src | wc -l)"
# 1인칭
grep -rnE "제가|저희가|저희는" src | head
# 느낌표 이모지
grep -rnE '[가-힣]!["<]' src | wc -l
```

i18n 파일이 있으면 그 파일 하나만 보면 된다. 위 `src` grep은 생성 코드(`__generated__`, API 클라이언트 주석)를 문구로 세므로, `find src -name "*.json" -path "*locale*"`로 파일을 먼저 찾고 있으면 아래로 바꾼다.

```bash
K=src/locales/ko.json
grep -cE '^\s*"[^"]+":' $K                                             # 문구 수
grep -nE '":\s*"(확인|예|OK|아니오)"' $K                                 # 범용 버튼
echo "합니다: $(grep -cE '합니다' $K)  해요: $(grep -cE '해요|에요|예요' $K)  하세요: $(grep -cE '하세요' $K)"
grep -nE '오류|실패|잘못' $K                                              # 에러 문구 전부 읽는다
grep -oE '":\s*"[^"]{2,12}"' $K | sort | uniq -c | sort -rn | head       # 같은 값이 여러 키에 복제
grep -nE '없습니다|비어' $K                                               # 빈 상태
```

2026-09-18 실측(대시보드 ko.json 237개): `src` grep은 "합니다" 138건을 냈는데 ko.json은 4건이었다. 134건이 생성 코드 주석이었다. 같은 값 "팀 추가"가 24개 키에 복제돼 있었고, 에러 문구 8건이 전부 "X에 실패했습니다."로 원인과 다음 행동이 없었다.

눈으로 보는 것:
- 이 문구를 지우면 사용자가 할 일을 모르는가. 모르면 남기고, 알면 지운다.
- 버튼 앞에서 1초 안에 누를지 말지 정할 수 있는가.
- 에러를 만난 사용자가 같은 조작을 반복할 것인가(원인 없음), 그만둘 것인가(행동 없음).

## 채점 (0~20)

steps/scoring.md의 "톤 일관성"과 "디테일 정확성"에 나눠 들어간다.

| 점수 | 기준 |
|---:|---|
| 20 | 버튼 전부 동사구, 라벨 명사구, 에러에 원인과 행동, 어투 하나, 1인칭 0 |
| 15 | 사소한 것 1~3건 (플레이스홀더 지시문 등) |
| 10 | "확인" 버튼 또는 원인 없는 에러가 있음 |
| 5 | 어투 혼재 + 에러 다수가 "오류가 발생했습니다" |
| 0 | 문구가 사용자를 돕지 않음 |

## 오탐 주의

- 다이얼로그의 취소 버튼은 "취소"가 맞다. 동사구다.
- 라벨이 질문형("알림을 받으시겠습니까?")인 설정 토글은 관례상 허용.
- 마케팅 랜딩 페이지의 카피는 이 축이 아니다. 조작 화면만.
- 개발자 대상 CLI 출력은 내부 코드명이 정보일 수 있다. 최종 사용자 화면만 스택 트레이스를 S1로.
- 영어 UI는 문장 부호와 대소문자 규칙(Title Case vs Sentence case)이 따로 있다. 하나로 통일됐는지만 본다.
