# 축 12. 화면 문구: 개선

**로드 시점: 개선 단계에서, 합의된 범위 안에서.** 무엇을 잴지는 `measure.md`, 실제 전후 모양은 `examples.md`.

## 원칙

화면에 있는 것만 말한다. 조작하는 자리의 문구는 그 조작으로 쓴다. 에러와 빈 상태는 원인과 다음 행동을 준다. 어투는 화면 전체에서 하나로 간다. 지우고 읽어 봐서 사용자가 할 일을 알면 지운 채로 둔다.

## 처방

**버튼과 메뉴는 눌렀을 때 일어나는 일로.**

| 전 | 후 |
|---|---|
| 확인 | 저장 / 삭제 / 초대 보내기 / 결제하기 |
| 예 / 아니오 | 삭제 / 취소 |
| 제출 | 신청하기 / 등록 |
| 다음 | 다음 단계로 (내용이 정해졌으면 그 내용: "주소 입력으로") |

**라벨은 명사구, 플레이스홀더는 예시 값.**

| 요소 | 전 | 후 |
|---|---|---|
| 라벨 | 이메일을 입력하세요 | 이메일 |
| 플레이스홀더 | 이메일을 입력하세요 | example@company.com |
| 헬프 텍스트 | (없음) | 로그인과 알림에 씁니다 |

**이름 자리는 전부 명사구.** 페이지 제목, 절 제목, 열 머리, 지표 라벨, 필터 라벨, 속성 라벨, 범례가 이름 자리다. 질문형이나 풀어 쓴 말은 친절해 보이지만 훑을 때 걸리고 표 머리에서 다른 열과 품사가 어긋난다. 그 분야에 정해진 용어가 있으면 그것을 쓴다. 풀어 쓴 설명이 필요하면 라벨이 아니라 헬프 텍스트나 툴팁으로 내린다.

| 자리 | 전 | 후 |
|---|---|---|
| 절 제목 | 달마다 얼마 썼나 | 월별 지출 |
| 절 제목 | 어디서 본 값인가 | 출처별 최신 값 |
| 지표 라벨 | 가진 것 / 갚을 것 | 자산 / 부채 |
| 열 머리 | 어디에 / 어디서 | 지출 항목 / 결제 수단 |
| 열 머리 | 기록상 / 지금까지 | 장부 잔액 / 누적 금액 |
| 상태 값 | 끝남 / 찾지 못함 | 종료 / 연결 거래 없음 |

버튼은 여전히 동사구이고 빈 상태와 에러는 문장이다. 명사구 규칙은 이름 자리에만 건다.

플레이스홀더만 있고 라벨이 없으면 라벨을 만든다. 입력하면 플레이스홀더는 사라진다.

**에러는 원인 + 다음 행동. 주어는 값.**

| 전 | 후 |
|---|---|
| 오류가 발생했습니다. | 저장하지 못했습니다. 네트워크가 끊겼습니다. 연결을 확인하고 다시 저장하세요. |
| 잘못 입력하셨습니다. | 이메일 형식이 맞지 않습니다. @ 뒤에 도메인이 필요합니다. |
| Internal Server Error (500) | 서버가 응답하지 않습니다. 잠시 뒤 다시 시도하세요. 계속되면 문의 시 코드 E-1042를 알려 주세요. |
| 권한이 없습니다. | 이 장치는 다른 팀 소유입니다. 팀 관리자에게 접근을 요청하세요. |

심각도에 맞는 표면. 입력 하나의 문제는 그 칸 아래 인라인, 저장 실패는 배너, 데이터가 지워지는 것은 모달.

**빈 상태는 왜 비었는지 + 첫 항목 만드는 법.**

| 전 | 후 |
|---|---|
| 데이터가 없습니다. | 아직 등록된 장치가 없습니다. [장치 추가]로 첫 장치를 등록하세요. |
| 검색 결과 없음 | "busan"에 맞는 장치가 없습니다. 철자를 확인하거나 필터를 지우세요. |

**확인 다이얼로그는 무엇이 같이 지워지고 되돌릴 수 있는지.**

| 전 | 후 |
|---|---|
| 정말 삭제하시겠습니까? [확인] [취소] | 장치 "tank-1"과 센서 데이터 30일치를 지웁니다. 되돌릴 수 없습니다. [장치 삭제] [취소] |

**화면 밖 설명을 지운다.** "이름은 프로필에서 고칩니다" 같은 문장 대신, 갈 곳이 필요하면 링크나 버튼으로. 이동 수단이 이미 있으면 아무것도 더하지 않는다. 지운 자리는 빈 채로 둔다.

**사용법은 도움말에, 화면에는 상태와 값.** 조작 안내는 그 조작이 걸린 순간에만 둔다. 확인을 기다리는 동안("u 한 번 더"), 입력을 받는 창 안처럼. 평소 화면의 "위아래: 항목 선택", "Enter: 수정" 같은 키 안내, 값 옆의 "~로 사용하세요", 토글을 켤 때 기능을 설명하는 알림은 지운다. 막는 장치가 필요하면 설명 문장이 아니라 확인 단계(모달)로 만든다. 지운 자리는 비워 둔다.

| 전 | 후 |
|---|---|
| 설정  위아래: 항목 선택  Enter: 수정 | 설정 (수정 중일 때만 "수정 중") |
| 사용  c 로 확인 창을 열어 세 단계 확인 뒤 사용 | (지움. c 를 누르면 확인 창이 뜬다) |
| 자동 전환 켬: 사용 중 계정이 80% 를 넘고 ... 전환합니다 | 자동 전환 켬 |
| 표본 없음 (조회가 쌓이면 표시) | 표본 없음 |

**화면에 보이는 것을 재설명하지 않는다.** 표 위의 "아래 표는 장치 목록입니다"를 지운다. 사용자가 실제로 모르는 것(이 칸에 무엇을 어느 정도로 적어야 하나)만 적는다.

**어투 하나.** `~합니다`체로 통일. `~해요`체와 섞지 않는다. 호칭("고객님")은 뺀다. 대개 주어 없이 문장이 된다. 앱이 1인칭으로 말하지 않는다. "제가 저장했어요" -> "저장했습니다". 느낌표와 이모지는 뺀다.

**앞에 중요한 말.** 사용자는 훑는다. "다음 단계로 진행하시려면 먼저 이메일을 인증하세요" -> "이메일을 인증하세요. 그다음 단계로 갈 수 있습니다."

**능동태.** "파일이 삭제되었습니다" -> "파일을 삭제했습니다". 에러와 확인에서 누가 했는지가 보인다.

**라벨, 상태, 기록 항목은 명사구.** 줄마다 훑는 자리라 서술어가 붙으면 문장으로 읽혀 속도가 떨어지고, 같은 목록 안에서 "갱신함"과 "토큰 갱신"처럼 모양이 갈린다. 결과를 적는 알림은 "무엇: 대상" 꼴이 짧고 대상이 앞에 안 묻힌다. 안내와 에러는 문장이 맞으므로 `~합니다`로 둔다.

| 자리 | 전 | 후 |
|---|---|---|
| 상세 라벨 | 어디서 / 누가 / 받은 시각 | 출처 / 갱신 주체 / 조회 시각 |
| 기록 항목 | 갱신함 / 창 열음 / 창 못 열음: X | 토큰 갱신 / 창 열기 / 창 열기 실패: X |
| 상태 | 백엔드에 붙는 중 / 다시 붙는 중 | 백엔드 연결 중 / 재연결 중 |
| 결과 알림 | a@b.com 로 전환 / a@b.com 다시 보임 | 계정 전환 완료: a@b.com / 숨김 해제: a@b.com |
| 설정 설명 | 이보다 오래된 기록은 지운다 | 이보다 오래된 기록 삭제 |

**정착한 기술 용어는 원어로.** 명사형으로 다듬는 것과 번역하는 것은 다르다. 사용자가 로그, 문서, 에러 메시지에서 원어로 만나는 용어(access token, refresh token, OAuth, API)는 원어로 둔다. 음차("액세스 토큰")는 한 번 더 되짚게 하고 원어로 검색되지 않는다. 가르는 기준은 이 화면을 쓰는 사람이 그 개념을 평소 어떤 말로 부르느냐다. 제목 자리면 첫 글자만 대문자("Access token"), 문장 안이면 소문자로 쓴다.

**쉬운 말은 은유가 아니라 실제 이름과 하는 일이다.** 비개발자에게 보이는 문구를 쉽게 만들 때 기술 용어를 은유("열쇠", "통로", "판")로 바꾸지 않는다. 읽는 사람은 그 은유를 발급 페이지, 설정 화면, 동료의 말에서 만나는 이름과 짝지어야 하는데 짝이 화면 어디에도 없다. 사용자가 실제로 보게 될 이름(발급 페이지 제목 "API 키", 제품명 "Exa")을 그대로 쓰고, 모르는 사람을 위한 풀이는 그 이름 뒤에 하는 일로 붙인다.

| 전 | 후 |
|---|---|
| 발굴 도구 열쇠 | Exa API 키 |
| 외부 후보 발굴만 막힘 | Exa 후보 검색과 웹 리서치만 막힘 |
| 지금 세션은 옛 열쇠를 들고 떠 있습니다 | 지금 세션은 이전 키로 실행 중입니다 |
| 후보 데이터가 예전 판이라 | 후보 데이터가 이전 버전이라 |

**한 기능에 이름 하나.** 기능마다 그 이름이 나오는 자리(단축키 줄, 상태 줄, 기록 종류, 설정 항목, 도움말, CLI 출력)를 전부 늘어놓고 하나로 고른다. 켜고 끄는 기능 이름("창 미리 열기")과 그 기능이 한 번 하는 일("창 열기")은 달라도 되지만, 같은 것을 가리키는 두 이름("사이클", "창 미리 열기")은 안 된다. 설정 항목 이름을 바꿨으면 그 값을 부르는 설명문도 같이 바꾼다.

## 흔한 실수

- 버튼을 동사구로 바꾸면서 길어진다. "새 장치를 등록하고 목록으로 돌아가기"가 아니라 "장치 등록".
- 에러에 원인을 넣으려고 내부 코드명을 노출한다. 원인은 사용자 말로, 식별자는 짧은 코드로.
- 친절하려고 "~해요"체로 간다. 한 화면에 "~합니다"가 남아 섞인다.
- 빈 상태에 일러스트와 격려 문구를 넣고 첫 항목 만드는 법은 안 넣는다.
- 지운 문장 자리를 다른 문장으로 채운다. 빈자리는 그대로 둔다.

## 검증

- `measure.md`의 grep을 다시 돌린다. "확인" 버튼, "오류가 발생" 에러, 1인칭, 느낌표가 0인지.
- 어투 카운트가 한쪽만 남았는지 본다.
- 화면마다 문구를 지우고 읽어 본다. 사용자가 할 일을 알면 지운 채로 둔다.
- 에러마다 원인과 행동이 둘 다 있는지 표로 센다.
