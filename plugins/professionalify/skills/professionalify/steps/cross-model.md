# 교차 다듬기: 다른 회사 모델에게 한 번 더 읽히기

**언제:** 산출물이 바깥으로 나갈 때. 다듬기 1 진단의 「어디로 나가는가」가 외부 발송이나 화면 게시면 다듬기 5 개선 뒤, 6 검증 전에 돈다. 스토어 리뷰 답글, 릴리스 노트, 스토어 설명, 공개 댓글, 고객과 파트너에게 보낼 초안이 여기 든다. 팀 안에서만 읽는 문서와 문장 조각 윤문은 건너뛴다.

**왜:** 다듬은 모델은 자기 글의 버릇을 못 본다. 같은 모델이 쓰고 같은 모델이 검사하면 그 모델이 놓치는 것은 두 번 다 놓친다. 다른 회사 모델에게 원문과 초안을 함께 주면 세 가지가 잘 걸린다. 입력과 어긋난 답(질문하지 않은 것에 답한 것), 사실 목록 밖의 주장, 그 언어 화자에게 어색한 표현이다. 여러 건을 한 템플릿으로 돌려 쓴 흔적도 여기서 드러난다.

## 위원 구성은 council 을 그대로 쓴다

모델을 고르고 부르는 일은 이 키트의 `council` 스킬이 이미 한다. 위원마다 실제로 한 번 물어 로그인과 플랜을 확인하고, 위원이 자기 회사 모델로 답하게 고르고(agy 는 Gemini 계열, cursor 는 Composer), 모두 읽기 전용으로 부르고, 빈 답이면 한 번 더 묻는다. 여기서 따로 CLI 를 부르지 않는다. 직접 부르면 모델 선택과 읽기 전용 옵션이 호출마다 달라진다.

```bash
C=<council 스킬 폴더>/scripts/council.py
timeout 400 python3 "$C" members --chair <세션 모델 계열>        # 6시간 안에 쟀으면 건너뛴다
RUN=~/.council/runs/$(date +%Y%m%d-%H%M)-polish-<슬러그>; mkdir -p "$RUN"
# question.md 를 쓴다 (아래)
timeout 1900 python3 "$C" stage1 "$RUN" --cwd "$RUN" --chair <세션 모델 계열>
```

- 위원은 `members` 가 `use` 로 고른 것 전부다. 하나만 쓰려면 `--members antigravity` 처럼 준다. 이때 모델은 members 캐시에서 온다. 캐시가 없으면 CLI 기본 모델(다른 회사 모델일 수 있다)로 가니 `members` 를 먼저 돈다.
- `use` 가 0 이면 교차 다듬기를 건너뛰고, 건너뛰었다는 것과 `fix` 줄을 결과에 적는다. 혼자 다듬은 결과를 교차 검토를 거친 것처럼 내지 않는다.
- 답은 `$RUN/stage1/<위원>.md` 에 있다. stage2(익명 순위)는 돌지 않는다. 여기서 필요한 것은 순위가 아니라 지적이다.

## question.md

위원은 대화를 모른다. 이 파일 하나로 답할 수 있게 쓴다. 「도구를 쓰지 말라」 줄은 빼지 않는다. council 의 위원 프롬프트가 작업 폴더의 파일을 읽어도 된다고 하므로, 이 줄이 없으면 위원이 폴더부터 열려다 읽기 전용 모드에 막힌다. agy 는 빈 답(`empty`)을 내고 grok 은 "먼저 폴더를 확인하겠습니다" 한 줄만 낸다. 이 줄을 넣으면 둘 다 답한다(agy 1~2분, grok 5분 안팎). 여러 건이면 한 파일에 번호를 매겨 묶는다. 건마다 부르면 호출 수만큼 한도를 쓴다.

```markdown
아래는 <누가> <어디에> 공개로 올릴 <무엇>이다. 건마다 원문(독자가 쓴 것), 초안, 쓸 수 있는 사실 목록이 있다.

필요한 자료는 이 글에 모두 있다. 파일을 읽거나 명령, 도구를 쓰지 말고 이 글만으로 바로 답하라.

조건
- 사실 목록 밖의 주장(기능, 버전, 날짜, 약속)을 넣지 않는다
- <길이 제한>, <언어 규칙>, <금지 표현>
- 독자가 실제로 말한 것에 답한다

건마다 셋을 내라.
1. 원문과 어긋나는 곳 (묻지 않은 것에 답함, 독자가 이미 한 일을 다시 시킴)
2. 사실 목록으로 확인되지 않는 주장
3. 그 언어 화자에게 어색하거나 기계적인 표현
그리고 고친 초안 한 벌. 고칠 것이 없으면 "그대로"라고 쓴다.

## 1
원문: ...
초안: ...

## 사실 목록
- ...
```

## 합치기

1. 위원이 짚은 것을 건마다 모은다. 둘 이상이 같은 곳을 짚었으면 고친다. 하나만 짚었으면 원문을 다시 읽고 정한다.
2. 위원이 고친 초안에서 받는 것은 표현과 맞춤뿐이다. 사실, 수치, 링크, 버전은 위원의 답에서 가져오지 않는다. 사실 목록에 없는 것이 들어왔으면 그 문장은 버린다.
3. 길이 제한과 언어 규칙을 다시 잰다. 위원 답은 대개 길어진다.
4. 결과에 한 줄을 남긴다. 부른 위원과 모델, 위원이 짚은 수, 받아들인 수, 버린 것과 이유.

## 흔한 실수

| 실수 | 왜 문제인가 | 대신 |
|---|---|---|
| 위원이 고친 초안을 그대로 올린다 | 위원은 사실 목록을 넘는 친절한 약속을 자주 넣는다 | 합치기 2 대로 표현만 받는다 |
| CLI 를 직접 부른다 | 모델이 CLI 기본값으로 가서 같은 회사 모델이 두 번 읽거나 쓰기 권한이 열린다 | council 의 `stage1` |
| 건마다 따로 부른다 | 쉰 건이면 쉰 번이다 | 한 파일에 묶어 한 번 |
| 위원 답이 한 줄이거나 `empty` 인데 성공으로 친다 | 위원이 도구를 쓰려다 막힌 것이다 | `stage1/<위원>.md` 를 열어 건마다 답이 있는지 보고, 없으면 「도구를 쓰지 말라」 줄을 확인하고 그 위원만 `--members` 로 다시 부른다 |
| 대화에 기댄 질문을 보낸다 | 위원은 무엇을 따져야 할지 모른다 | 원문, 초안, 사실 목록, 조건을 질문에 다 넣는다 |
