## 전체 설정

| 필드 | 필수 | 뜻 |
|---|---|---|
| `base` | 예 | 개발 서버 주소. `http://localhost:3000` |
| `depths` | 예 | 화면들. 깊이별로 나눠 적습니다 |
| `out` |  | 결과가 쌓일 곳. 기본 `.canvas` |
| `title` |  | 지도 위쪽에 뜰 이름. 기본 "화면 지도" |
| `host` |  | 기기 주소창에 적힐 이름. 비우면 `base`의 host |
| `views` |  | 보기 목록. 비우면 폰 하나 |
| `accent` |  | 강조색. 기본 `#f97316` |
| `prelude` |  | 화면을 열기 전에 브라우저에서 한 번 돌릴 JS |
| `signIn` |  | 계정을 갈아 끼우는 JS를 돌려주는 함수 |
| `signInPath` |  | 로그인 화면 주소. 기본 `/` |
| `signOut` |  | 계정을 바꾸기 전에 브라우저에서 돌릴 로그아웃 JS. 로그인한 화면 뒤에 로그아웃 화면이 오면 필요하다 |

## 보기

```js
views: [
  { name: "phone", label: "폰", width: 390, height: 844 },
  { name: "wide", label: "데스크탑", width: 1280, height: 800 },
]
```

`name`은 파일 이름에 쓰이므로 영문 한 단어로 둡니다. `label`은 지도의 전환 단추에 뜹니다.

**폭이 700 이상이면 창 모양으로, 미만이면 폰 모양으로 그립니다.** 노치를 달지 신호등을
달지를 이 값으로 가릅니다.

보기를 여럿 두는 이유는 폭에 따라 **마크업 자체가 갈리는 화면**이 있기 때문입니다. 목록이
좁을 때 카드 덱이고 넓을 때 그리드인 경우, 한 벌만 떠 두면 폭만 늘어난 덱이 뜹니다.
반응형이 CSS 수준뿐인 제품이면 하나만 두어도 됩니다.

## 로그인

계정에 따라 다른 화면이 뜨는 제품이라면 `signIn`을 채웁니다. 화면의 `as`에 적은 이름을
받아 **브라우저에서 돌릴 JS를 문자열로 돌려주는 함수**입니다.

```js
signInPath: "/login",
signIn: (name) => `
  const button = [...document.querySelectorAll("button")]
    .find((node) => node.textContent.includes(${JSON.stringify(name)}));
  button?.click();
`,
```

개발 서버에 계정을 눌러 들어가는 자리가 있으면 그것이 가장 빠릅니다. 없으면 이메일과
비밀번호를 채워 넣는 코드를 돌려주십시오.

```js
signIn: (name) => `
  document.querySelector("#email").value = ${JSON.stringify(name)} + "@example.com";
  document.querySelector("#password").value = "devpassword";
  document.querySelector("form").requestSubmit();
`,
```

**같은 계정이 이어지는 화면끼리 붙여 두면 로그인이 그만큼 줄어듭니다.** 계정이 바뀔 때만
로그인 화면으로 돌아갑니다.

`prelude`는 로그인 전에 한 번 돕니다. 쿠키 배너나 온보딩 팝업처럼 지도에 담을 필요 없는
것을 여기서 끕니다.

```js
prelude: 'localStorage.setItem("cookie-consent", "denied")',
```

## 화면

```js
{
  id: "detail",              // 파일 이름과 화살표에 쓰는 값
  label: "상세",              // 노드 이름줄에 뜹니다
  path: "/items/42",         // 열 주소
  as: "김테스트",             // 어느 계정으로 볼까 (선택)
  click: "고급",              // 찍기 전에 눌러야 하는 것 (선택)
  run: "await ...",          // 클릭 하나로 안 되는 상태를 만드는 JS. await 가능 (선택)
  wait: 2,                   // run 뒤에 기다릴 초 (선택)
  note: "탭 안의 화면입니다",   // 노드 아래 한 줄 (선택)
  exits: [...],              // 나가는 길 (선택)
  discover: {...},           // 주소를 찾아야 할 때 (선택)
}
```

`click`은 탭이나 아코디언 안의 화면을 담을 때 씁니다. 그 글자가 든 버튼을 눌러 화면
상태를 바꾼 뒤에 뜹니다. **같은 주소의 다른 상태를 두 화면으로 담고 싶을 때** 유용합니다 —
`id`만 다르게 하고 `path`를 같게 두면 됩니다.

`note`는 사람이 지도를 볼 때 알아야 할 것을 적는 자리입니다. 화면을 보면 아는 것 말고,
**보이지 않는 조건**을 적으십시오. "확정된 사람에게만 보입니다" 같은 것입니다.

## 나가는 길

```js
exits: [
  { to: "detail", by: "자세히 보기" },
  { to: "settings", by: 'sel:a[href="/settings"]' },
  { to: "quiz", by: ["다시 풀기", "처음 풀어보기"] },
]
```

`by`로 찾은 요소에 테두리가 둘리고 그 자리에서 화살표가 나갑니다.

- **글자**: 그 글자가 들어 있는 `a`·`button`·`[role=button]` 중 **보이는 첫 요소**
- **`sel:` 접두사**: CSS 선택자. 글자로 집기 어려울 때
- **배열**: 먼저 찾히는 것을 씁니다

배열이 필요한 경우가 생각보다 많습니다. 같은 문이 상황마다 다른 얼굴을 하기 때문입니다 —
테스트를 안 푼 사람에게는 "알아보기"이고 푼 사람에게는 "다시 풀기"입니다. 폭에 따라
덱의 링크였다가 목록의 카드였다가 하기도 합니다.

**앞으로 가는 것만 적으십시오.** 돌아가는 링크(`←`, 탭 전환, 전역 띠)는 들어온 길의
역이라, 그으면 같은 관계가 두 번 그려지고 화살표가 양쪽으로 붙어 어느 쪽이 흐름인지
읽히지 않습니다.

한 요소가 여러 문을 겸해도 됩니다. 로그인 버튼 하나가 탭 넷으로 보낸다면 `exits`에 넷을
적고 `by`를 같게 두면 됩니다.

## 주소가 그때그때 다를 때

상세 화면의 주소는 시드를 돌릴 때마다 달라지므로 설정에 못 박을 수 없습니다.

```js
{
  id: "detail",
  label: "상세",
  path: "/items/[id]",       // 주소창과 지도에 이렇게 뜹니다
  discover: {
    from: "/items",          // 여기서
    find: 'sel:a[href^="/items/"]',   // 이걸 찾아 그 href 로 갑니다
  },
}
```

`find`도 `sel:` 없이 글자로 줄 수 있습니다. 목록에서 실제로 서 있는 첫 항목을 집습니다.

**`path`에는 대괄호 자리표시자를 그대로 두십시오.** 지도의 주소창에 그렇게 뜨는 편이
정확합니다 — 사람마다 다른 주소라는 것이 드러납니다.
