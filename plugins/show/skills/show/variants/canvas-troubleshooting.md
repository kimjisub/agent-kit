## 화면이 비어 있거나 잘못된 상태

**빈 DB에서 뜨면 절반이 "아직 아무것도 없습니다" 화면이 됩니다.** 지도의 값어치는 실제
화면에 있으므로, 뜨기 전에 앱을 볼 만한 상태로 만들어야 합니다.

시드와 되돌리기를 한 쌍으로 프로젝트에 두는 것을 권합니다.

```
scripts/canvas/seed.sql      뜨기 전에 돌립니다
scripts/canvas/unseed.sql    다 뜨고 나면 되돌립니다
```

되돌리기가 함께 있으면 마음 편히 돌릴 수 있습니다. 시드에는 이런 것이 필요합니다.

- 목록이 비지 않을 만큼의 데이터
- 조건부로 뜨는 UI를 켜는 값 (기능 스위치, 날짜, 상태)
- 자격이 갈리는 계정 (확정된 사람과 떨어진 사람)

**로컬 DB에서만 돌리십시오.** 이 SQL은 상태를 통째로 갈아엎습니다.

## 문을 못 찾음

`snap`이 끝나면 못 찾은 문을 알려 줍니다. 그 화살표는 카드 머리에서 나가므로 지도가
망가지지는 않지만, 무엇을 눌러 가는지가 사라집니다.

**대부분은 같은 문이 상황마다 다른 얼굴을 하기 때문입니다.**

| 왜 | 어떻게 |
|---|---|
| 상태에 따라 글자가 다름 | `by: ["다시 풀기", "처음 풀어보기"]` |
| 폭에 따라 요소가 다름 | `by: ["자세히 보기", 'sel:a[href^="/p/"]']` |
| 그 화면에 아직 데이터가 없음 | 시드를 손보십시오 |
| 감춰진 요소를 먼저 집음 | 보이는 것만 고르므로 이 일은 없어야 합니다. 여전히 그렇다면 `sel:`로 더 좁히십시오 |

**한 요소가 여러 문을 겸하는 것은 정상입니다.** 로그인 버튼 하나가 탭 넷으로 보낸다면
`exits`에 넷을 적고 `by`를 같게 둡니다.

## 화살표가 어긋남

지도는 화면이 스스로 알려 온 자리를 씁니다. 스크롤해도 따라가고 폰트가 늦게 와도
따라갑니다. 그래도 어긋난다면:

**아래로 갈수록 벌어진다면** 화면이 자리를 못 알려 오고 있습니다. 뜰 때 재 둔 값으로
버티는 중인데, 그 값은 스크립트가 살아 있던 화면에서 잰 것이라 스크립트를 걷어 낸
화면과 조금씩 다릅니다. 브라우저 콘솔에서 오류를 보십시오 — 심어 둔 몇 줄이 죽었을 수
있습니다.

**문이 아예 화면 밖이면** 화살표가 기기 가장자리에 붙어 기다립니다. 이것은 정상입니다.
스크롤해 문이 올라오면 따라 올라옵니다.

## 화면이 깨져 보임

**서체가 다르거나 그림이 빠졌다면** 자산을 못 받은 것입니다. 뜰 때 개발 서버가 살아
있었는지, `snap`과 `build` 사이에 서버를 껐는지 보십시오 — 자산은 `build` 단계에서
받으므로 그때도 서버가 필요합니다.

**레이아웃이 원본과 미묘하게 다르다면** 그것은 스크립트를 걷어 낸 대가입니다. 클라이언트가
그리던 것(캔버스로 그린 QR, JS로 크기를 재는 요소)은 빈 자리로 남습니다. 구조를 보는 데는
지장이 없지만, 그 요소가 중요하다면 지도가 아니라 실제 화면에서 보십시오.

**앱이 살아나려 한다면** — 콘솔에 개발 서버 연결 오류가 쏟아진다면 — 스크립트가 덜 지워진
것입니다. 인라인이 아닌 형태로 실려 있을 수 있습니다.

## 지도가 안 열리거나 배율이 이상함

**열자마자 배율이 이상한 것**은 iframe이 아직 도착하지 않아 노드가 납작하게 재어진
것입니다. 0.7초 뒤 스스로 맞춥니다. 컨트롤의 전체 맞춤을 눌러도 됩니다.

**아무것도 안 보인다면** `screens/` 폴더가 비었는지 보십시오. `snap`이 실패했는데
`build`가 그대로 돌면 빈 지도가 나옵니다.

**iframe이 통째로 안 뜬다면** 브라우저가 `file:` 하위 창을 막는 설정일 수 있습니다.
Chrome은 기본으로 허용합니다. 정 안 되면 그 폴더에서 `python3 -m http.server`를 띄우고
`http://localhost:8000`으로 여십시오.

## 브라우저 도구

`agent-browser`가 있으면 그것을 씁니다. 데몬이 세션을 들고 있어 로그인이 명령 사이에
살아남으므로, 계정을 갈아 끼우는 이 작업과 잘 맞습니다.

```bash
npm i -g agent-browser
```

없으면 Playwright로 넘어갑니다.

```bash
npm i -D playwright && npx playwright install chromium
```

`--browser playwright`로 못 박을 수 있습니다.

**Playwright 쪽은 배율을 바꿀 때 컨텍스트를 새로 만듭니다.** 로그인 상태를 옮겨 담지만,
쿠키가 아닌 방식으로 세션을 들고 있는 앱이라면 여기서 로그인이 풀릴 수 있습니다. 그럴
때는 보기를 하나만 두거나 `agent-browser`를 쓰십시오.

## 규모가 커질 때

화면이 서른을 넘으면 몇 가지가 눈에 띕니다.

**뜨는 데 오래 걸립니다.** 화면당 두 보기에 각 5초 남짓이니 서른이면 5분입니다.
`snap`은 한 번만 돌리고 `build`를 반복하십시오 — 배치나 화살표를 손보는 일은 `build`
쪽이고, 그쪽은 몇 초면 끝납니다.

**폴더가 커집니다.** 자산까지 받아 두므로 수십 MB가 됩니다. `.gitignore`에 반드시
넣으십시오.

**열이 세로로 길어집니다.** 한 깊이에 화면이 열 개 넘게 서면 그 열만 아래로 늘어집니다.
깊이를 더 잘게 나누는 것이 대개 옳습니다 — 그 열 안에 실은 두 단계가 섞여 있는 것입니다.

**노드가 많으면 캔버스가 무거워집니다.** iframe 서른 개가 동시에 뜨므로 메모리를 씁니다.
`화면 만지기`를 끄면 조금 가벼워집니다.
