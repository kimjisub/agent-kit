# 그리기

**로드 시점 - Step 3 에서 직접 그린 SVG, 단계 재생, 값을 바꿔 보는 그림을 만들 때.** 어떤 그림을 고르나는 [figures](../catalogs/figures.md), 마크업 계약은 [kit](../catalogs/kit.md), 모양 규칙은 [style](../catalogs/style.md) 에 있다.

출처: visual-explainer v0.14.0 의 `references/diagrams.md` 와 `references/motion.md`(MIT, `kit/LICENSE`)를 옮기고 고쳤다.

직접 그린 SVG 가 기본 그림이다. 자리를 정확히 잡고, 페이지의 토큰과 글꼴을 쓰고, 움직일 수 있다. 그림을 태그에 맞추려고 휘지 않는다. 상자와 화살표만이면 `<ve-flow>` 로 충분하다.

## 격자 위에 계획하기

```
x:  40        280        520        760      열 간격 240
    +------+  GET /u   +------+  없음   +------+
y:90|Client|---------->| API  |-------->|  DB  |
    +------+           +--+---+         +------+
                     적중 | 읽기
y:210                  +--v---+
                       |Cache |
                       +------+
```

- 먼저 글자로 그려 보고, 열과 행을 좌표로 바꾼다. 라벨은 14단위 이상. 렌더러가 viewBox 와 상관없이 휴대폰에서 읽히는 크기로 맞춘다
- 상자 사이는 40단위 이상. 화살표는 직각(`M x y H x V y`). 라벨은 선 위 9단위
- SVG 글자는 줄바꿈이 안 된다. 한 줄 18자 안팎(한글은 9자 안팎), 둘째 줄은 `<tspan x=".." dy="1.2em">`
- 경계(프로세스, 네트워크, 신뢰 구역)는 점선 `rect.ve-bnd` 와 왼쪽 위 `text.ve-bnd-t`
- 상자가 12개를 넘으면 5~8개짜리 개요를 그리고 세부는 카드나 둘째 그림으로 뺀다
- 순서도는 행위자마다 열 하나와 가는 생명선, 시간은 아래로, 화살표마다 호출 이름. 스키마는 테이블마다 상자 하나와 고정폭 키 칸, 여러 개면 까마귀발 끝

## 모양

- **모양이 그것이 무엇인지 말한다.** 서비스는 사각형, 저장소는 원통(`path.sh` + `ellipse.sh.lid`), 큐는 짧은 칸막이 셋이 든 사각형, 선택이거나 내려간 것은 점선 사각형
- **작은 그림**(`.gl`)은 이름이 종류를 말하지 않을 때만 상자 왼쪽 위에 16단위 선 그림으로. 이모지는 쓰지 않는다
- **화살표**: 실선은 동기 호출, 점선은 비동기나 선택, 굵고 빛나는 강조색은 이 그림이 말하는 경로, 빨간 x 는 막힘
- **화살표마다 동사를 단다.** `쓴다`, `30초마다 묻는다`. 이름이 아니라 동작을 그린다. "캐시" 라는 상자가 아니라 캐시를 지나는 요청 경로다

## 치수선

구간을 재는 숫자는 그 구간 위에 둔다. 순서도의 시간 축에 지연, 타임라인에 TTL 구간, 바이트 배치에 칸 크기.

```
   +                       +    잰 두 점에서 나온 연장선
   |<-------- 9 ms ------->|    치수선, 값은 가운데 틈에
```

```html
<g class="ve-dim"><path class="ext" d="M120 300V322M380 300V322"/><path class="ln" d="M120 316H380M116 320l8-8M376 320l8-8"/><text x="250" y="310">9 ms</text></g>
```

- 양 끝에 짧은 45도 눈금. 값은 선 위 6단위에 가운데로, 선 위에 겹치지 않게
- 치수선은 모양 옆 레일에 두고 짧은 것을 가까이. 더해지는 구간(`1 ms` 다음 `9 ms`)은 한 레일에 잇고 합계는 그 바깥 레일에
- 주장을 싣는 치수 하나만 강조색(`.is-key`)

## 흐르는 점

트래픽이나 데이터가 움직이면 큰 그림 위에 움직이는 점으로 방향과 양을 보인다. 점이 나오는 간격의 비가 실제 비율이다.

```html
<path data-flow="hit"  data-every="420"  d="M95 105H375V80H695V105H375"/>   <!-- 보이지 않는 경로 -->
<path data-flow="miss" data-every="7000" d="M95 105H355V270H395V130H695"/>  <!-- 420:7000 은 약 94:6 -->
<g class="ve-dots" aria-hidden="true"></g>                                   <!-- 화살표 뒤, 상자 앞 -->
```

경로는 상자의 가운데를 지나 점이 한 상자로 들어가 다음 상자로 나온다. 움직이는 층은 페이지에 하나.

## 함께 밝히기

같은 `data-ref` 를 가진 것은 함께 밝아진다. 본문 낱말, 상자, 화살표, 카드, 버튼. 본문 낱말에는 `tabindex="0"`. 한 요소가 여럿을 가질 수 있다(`data-ref="hit miss"`). 그림마다 핵심 낱말 두셋에서 넷만 잇는다.

## 번호 표시

번호 원과 짧은 지시선. 지시선은 가리키는 점에 정확히 끝난다. 단계 재생에서는 번호 N 이 단계 N 이다(원과 지시선에 `data-s="N"`). 단계가 없으면 그림 아래 한 줄 메모로 둔다(`3 없으면 Postgres 를 읽는다`). 그림마다 셋에서 여섯.

```html
<path class="ann" data-s="3" d="M520 71V96"/><g class="ve-co" data-s="3" transform="translate(520 60)"><circle r="11"/><text>3</text></g>
```

## 전후

같은 좌표에 그린 그림 하나와 토글(`button[aria-pressed]` 가 `figure[data-view]` 를 바꾸고, `.only-before` / `.only-after` 묶음). 더해진 것은 `--ok` 선, 빠진 것은 `--risk` 점선. 정적으로는 같은 축척의 두 판을 나란히. 실제 화면과 도면의 전후는 그림이 아니라 사진이라 `.pair[data-compare]` 다([output §겹쳐 보기](60-output.md#겹쳐-보기---나란히-슬라이더-차이)).

## 작은 그림 여럿

같은 작은 그림을 경우마다 같은 좌표로 그려, 눈이 차이만 보게 한다. 바뀌는 부분이 그 경우의 상태 색을 띤다(`.case[data-st]`, kit 의 상자나 화살표에 `.is-st`, 직접 그린 모양은 `var(--st)`). 카드마다 상태 꼬리표, 짧은 제목, 작은 그림. 문장은 없다. 작은 그림의 라벨도 14단위 이상.

## 작은 차트

구간을 재지 않는 숫자에는 옆에 작은 차트를 둔다. 「100 중 N」 은 `<ve-waffle>`, 값 두셋에서 다섯은 `<ve-bars>`(중요한 것에 `hot`), 전체의 몫은 `<ve-stack>`. 추세는 스파크라인이다. `0 0 100 24`, `polyline` 하나, `vector-effect: non-scaling-stroke`, 값을 담은 `aria-label`. 직접 그린 차트의 축과 눈금은 `.ve-axis`, 그 라벨은 `.ve-axis-t`.

## 다른 모양

- **파일 지도**: 고정폭 중첩 `<ul>`. 경로마다 상태 꼬리표(추가, 수정, 삭제)와 `+12 -3`
- **타임라인**: 레일 선 하나와 날짜 점이 있는 CSS 격자. 가장 새것에 강조색

## 단계와 재생

단계마다 부분이 앞으로 나오고 한 줄 캡션이 붙는다. 재생 버튼과 막대가 있으면 장면 재생기다.

```
<figure class="ve-steps">  부분: data-s="N" (N 단계에 나온다), pathLength="1" 인 경로는 그려지며 나온다
  .ve-player -> ol.ve-cap > li[data-n="1/5"], button[data-go=-1], button[data-play], input[type=range], button[data-go=1]
```

- 단계 수는 `li` 의 수이고 `data-s` 는 1 부터 센다. 마지막 단계(전체 그림)로 열리고, 재생하면 1 단계부터 다시 돈다. 인쇄에도 마지막 단계가 나온다
- 장면 하나에 주장 하나. 단계마다 무언가 눈에 띄게 바뀐다. 저절로 재생하지 않는다
- 버튼 글자는 페이지가 쓴다(`이전`, `재생`, `다음`)

### 상태와 사건의 재생

상태 기계, 업무 흐름, 리듀서는 단계 하나가 사건 하나다. 캡션은 무엇이 일어났고 왜인지 말한다. `없음 -> 조회, TTL 이 지나서(cache.ts:48)`. 「왜」 는 실제로 걸린 조건이나 분기다. 인용하고, 지어내지 않는다. 주장 하나를 싣는 사건 6~12개를 고르고, 다른 갈래는 둘째 재생이나 작은 그림 여럿으로 보인다. 사건이 실제 실행에서 왔으면 캡션에 그렇다고 쓴다.

```html
<path class="ve-e" data-s="0 3 5" d="M730 90H800"/>                                                 <!-- 처음부터 그려져 있고 3, 5 단계에 밝아진다 -->
<g class="ve-co q" data-s="0 3 5" transform="translate(765 68)"><circle r="11"/><text>3</text></g>      <!-- 그 번호, 3 과 5 에 채워진다 -->
<circle class="ve-tok" data-s="6" r="5" style="offset-path: path('M910 150V295H650V150'); --dur: 2200ms"/>   <!-- 경로 하나 -->
<g class="ve-at job" data-s="3 4" style="--d: 850ms"><rect x="217" y="72" width="26" height="26" rx="4"/><text x="230" y="85">J3</text></g>   <!-- 3, 4 단계에만 보인다 -->
<g class="ve-vals"><text class="sub" data-s="0" x="236" y="52">0 / 8</text><text class="sub" data-s="2" x="236" y="52">5 / 8</text></g>
```

- `data-s` 에 단계를 여럿 쓰면 처음 단계에 나타나고 그 단계마다 밝아진다. `0` 은 처음부터 그린다. 기계 전체를 `0` 으로 그리고 실행이 경로를 밝히게 한다
- **점**(`.ve-tok`)은 상자 밑으로 가며 상자에 들어가 반대쪽으로 나온다. `--dur` 은 달리는 시간(기본 900ms), `--d` 는 늦춤. 몰려오는 것은 150ms 쯤 간격
- **나왔다 사라지는 것**(큐의 일, 바쁜 일꾼, 지금 상태의 고리)은 `.ve-at` 묶음이다. `data-s` 에 적은 단계에만 보인다. 밑에 빈 칸을 그려 둔다
- **바뀌는 값**(개수, TTL, 상태 이름)은 `.ve-vals` 안에 단계마다 글자 하나씩, 한 자리에
- **함께 쓰는 자원**(일꾼 풀, 허가)은 칸(`rect.ve-slot`, 차면 `.is-on`)과 개수를 담은 점선 경계
- 상자 이름 위 종류 라벨 `<text class="ve-kind">`: 사실, 판단, 상태, 효과

## 값을 바꿔 보는 그림

설정을 손으로 느끼게 하는 조작. TTL 막대를 움직이면 적중률, 점의 비, 제목 문장이 함께 바뀐다. 정책 토글로 나쁜 규칙이 더 좋아 보이는 틀린 숫자를 내는 것도 보일 수 있다.

- 조작은 하나에서 셋(`input[type=range]`, `button[aria-pressed]`). 각각이 읽는 사람이 신경 쓰는 것을 바꾼다
- 순수 함수 `model(settings)` 하나가 그림, 숫자, 문장을 다 만든다
- 처음 값은 실제 지금 값이고 눈금에 표시한다. 조작은 JS 로 넣고 인쇄에서 숨긴다. 인쇄와 JS 가 없는 화면에는 그 값의 상태가 남는다
- 식을 캡션이나 `<details>` 에 보인다. 줄인 모형이면 「예시」 라고 단다. 개념을 모형으로 만들고, 운영 코드를 그대로 베끼지 않는다. 실제 동작을 보여야 하는 자리면 실제로 돌려 미리 계산한 결과 표에서 고른다

## 3D

깊이가 데이터를 실을 때만이다. 임베딩, 실제 공간 배치, 높이가 양인 쌓기, 기하. 상자와 화살표 그래프는 3D 가 아니다.

- 페이지는 바깥으로 요청하지 않으므로 three.js 를 CDN 으로 부르지 않는다. 라이브러리 코드를 페이지 안에 넣을 수 있을 때만 만든다. 그렇지 않으면 3D 도구로 렌더한 이미지를 [drawing](../variants/drawing.md) 재료로 싣는다
- 만든다면: 고정 비율 `.frame` 안 캔버스에 `role="img"`, `aria-label`, 「그림 N」 캡션, 핵심 숫자를 담은 한 줄 대체 글. 색은 `getComputedStyle` 로 페이지 토큰에서. 조명은 방향광 하나와 주변광, 블룸, 안개, 입자는 쓰지 않는다. 처음 각도는 답이 보이는 각도이고, 자동 회전은 첫 조작 전까지만 하며 움직임 줄이기 설정에서는 하지 않는다
