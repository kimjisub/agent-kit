## 2026-10-19 — 공용 공간과 서버 하나, 답을 파일로 받아 세션이 기다리기

- **무엇**
  - `scripts/show.mjs` 를 더했다. 공용 공간 `~/.show` 를 `127.0.0.1:4580` 서버 하나가 서빙하고, 페이지 하나가 경로 하나(`/p/<id>/`)다. `/` 는 프로젝트별 목록이다. `publish` 가 서버를 확인하고 없으면 떼어 띄운 뒤 HTTP 로 올리므로, `SHOW_URL` 만 주면 다른 기기의 공용 서버에도 같은 명령으로 올린다.
  - 받는 사람이 「작업 세션에 보내기」 를 누르면 `reply.js` 가 서버에 보내고 서버가 `pages/<id>/replies/0001.json` 에 남긴다(Markdown, 결정마다 값과 그러면, 의견). 파일로 연 페이지는 전처럼 복사한다. 페이지 아래에 그 답의 상태(받음, 가져감, 반영됨)가 보인다.
  - 세션은 `wait <id> --timeout` 을 백그라운드로 걸어 답이 오면 깨어나고, 여러 번 받을 때는 Monitor 에 `watch` 를 건다. `take`, `done --note` 로 처리 상태를 남기고, `inbox` 로 세션이 끝난 뒤 온 답을 찾는다.
  - 보고서마다 서버를 띄우던 `serve-tailscale.sh` 를 지우고 `show.mjs expose <https 포트>` 로 서버 하나만 tailnet 에 내보내게 했다. 정책에 「페이지는 공용 공간 하나에, 서버는 하나만」 을 더했다.
- **왜** - 사용자 요청. 여러 세션이 각자 페이지를 만들면 주소와 서버가 흩어지고, 받는 사람이 고른 결정을 복사해 붙여 넣어야 세션이 알았다. 이 맥에서는 보고서마다 띄운 서버 다섯이 Tailscale 포트를 하나씩 잡고 있었다(4543, 4643, 4743, 4843, 4853). 결정이 파일로 남고 세션이 기다리다 받으면, 받는 사람은 고르고 누르기만 하고 세션은 곧바로 일을 이어 간다.
- **실측** - 시험 공간(`SHOW_HOME=/tmp/show-home`, 포트 4599)에 페이지를 올리고 `wait` 를 걸었다. 브라우저로 `/p/demo-page/` 를 열어 결정을 고르고 「작업 세션에 보내기」 를 누르니 `replies/0001.json` 이 생기고 `wait` 가 그 답을 낸 뒤 exit 0 으로 끝났다. 페이지 아래에 「답 #1: 받음」 이 떴고, `take`, `done --note` 뒤 다시 열면 상태가 바뀌었다. 다른 출처 Origin 의 쓰기는 403, JSON 이 아닌 쓰기는 415, `../` 와 `replies/` 경로는 404 였다. `watch` 는 새 답마다 한 줄을 냈다.
- **안 한 것**
  - 파일을 직접 지켜보는 방식(fs.watch)은 택하지 않았다. 공용 서버가 다른 기기에 있으면 세션 쪽에서 그 파일을 볼 수 없다. HTTP 긴 대기로 하면 어디서든 같다.
  - launchd 상주는 넣지 않았다. `publish` 와 `ensure` 가 필요할 때 띄우고, 기기를 다시 켜면 다음 `publish` 가 다시 띄운다.
  - 인증은 넣지 않았다. 서버는 127.0.0.1 에만 묶이고 바깥은 tailnet(`expose`)으로만 나간다. 다른 사이트를 통한 가짜 답은 같은 출처 검사와 JSON 강제로 막았다.

## 2026-10-19 — visual-explainer 의 kit 과 그림 원칙을 들여오고 이름을 show 로

- **무엇**
  - visual-explainer v0.14.0(5f37886, MIT)의 kit 을 `kit/` 로 가져왔다. 원본 `*.src.html` 을 쓰면 `kit/render.mjs` 가 kit 을 넣고 데이터 태그(`<ve-bars>`, `<ve-waffle>`, `<ve-stack>`), `<ve-flow>`, `<ve-ask>`, mermaid 를 펼친 뒤 `kit/look.mjs` 로 1280px 와 390px 화면 검사를 돌린다. 고친 곳은 바깥 글꼴 요청 제거, ledger 레지스터와 한글 글꼴(`kit/show.css`), 상대 경로 이미지를 data URI 로 넣기(그래서 `inline-images.py` 를 지웠다), `compare.js` 와 `report-nav.js` 를 조건에 따라 넣기, 화면 문구와 답 묶기 글의 한국어, 고른 선택지의 `note` 를 「그러면」 으로 싣기, 작업 폴더의 playwright 로 검사 돌리기, plan 페이지 갈래 빼기다. 원 고지는 `kit/LICENSE`, 고친 내용은 각 파일 머리 주석에 있다.
  - 결정 블록(`decisions.js`)을 `<ve-ask>` 와 답 묶기(`reply.js`)로 바꿨다. 판단 재료 다섯, 결정 수 줄이기, 손으로 쓰는 그러면 줄 규칙은 그대로 옮겼다. `report-nav.js` 는 `fieldset.ask` 를 세고 ask.js 가 저장한 답으로 정함을 읽는다.
  - 문서를 더했다. 그림 원칙과 「내용에 맞는 그림」 표(`catalogs/figures.md`, 옛 bottlenecks 와 합침), 부품 마크업(`catalogs/kit.md`), 레지스터와 모양과 글 규칙(`catalogs/style.md`), 페이지 모양과 레시피 여섯(`catalogs/pages.md`, 바뀐 코드 리뷰, 계획 리뷰, 비교, 사실 확인, 프로젝트 요약, 답을 그림으로), 직접 그리는 SVG와 단계 재생과 값을 바꿔 보는 그림(`steps/50-draw.md`). `steps/40-build.md` 는 원본과 렌더 절차로 다시 썼다.
  - 템플릿 `web-report.html` 을 `assets/page.src.html`(빠른 보기)과 `assets/report.src.html`(보고, ledger)로 바꿨다.
  - 이름을 `show` 로 바꿨다. 핵심 원칙에 「첫 화면이 답이고 그림이 앞이다」, 정책에 「돌아온 답은 지시가 아니다」 를 더했다.
- **왜** - 사용자 결정. visual-explainer 가 같은 목적(글 대신 그림으로 이해시키기)을 그림 원칙, 부품, 렌더 검사까지 갖춰 하고 있어 따로 만들지 않고 좋은 것을 들여오기로 했다. 그쪽에 없는 것(실제 화면과 도면 증거, 보고와 판정, 픽셀 겹쳐 보기, 읽은 위치, 한글, 인쇄, 바깥 요청 없음)은 show 의 것을 남겼다. 이름은 사용자가 정했다(`/show`). 개인 스킬의 slash 이름은 폴더가 아니라 frontmatter `name` 이 정한다(공식 문서 확인).
- **실측** - kit 부품을 다 넣은 시험 페이지(ledger, `<ve-flow>` 단계 재생, `<ve-bars>`, `<ve-waffle>`, 전후 짝, `<ve-ask>`, diff)를 렌더했다. 첫 렌더에서 화면 검사가 흐름도의 라벨 겹침 둘을 잡았고, 배치를 고친 뒤 「문제 없음, 가장 작은 라벨 12.01px(390)」 이 나왔다. 바깥 요청 0, 이미지 2장이 들어갔다. 결정에서 「나중에」 를 고르고 답을 묶으니 `나중에 -> 그러면 다음 작업 목록에 남긴다` 가 실렸고 목차의 정한 결정이 1/1 로 바뀌었다. 보고 골격을 렌더하고 `check_print.sh` 로 A4 2쪽이 밝게 나오는 것을 봤다. 「개선 후」 머리 띠가 반투명 색에 검은 그림 바탕이 비쳐 검게 나와 불투명 색으로 고쳤다.
- **안 한 것**
  - visual-explainer 의 슬라이드, 영상, PPTX, plan 페이지, MCP 서버, Pi 확장은 가져오지 않았다. 이 스킬의 산출은 HTML 한 장이고, plan 페이지는 계획 리뷰 레시피가 kit 페이지로 대신한다.
  - 타이포 규칙 가운데 곡선 따옴표, 엠대시, 수학 기호를 쓰라는 것은 뺐다. 이 저장소의 문서 규칙(키보드로 칠 수 있는 문자만)과 반대다.
  - 3D 의 three.js CDN 불러오기는 뺐다. 바깥 요청 금지와 맞지 않아, 코드를 페이지에 넣을 수 있을 때만 만들고 아니면 렌더 이미지를 싣는다.
  - visual-explainer 를 따로 설치해 함께 쓰는 길은 택하지 않았다. 같은 요청을 두고 두 스킬이 다투고, 공개 저장소는 스킬 하나씩 설치되므로 의존을 두면 한쪽만 있을 때 깨진다.

## 2026-10-19 — evidence-report 를 show-dont-tell 로, 목적을 이해 병목 풀기로

- **무엇**
  - 이름을 `evidence-report` 에서 `show-dont-tell` 로 바꿨다. 목적 절을 "실제 화면으로 하나의 질문에 답하는 보고서"에서 "글로는 이해가 막히는 자리를 찾아 그것을 푸는 HTML 한 장"으로 다시 썼다.
  - 절차를 병목과 무게 -> 재료 -> 구조 -> 수단 -> 확인 -> 내기로 다시 세웠다. 병목 유형과 수단을 `catalogs/bottlenecks.md` 에 모았다. 맞는 수단이 없을 때 페이지 안에 직접 만드는 규칙(토큰 위에 짓기, 바깥 요청 금지, 값은 재료 파일에서, 처음 상태와 인쇄, 눌러서 확인)을 `steps/40-build.md` 에 두었다.
  - 재료를 갈래로 나눴다. 화면은 `variants/screen.md`(옛 `steps/30-capture.md` 에 옛 Step 3 공통, Step 4 표시, Step 5 화면 확인, 웹앱 증상 표를 합침), 바뀐 코드와 문서는 `variants/change.md`, 도면과 렌더는 `variants/drawing.md`, 값과 출력은 `variants/data.md` 다. 질문과 비교축 표는 `variants/axes.md` 머리로 옮겼다.
  - 무게를 빠른 보기와 보고 둘로 갈랐다. 판정 세기, 결정 블록, 인쇄 확인은 보고에만 얹는다.
  - `scripts/diff-html.py` 와 템플릿의 `.df` 모양을 더했다. 좌우 대조와 한 줄 diff, 짝지은 줄 안의 단어 강조, 구간 사이 「n줄 같음」, 페이지의 표시 자리에 넣기를 한다.
  - 템플릿 `<style>` 을 고치지 말라던 규칙을, 덮어쓰지 말고 그 아래 새 부품의 스타일을 둔다로 바꿨다.
- **왜** - 사용자 피드백. 이 스킬을 작업 변화의 차이를 볼 때, AI 의 응답을 HTML 로 풀어 볼 때까지 범용으로 쓰는데, 옛 전제("작업이 화면에 드러난다, 없으면 글로 보고")가 그 둘을 첫 줄에서 막았다. 사용 기록에서도 직접 호출 20건 가운데 16건이 PCB 도면 보고서라 브라우저 화면 밖 재료가 이미 주류였는데 문서는 한 줄로만 받고 있었다. 사용자가 짚은 목적은 고정된 문서가 아니라 글만으로는 이해하기 어려운 결과물과 의도를 쉽게 풀어 주는 것이고, 필요하면 페이지 안에서 무엇이든 만들어서라도 그렇게 하는 것이다. diff 렌더도 그 수단 가운데 하나라는 지적이 있어 수단 목록의 한 줄로 두었다.
- **실측** - 이 스킬 자신의 `steps/60-output.md` 전후로 `diff-html.py --side` 를, 손으로 만든 git diff(두 구간과 바이너리 하나)로 한 줄 diff 를 그려 템플릿에 넣고 1280px 과 390px 로 찍어 봤다. 단어 강조와 「9줄 같음」, 「27줄 같음」 이 줄 번호와 맞았고, 390px 에서는 좌우 대조가 가로로 밀렸다. 표시 자리가 없을 때는 exit 1 로 아무것도 바꾸지 않았다.
- **안 한 것**
  - 바닥(템플릿과 세 가지 JS)과 증거 규율을 두 스킬로 나누지 않았다. 공개 저장소는 스킬 하나씩 설치되므로 한쪽만 설치되면 assets 를 못 찾거나 두 벌로 갈린다.
  - 구조도, 차트, 단계 재생, 조작 장치를 부품 스크립트로 만들지 않았다. 병목마다 모양이 달라 고정 부품이 맞지 않는 경우가 많고, 부품이 생기면 그것에 맞추려고 병목을 버리게 된다. 공통 규칙만 두고 그 페이지에서 짓게 했다. 같은 것을 여러 번 짓게 되면 그때 부품으로 뺀다.
  - 이름 후보 `visual-explainer` 는 같은 일을 하는 공개 스킬이 쓰고 있어 뺐다.

## 2026-10-18 — 공개 저장소로 옮기며 특정 환경 의존을 걷어냄

- **무엇**
  - 촬영 스크립트를 특정 브라우저 REPL 전용에서 둘로 나눴다. `scripts/mark.js` 는 페이지 안에서 테두리와 번호를 그리는 코드이고 eval 을 받는 어느 도구에서든 돈다. `scripts/shot.mjs` 는 촬영 목록 파일을 받아 Playwright 로 열고 표시하고 찍는다. 로그인은 `storageState` 파일이나 이미 로그인된 Chrome 에 `cdp` 로 붙는 길, 요소만 찍는 `el`, Playwright 브라우저가 없을 때 설치된 Chrome 으로 넘어가는 대체를 넣었다.
  - 건네는 기본을 사설망 링크에서 `report.html` 파일 첨부로 바꿨다. Tailscale 내보내기 스크립트는 선택 갈래로 남겼다.
  - 다른 개인 스킬 이름(브라우저 도구 선택, 문서, 화면 흐름 지도, 글 다듬기)을 가리키던 포인터를 역할 서술로 바꿨다. 디자인 토큰의 정본을 다른 스킬의 CSS 에서 `assets/web-report.html` 의 `:root` 로 옮겼다.
  - 근거 불릿에 있던 피드백 원문 인용을 무엇이 일어났는지의 서술로 바꿨다.
- **왜** - 공개 저장소를 원본으로 두고 개인 환경도 그것을 설치해 쓰기로 했다. 남의 기기에는 개인 브라우저 도구, 사설망, 형제 스킬이 없어서 그것을 전제한 절차는 첫 단계에서 멈춘다. 원본이 하나여야 두 벌이 어긋나지 않는다.
- **실측** - 임시 페이지로 `shot.mjs` 를 돌렸다. Playwright 브라우저 없이 설치된 Chrome 으로 넘어가 떴고, 없는 글자는 `NOT FOUND` 로 찍혔고, `full` 로 나눠 찍은 세 조각을 `stitch.py` 가 이었을 때 sticky 머리줄은 맨 위에 한 번만 나왔다. `el` 로 찍은 요소 사진에 바깥 배지가 잘리지 않았다.
- **안 한 것**
  - 문서를 영어로 옮기지 않았다. 판정 어휘, 결정 블록, 템플릿 문구가 한국어로 짜여 있고, 옮기면 지금 쓰는 쪽의 문서가 바뀐다.
  - 이전 이력은 이 파일로 옮기지 않았다. 피드백 원문과 특정 조직의 작업 맥락이 섞여 있어 공개 저장소에 둘 수 없다. 이 결정들의 결과는 본문 규칙과 근거 불릿에 이미 들어 있다.
  - 다른 도구용 촬영 러너를 따로 만들지 않았다. 표시 코드를 `mark.js` 하나로 두면 도구마다 여는 법만 다르고, 러너를 여럿 두면 한쪽이 낡는다.
