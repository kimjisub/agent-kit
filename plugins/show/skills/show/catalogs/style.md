# 모양과 말

**로드 시점 - Step 3 에서 페이지를 쓰기 전에 한 번, 그리고 내가 쓰는 CSS 를 더할 때.** kit 의 클래스는 이미 이 규칙을 따른다. 여기는 내가 쓰고 그리는 것에 대한 규칙이다. 부품 목록은 [kit](kit.md), 그리는 규칙은 [draw](../steps/50-draw.md).

## 표준 문서 모양

어느 페이지든 흰 바탕의 한 단 문서다. 레지스터를 고르지 않고 `data-register` 도 달지 않는다(달아도 같은 모양으로 나온다). 모양의 정본은 `kit/show.css` 의 「표준 문서」 절이다.

- 흰 바탕, 검은 글, 강조색 하나(잉크 파랑). 색은 핵심 경로, 링크, 판정과 전후 표시에만 쓴다
- 글꼴은 본문 하나와 고정폭 하나. 고정폭은 코드, 경로, 명령에만 쓰고 라벨과 꼬리표는 본문 글꼴이다
- 단은 960px, 글줄은 720px(한 줄 45자 안팎). 그림과 표는 단을 다 쓴다
- 제목은 세 단계(h1 28px, h2 21px, h3 17px). 굵기는 본문 400, 강조 600, 제목 700 까지
- 격자 바탕, 그림자, 발광, 그러데이션, 등장 움직임, 대문자 꼬리표, 둥근 알약은 없다
- 받는 사람 기기가 어두운 모드여도 밝게 나온다. 인쇄에도 같은 모양이 그대로 나온다

페이지마다 색이나 글꼴을 새로 고르지 않는다. 받는 사람이 여러 페이지를 같은 눈으로 읽게 하려는 것이다.

## 보이는 것의 원칙

1. **바탕은 조용하게, 신호는 하나.** 화면의 90% 가까이는 중립이다. 강조색은 지금 봐야 하는 것에만 쓴다. 핵심 상자 하나, 뜨거운 경로 하나, 지금 쓰는 조작 하나, 중요한 숫자 하나다.
2. **그림이 곧 화면이다.** 본문의 낱말과 그림 속 그 부분이 함께 밝아진다(`data-ref`, [draw §함께 밝히기](../steps/50-draw.md#함께-밝히기)).
3. **전체 먼저, 세부는 다음.** 전체 그림을 먼저 보이고, 세부는 넘기거나 펼쳐서 본다. 원자료는 `<details>` 로 접되 근거 절은 끝에 보이게 둔다.
4. **움직임은 변화나 흐름을 보일 때만.** 점이 실제 비율로 움직이고, 단계가 부분을 드러낸다. 블록은 처음부터 다 보인다. 시차 스크롤, 스크롤 가로채기, 꾸밈용 반복은 쓰지 않는다. 움직임 줄이기 설정이면 마지막 상태를 보인다.
5. **다듬음도 뜻이다.** 모양이 그것이 무엇인지 말한다. 핵심 상자 하나에 `.is-key`, 뜨거운 경로 하나에 `.is-hot`.

## 글

- 답을 먼저 쓴다. 제목은 주제가 아니라 결론이다. "캐시 구조" 가 아니라 "캐시 적중은 DB 를 건너뜁니다"
- 한 문장에 한 생각. 문단은 한두 문장. 한 화면에 짧은 문단 하나 정도
- 한 개념에 한 낱말. 읽는 사람이 화면에서 보는 이름으로 부른다
- 비유, 상투어, 얼버무림을 쓰지 않는다. 단계는 번호 목록으로 쓴다. 약어는 처음 한 번 풀어 쓴다
- 그림을 설명하는 문장은 그림 안의 라벨이 된다. 본문에는 그림이 못 말하는 이유와 맞바꿈만 남는다
- 키보드로 칠 수 있는 문자만 쓴다. 곡선 따옴표, 엠대시, 원문자, 특수 화살표는 쓰지 않고 `-`, `->`, `1.` 로 쓴다

## 숫자 표기

- 표, 수치 띠, 바뀌는 값은 고정폭 숫자(`tabular-nums`)로 쓰고 숫자 열은 오른쪽에 맞춘다
- 읽기 좋게 줄인다(`5.6k`, `-86%`). 단위는 라벨마다 다시 쓴다. 비교 기준을 함께 쓴다(`5,600 에서`)
- 비율에는 분모를 함께 적는다

## 배치

- **한 단.** 제목, 글, 그림, 캡션의 왼쪽 끝이 하나다. 곁 메모 단을 두지 않는다. 가운데 정렬은 쓰지 않는다
- **화면마다 주인공 하나.** 눈을 흐리게 떠도 읽히는 것 하나, 보조 하나나 둘, 나머지는 조용한 글이다. 위치를 보인다(`2 / 5`, 목차)
- **절은 `h2` 하나로 연다.** 절 위 라벨은 쓰지 않는다. 쓴 것이 남아 있으면 `h2` 위에 작고 흐린 글로 나온다
- **가까움.** 제목 위 여백은 아래 여백의 두세 배다. 관련 있는 것끼리 더 가깝게 둔다
- **구조는 여백 먼저, 가는 선 다음, 틀은 마지막.** 카드 안에 카드를 두지 않는다

## 그림

- **잉크는 데이터에.** 모든 표시가 데이터를 싣거나 눈을 이끈다. 차트 테두리, 그래프 바탕, 굵은 격자, 3D 막대는 쓰지 않는다
- **층.** 바탕 < 구조 < 데이터 < 신호(강조색). 위로 갈수록 진하다. 가까운 두 선은 세 번째 모양을 만드니 띄우거나 합친다
- **가장 작은 차이.** 구분은 보이는 한 가장 옅게. 라벨은 두 단계(작고 흐린 것, 크고 밝은 것)
- **라벨은 데이터 위에.** 가로로, 왼쪽 맞춤, 단위와 함께. 계열이 다섯 아래면 범례를 두지 않는다
- **정직한 축.** 막대는 0 에서 시작한다. 작은 그림 여럿은 축을 하나로 쓴다. 순서에 뜻이 없으면 값으로 정렬한다
- **선 굵기.** 구조 1, 데이터와 윤곽 1.5~1.75, 신호 2.5~3
- **색 단계.** 순차는 한 색상의 명도 단계, 발산은 중립을 가운데 둔 두 색상, 범주는 같은 명도와 채도의 다섯 색까지
- **분야의 그림 관례는 따른다.** 업무는 수영 레인, 회계는 원장, 프로토콜은 타이밍도, 상자의 작은 그림은 그 분야의 기호를 선으로. 말장난, 마스코트, 삽화는 쓰지 않는다

## 쓰지 않는 것

- Inter, Roboto, Arial, system-ui 만으로 된 글꼴(한글은 show.css 의 글꼴을 쓴다)
- 보라나 자홍 강조색, 네온, 유리 효과, 그러데이션 글자와 배경과 덩어리
- 클립아트, 마스코트, 이모지 표시. 상자의 종류 표시도 이모지가 아니라 선 그림
- 모든 것을 가운데 정렬. 둥근 카드에 색 막대 하나 붙이기. 순서에 뜻이 없는데 `01/02/03`

## 내가 쓰는 CSS

kit 과 show.css 의 클래스를 먼저 쓴다. 같은 것이 어디서나 같게 보인다. 더하는 것은 kit 의 단계만 쓴다(`--t-label`...`--t-h1`, `--s-1`...`--s-8`, `--r-1`, `--r-2`, `--fast` `--med` `--slow` 와 `--ease`).

- **간격.** 부품 안 `s-2`~`s-4`, 부품 사이 `s-5`~`s-6`, 절 사이 `s-8`. 간격이 크면 덜 관련된 것이다
- **모서리.** `r-1` 은 꼬리표, 버튼, 입력칸, 글 안 강조. `r-2` 는 틀, 표, 겹쳐 뜨는 것. 그 밖에는 둥글게 하지 않는다
- **색.** 강조색은 화면의 10% 이하. `ok warn risk info` 는 상태에만. 흐린 라벨은 투명도가 아니라 `--text-dim`
- **움직임.** `transform`, `opacity`, `stroke-dashoffset` 만. 마우스 올림은 `fast`, 상태는 `med`, 단계는 `slow`. 그림자는 쓰지 않는다
- **알림 상자.** 바탕색, `r-2`, 안 여백 `s-4`, 제목은 상태 꼬리표. 옆에 색 막대를 붙이지 않는다
- **코드.** 고정폭 `--t-small`, 바탕색, `r-2`, 안 여백 `s-4`, 가로로 밀린다
- **불러올 때 아무것도 밀리지 않게.** SVG 마다 `viewBox`, 이미지마다 너비와 높이
- 폭은 % 와 `max-width` 로 잡는다. px 폭을 박으면 휴대폰에서 화면 밖으로 나간다. 새 부품마다 `@media (max-width:720px)` 규칙을 함께 쓴다
