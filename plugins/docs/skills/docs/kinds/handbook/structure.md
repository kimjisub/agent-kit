# handbook: 구조

## 문서 골격

위에서 아래로 이 차례입니다. 가운데의 파트와 장은 문서마다 다르고, 앞의 셋과 뒤의 둘은 거의 모든 handbook 에 있습니다.

| 자리 | 장 | 담는 것 |
|---|---|---|
| 표지 | (scaffold 가 채움) | 제목, 한 줄 설명, 작성, 갱신일, 범위 |
| 0장 | 이 문서에 대해 | 왜 이 문서를 쓰나, 어떻게 읽나, 문서 지도(`ol.guide-toc`). 인수인계서면 작성자의 편지와 서명(`p.sign`) |
| 참고 | 용어 안내 | 문서 전체에서 쓰는 말의 표. 장 번호 대신 `data-num="참고"` |
| 파트별 장 | 배경 -> 대상별 장 | 독자가 알아야 할 배경(회사, 팀)부터, 대상(제품, 서비스, 인프라, 계정, 보안)별로 한 장씩 |
| 지금 | 진행 중인 일과 정기 업무 | 한눈에 보는 진행 상황, 잡혀 있는 일정, 반복 업무 |
| 끝 | 이어받는 역할 | 역할이 만드는 결과, 맡는 일, 판단 범위, 인계 직후 우선순위, 인수 확인 기준 |

- **배경은 뒤 장을 읽는 데 필요한 만큼만** 씁니다. 회사 소개가 따로 있으면 그쪽을 가리키고 짧게 끝냅니다.
- **대상별 장은 같은 절 순서를 반복합니다.** 예: 구성 -> 화면과 기능 -> 구조 -> 운영 구성 -> 배포와 롤백 -> 외부 연동 -> 데이터와 백업 -> 알려진 함정. 독자가 두 번째 장부터는 어디에 무엇이 있을지 압니다.
- **"지금" 장은 따로 둡니다.** 진행 상황은 가장 빨리 낡으므로 한 장에 모아 두면 갱신할 곳이 하나입니다. 대상별 장에는 오래 유지되는 구조를 씁니다.
- **마지막 장은 행동으로 끝냅니다.** 인계 직후 무엇부터 하고, 무엇을 할 수 있게 되면 인수가 끝났다고 보는지를 씁니다.

@ASK(handbook-kind): 어떤 handbook 인가요? [인수인계서 | 운영 핸드북 | 온보딩 가이드 | 시스템 설명서]
> 인수인계서면 0장에 편지와 서명, 끝에 이어받는 역할 장이 들어갑니다. 운영 핸드북이면 "지금" 장과 정기 업무가 무겁고, 온보딩 가이드면 배경 장이 무겁습니다.

@ASK(readers): 이 문서를 누가 읽나요? 장마다 "읽는 사람"에 쓸 사람이나 역할을 모두 알려 주세요.
> 장을 나누는 기준이 됩니다. 한 장을 읽는 사람이 둘 이상으로 갈리면 장을 가를지 봅니다.

장과 절의 마크업(`section.chapter`, `data-part`, `data-num`, 문서 지도)은 `layouts/web/layout.md` 에 있습니다. 0장은 `data-num="00"`, 참고 장은 `data-num="참고"` 로 둡니다.

## 절 안의 순서

1. 결론 한두 문장(무엇이고 지금 어떤 상태인가)
2. 그림이나 표(구성도, 흐름, 비교 표)
3. 설명과 예외
4. 더 볼 곳(저장소 경로, 문서 링크)

"알려진 함정", "먼저 볼 위험"처럼 놓치면 사고가 나는 것은 절 첫머리에 `.risk` 나 `.warn` 으로 올립니다.

## 비밀 값

비밀번호, 토큰, 개인 키는 이 문서에 넣지 않습니다. "값은 어디서 받나"(비밀 관리 도구의 항목 이름, 별도 전달 문서)만 씁니다. 문서가 PDF 로 전달되고 사본이 남기 때문입니다.

## 표지 변수

라벨은 kind.md 의 `labels` 가 정합니다(작성, 대상, 범위, 갱신, 담당).

| 변수 | 라벨 | 예 |
|---|---|---|
| `DOC_TITLE` | 브라우저 탭 | 인수인계서 |
| `DOC_HEADER` | 사이드 목차 머리, 인쇄 꼬리말 | 인수인계서 |
| `CATEGORY` | 제목 위 작은 글씨 | 인수인계서 (기본 핸드북) |
| `COVER_TITLE` | 표지 제목 | 인수인계서 |
| `SUBTITLE` | 제목 아래 한 줄 설명 | 맡던 서비스 셋과 인프라의 배경, 현재 상태, 이어받을 역할을 설명하는 문서입니다. |
| `COVER_FROM` | 작성 | 홍길동 |
| `COVER_TO` | 대상 | 인수자, 운영진 |
| `COVER_TARGET` | 범위 | 서비스 운영과 사내 IT |
| `COVER_PERIOD` | 갱신(사이드 목차 머리 아래에도) | 2026-09-30 |
| `COVER_OWNER` | 담당 | |
| `COVER_CONFIDENTIAL` | 표지 아래 작은 안내 | 비밀 값은 별도로 전달합니다. |

비운 변수는 표지에서 자리째 사라집니다.

## 호출 예시

```bash
KIND=handbook DOC_TITLE="인수인계서" DOC_HEADER="인수인계서" CATEGORY="HANDOVER" \
COVER_TITLE="인수인계서" SUBTITLE="..." COVER_FROM="홍길동" COVER_PERIOD="2026-09-30" \
COVER_TARGET="서비스 운영과 사내 IT" \
bash <skill-dir>/scripts/build.sh scaffold "/path/to/인수인계서"
```

그림은 문서 폴더의 `assets/diagrams/`, 화면 캡처는 `assets/screenshots/` 에 두고 상대 경로로 겁니다.
