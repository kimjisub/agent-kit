# handbook: 장 단위 참조 문서

여러 독자가 각자 필요한 장만 찾아 읽는 긴 문서입니다. 인수인계서, 운영 핸드북, 온보딩 가이드처럼 처음부터 끝까지 읽히지 않고 "이 서버는 어디서 들어가나"를 찾으러 다시 열리는 문서가 여기 듭니다.

## 이 문서가 뭔가

한 번 읽고 끝나는 보고서가 아니라, 이어받은 사람이 몇 달 동안 되돌아와 찾는 참조 문서입니다. 그래서 장이 독자 단위입니다. 장마다 "읽는 사람"을 적어 독자가 자기 장을 고르고, 파트(회사, 제품, 개발, 인프라, 지금 등)가 장을 묶습니다.

기본 레이아웃은 `web` 입니다(화면에서 사이드 목차로 읽고, 인쇄하면 장마다 쪽이 끊긴다). 짧은 인수인계 메모처럼 장이 셋 이하면 `LAYOUT=a4` 로 뽑습니다. 이때 장은 `h1` 절이 됩니다.

### 다른 유형과의 차이

| 종류 | 읽는 방식 | 담는 것 |
|---|---|---|
| handbook | 필요한 장만 찾아 읽고 다시 엶 | 여러 영역의 배경, 현재 상태, 이어받을 일 |
| manual | 절차를 따라 하며 읽음 | 한 가지 작업의 절차 |
| analysis | 처음부터 한 번 읽고 판단 | 조사와 근거, 결론 |

한 가지 작업의 절차만 담으면 manual, 여러 영역의 배경과 현재 상태와 이어받을 일을 담으면 handbook 입니다.

### 전형적 사용 사례

- 퇴사나 역할 이동 때의 인수인계서
- 팀이나 서비스의 운영 핸드북(구성, 배포, 장애 대응, 계정)
- 새로 온 사람을 위한 온보딩 가이드
- 여러 시스템에 걸친 설명서(아키텍처, 데이터 흐름, 외부 연동)

## 이 폴더 구성

| 파일 | 담는 것 |
|---|---|
| `structure.md` | 문서 골격(표지, 0장, 참고 장, 파트별 장, 지금, 이어받는 역할), 절 안의 순서, 비밀 값, 표지 변수, 호출 예시 |
| `inputs.md` | 쓰기 전에 모을 재료 |
| `review.md` | 내용과 문체 검증 |

장과 절의 마크업, 컴포넌트, 화면과 인쇄는 `layouts/web/layout.md` 에 있습니다.
