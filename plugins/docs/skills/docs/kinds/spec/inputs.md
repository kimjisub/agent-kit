# spec: 작성 전 선행 재료

아래가 없으면 구현자가 문서만 보고 구현할 수 없다. 작성 전에 확인하고, 빠진 것은 양쪽 담당자에게 먼저 묻는다. 끝내 정할 수 없는 것은 `open` 상자로 드러낼 목록으로 따로 모은다.

## 결정 공란

- [ ] [structure.md](structure.md#결정-공란) 의 결정 공란(spec-status, implementer-side, auth-scheme)을 사용자와 모두 정했다

## 범위

- [ ] 연동의 목적을 한 문장으로 쓸 수 있다
- [ ] 연동하는 두 시스템과 각 담당 조직이 정해졌다
- [ ] 범위 밖 항목(이번에 다루지 않는 흐름)이 정해졌다

## 채널과 흐름

- [ ] 채널(Webhook, 조회 API, 파일)마다 방향과 트리거를 안다
- [ ] 호출 빈도와 예상 건수(초당, 일간)를 안다

## 공통 규약

- [ ] 전송 방식(HTTPS, 기본 URL, 환경별 주소)을 안다
- [ ] 인증과 서명 방식이 정해졌거나 후보가 있다(`auth-scheme`)
- [ ] 시간 형식, 시간대, 문자 인코딩, 숫자 단위가 정해졌다
- [ ] 재시도 정책과 멱등성 기준이 정해졌다
- [ ] 오류 응답 형식과 상태 코드 목록이 있다

## 엔드포인트와 필드

- [ ] 엔드포인트나 이벤트 목록이 있다
- [ ] 항목마다 필드 이름, 타입, 필수 여부, 허용 값, 단위를 안다
- [ ] 항목마다 실제 데이터 모양에 맞는 예시를 만들 수 있다(실제 고객 데이터는 쓰지 않는다)

## 구현 분담

- [ ] 우리가 제공하는 것과 상대가 구현할 것을 나눌 수 있다(`implementer-side`)
- [ ] 이미 구현된 항목과 구현 예정 항목을 구분했다

## 미확정

- [ ] 미정 항목마다 선택지, 결정 주체, 기한을 적을 수 있다

## 표지

- [ ] 작성, 연동 대상, 수신 구현, 버전 값이 정해졌다. 정하지 않은 것은 비워 두면 표지에서 사라진다
