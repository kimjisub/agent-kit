# briefing 덱 흐름, 표지 변수, 호출 예시

발표 내용의 흐름만 다룬다. 슬라이드 한 장의 분량, 세로 공간, 결론바, 덱 전체 중복 점검, 골격과 스니펫은 [layouts/deck/layout.md](../../layouts/deck/layout.md) 를 따른다.

## 권장 덱 흐름

```
표지(자동) -> [섹션 표지(선택)] -> 본문 슬라이드(반복) -> 마무리
```

| 순서 | 슬라이드 종류 | 필수 여부 |
|---|---|---|
| 1 | 표지(`cover`), 레이아웃의 `cover.html` 이 자동 생성 | 필수 |
| 2+ | 섹션 표지(divider), 챕터 전환 | 선택 |
| 이후 | 본문 슬라이드(`slide`) | 필수(내용만큼) |
| 마지막 | 마무리 슬라이드(다음 단계, 연락처) | 권장 |

- **스토리라인을 먼저 짠다.** 예: 문제 -> 원인 -> 해결 -> 행동, 또는 문제 -> 방법 -> 결과 -> 결론. 슬라이드 제목만 순서대로 읽어도 이 줄기가 이어져야 한다.
- **섹션 전환 표시는 발표 자리로 고른다.** 시간이 빠듯한 대면 발표(예: 8분)는 divider 와 목차 슬라이드를 빼고 모든 본문 슬라이드에 스테퍼를 넣어 표지에서 바로 본문으로 간다. 혼자 읽는 송부용 덱은 divider 로 섹션을 끊는다. 근거와 스니펫은 [layout.md 의 divider 대신 스테퍼](../../layouts/deck/layout.md#divider-대신-스테퍼).
- **마무리는 도입에서 던진 것을 회수한다.** 첫 섹션의 문제나 질문을 마무리 슬라이드가 받고, 다음 단계나 연락처로 끝낸다. 같은 메시지는 첫 언급과 마무리 회수, 2회까지만 쓴다.
- **발표 맥락에 맞춰 밀도를 정한다.** 대면 발표면 슬라이드당 텍스트를 줄이고 큰 글자와 KPI 중심으로 짠다. 이메일 송부면 각 슬라이드에 맥락 설명을 충분히 담아 발표자 없이도 읽히게 한다. 화면 공유면 발표자가 보충한다는 전제로 핵심만 담는다.

`LAYOUT=a4` 로 뽑으면 같은 흐름을 절로 옮긴다. 슬라이드 제목이 절 제목, 발표 멘트가 본문 산문이 된다.

## 표지 변수 매핑

표지는 레이아웃의 `cover.html` 이 자동 생성하고, 빌드 때 아래 환경 변수가 치환된다. 값을 비운 요소는 표지에서 사라진다. deck 표지는 다섯 변수만 쓰고 라벨은 찍지 않는다. a4 표지는 `kind.md` 의 `labels` 를 라벨로 붙여 메타 다섯 줄을 찍는다.

| 환경 변수 | deck 표지 자리 | a4 표지 라벨 | 예시 값 |
|---|---|---|---|
| `CATEGORY` | `.cover-label`(카테고리 레이블). 생략하면 `BRIEFING` | 같음 | `BRIEFING` |
| `COVER_TITLE` | `<h1>`(메인 제목) | 같음 | `2026 3분기 채용 성과` |
| `SUBTITLE` | `.cover-company`(회사, 수신처 부제) | 같음 | `사업본부 월간 회의` |
| `COVER_TO` | `.cover-meta`(청중, 날짜 같은 메타 한 줄) | 청중 | `사업본부 전원, 2026-09-30` |
| `COVER_PERIOD` | 표지 하단 우측 글자 | 일시 | `2026년 9월 30일` |
| `COVER_FROM` | 안 씀 | 발표 | `경영지원팀` |
| `COVER_TARGET` | 안 씀 | 주제 | `3분기 채용 지표와 4분기 계획` |
| `COVER_OWNER` | 안 씀 | 발표자 | `홍길동` |

## @ASK (작성 전 맥락 수집)

@ASK(presentation-context): 이 덱은 어떤 자리에서 쓰나요? [대면 발표 | 이메일 송부(혼자 읽는 덱) | 화면 공유]
> 대면 발표면 슬라이드당 텍스트를 줄이고 큰 글자와 KPI 중심으로 짭니다. 이메일 송부면 각 슬라이드에 맥락 설명을 충분히 담아 정보 밀도를 높입니다.

@ASK(slide-count-target): 목표 슬라이드 수를 알려 주세요. [10장 이하 | 15장에서 20장 | 20장 초과]
> 목표 수량이 정해지면 섹션별 슬라이드 배분을 먼저 계획한 뒤 본문을 씁니다. a4 로 뽑으면 절 수로 읽습니다.

## 호출 예시

```bash
# 1. scaffold: 표지와 셸 HTML 생성 (LAYOUT 을 생략하면 deck)
KIND=briefing \
DOC_TITLE="2026 3분기 채용 성과" \
COVER_TITLE="2026 3분기 채용 성과" \
SUBTITLE="사업본부 월간 회의" \
COVER_TO="사업본부 전원, 2026-09-30" \
COVER_PERIOD="2026년 9월 30일" \
bash <skill-dir>/scripts/build.sh scaffold "/path/to/발표덱"

# 2. 본문 슬라이드 작성
#    발표덱/발표덱.html 의 표지 슬라이드 뒤에 <section class="slide">...</section> 를 직접 추가한다

# 3. PDF 렌더
bash <skill-dir>/scripts/build.sh pdf "/path/to/발표덱"
```

- 유인물로 뽑으려면 `LAYOUT=a4` 를 붙이고 `COVER_FROM`, `COVER_TARGET`, `COVER_OWNER` 도 채운다.
- 회사 양식이 필요하면 `BRAND=<id>` 를 붙인다(기본 `default`).
- 작성 전 결정 공란 목록은 `bash <skill-dir>/scripts/build.sh ask briefing` 으로 받는다.
