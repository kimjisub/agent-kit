# briefing 내용 검증 체크리스트

표현 검증(넘침, 정렬, 브랜드 색)은 `layouts/<layout>/review.md` 다(deck 이면 [layouts/deck/review.md](../../layouts/deck/review.md)). 이 문서는 발표 내용만 본다. 초안을 끝낸 뒤, PDF 를 굳히기 전에 순서대로 확인한다.

---

## 1. 덱 전체 구조

- [ ] 표지가 있다(deck 이면 첫 슬라이드가 `.cover` 로 시작한다)
- [ ] 마무리 슬라이드가 있다(덱이 다음 단계나 연락처로 끝난다)
- [ ] 슬라이드 제목만 순서대로 읽어도 논리 흐름이 이어진다
- [ ] 목표 슬라이드 수(`@ASK(slide-count-target)` 결정값)와 2장 이내로 맞는다

## 2. 슬라이드별 메시지 단일성

- [ ] 각 슬라이드 제목(`.slide-title`)이 그 슬라이드의 결론을 담는다
- [ ] 한 슬라이드에 독립된 메시지가 둘 이상 섞이지 않았다
- [ ] 불릿이나 표 항목이 5\~6개를 넘는 슬라이드가 없다
- [ ] 부제(`.slide-subtitle`)가 있다면 제목을 보완하는 한 줄이다(제목의 반복이 아니다)

## 3. 발표 맥락 적합성

- [ ] `@ASK(presentation-context)` 결정값에 맞는 정보량이다
  - 대면 발표: 슬라이드당 텍스트가 적고 KPI 와 도식 중심이다
  - 이메일 송부(혼자 읽는 덱): 발표자 없이도 이해되게 맥락 설명이 들어 있다
  - 화면 공유: 발표자가 보충 설명한다는 전제로 핵심만 담았다

## 4. 데이터, 수치 품질

- [ ] 모든 수치에 단위가 있다(예: "1,234명", "18%", "42일")
- [ ] 모든 수치에 기준 시점이나 출처가 있거나 `.bottom-paragraph` 나 각주로 달았다
- [ ] 추정값에 "추정" 또는 "약" 표기가 있다
- [ ] 표현이 `brands/<brand>/voice.md` 기준을 따른다. 형용사 과잉이나 근거 없는 주장이 없다

## 5. 섹션 흐름

- [ ] 섹션 표지가 있다면 그 뒤 본문 슬라이드가 그 섹션 주제를 다룬다
- [ ] 섹션 사이 연결이 이어진다(설명 없이 주제가 바뀌지 않는다)
- [ ] 어젠다 슬라이드가 있다면 실제 덱 구성과 일치한다

## 6. 용어 일관성

- [ ] 같은 개념을 덱 안에서 같은 단어로 부른다(사용자와 고객, 회원과 가입자를 섞지 않는다)
- [ ] 영문 약어는 첫 등장 때 풀어 쓰거나 괄호로 병기했다(예: "MAU(월간 활성 사용자)")

## 7. AI 티 나는 문장 점검

발표 자료에서는 빠뜨리지 않는다. 슬라이드의 모든 문장은 **사실, 숫자, 다음 장 연결** 중 하나의 역할을 해야 한다. 아래 패턴을 찾아 고친다.

- [ ] **자기평가 문구가 없다.** "정직하게", "솔직히", "숨기지 않고", "\~가 본 발표의 태도다" 같은 말. 정직함은 문구가 아니라 내용(한계 명시, 편향 표기)으로 드러낸다
- [ ] **본문을 되풀이하는 결론바가 없다.** 하단 강조 바가 부제나 본문을 한 줄로 다시 말하지 않는다(새 사실이나 다음 장 질문만)
- [ ] **무게 잡는 수식어가 없다.** "본질적", "정면 대응", "근본적", "핵심적"처럼 빼도 뜻이 같은 말
- [ ] **대구 문형을 남발하지 않았다.** "X 가 아니라 Y 로, A 가 아니라 B 로" 식의 대칭 문장. 의도한 도입부 1\~2곳 외에는 사실 문장으로 쓴다
- [ ] 구호형 문장("\~가 생명", "\~가 곧 \~다")을 구체 수치나 설계 결정으로 바꿨다

## 8. 중복, 계층

- [ ] 같은 문구나 수치가 덱에서 3곳 이상 반복되지 않는다(첫 언급과 마무리 회수, 2회까지)
- [ ] 문제 슬라이드의 난제와 방법 슬라이드가 1:1 로 대응한다(예고 없이 나온 방법, 받지 않은 난제가 없다)
- [ ] 한계와 향후 과제 같은 의도한 호응(2회) 외에, 중간 슬라이드가 같은 목록을 또 나열하지 않는다
- [ ] 진행 표시 수단이 하나다. 스테퍼를 쓰면 `.slide-number` 에 섹션명을 겹쳐 적지 않는다
