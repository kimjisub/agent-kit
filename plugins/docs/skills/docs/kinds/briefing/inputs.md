# briefing 작성 전 준비 재료

본문 HTML 을 쓰기 전에 아래 항목을 모두 확인하고 준비한다. 체크가 끝나지 않은 채 슬라이드를 채우면 구조를 다시 짜게 된다.

## 1. 목적, 맥락

- [ ] 발표 목적을 한 문장으로 정했다(예: "협업툴 두 제품 중 하나를 도입하도록 경영진 승인을 받는다")
- [ ] 청중이 분명하다(예: CFO 와 IT 팀장, 의사결정권자 1인)
- [ ] 사용 자리를 정했다(`@ASK(presentation-context)` 응답 완료: 대면 발표, 이메일 송부, 화면 공유)
- [ ] 목표 슬라이드 수를 정했다(`@ASK(slide-count-target)` 응답 완료)

## 2. 핵심 메시지

- [ ] 덱이 전할 핵심 메시지 3\~5개를 개조식으로 정리했다
- [ ] 각 메시지가 슬라이드 1장에 1개씩 배분될 만큼 구체적이다
- [ ] 덱 전체 스토리라인(예: 문제 -> 원인 -> 해결 -> 행동)을 설계했다

## 3. 데이터, 수치

- [ ] 쓸 숫자와 통계의 출처와 기준 시점을 확인했다
- [ ] 추정값은 "추정"으로 표기할 준비가 됐다
- [ ] KPI 슬라이드에 넣을 지표 값과 단위를 확정했다(예: "1,234명", "2026-05 기준")

## 4. 이미지, 자산

- [ ] 넣을 이미지와 도표 파일을 번들의 `assets/` 에 모았다
- [ ] 이미지 파일이 실제로 있고 열리는지 확인했다
- [ ] 로고는 빌드가 브랜드 폴더에서 주입하므로 따로 준비하지 않는다(`layouts/<layout>/cover.html` 과 `style.css` 가 넣는다)

## 5. 표지 메타

- [ ] `CATEGORY`(카테고리 레이블) 값을 정했다. 생략하면 `BRIEFING`
- [ ] `COVER_TITLE`(메인 제목) 문구를 확정했다
- [ ] `SUBTITLE`(수신처나 회사명) 문구를 확정했다
- [ ] `COVER_TO`(청중, 날짜 메타) 문구를 확정했다
- [ ] `COVER_PERIOD`(deck 은 표지 하단 우측, a4 는 일시) 값을 정했다
- [ ] a4 로 뽑으면 `COVER_FROM`(발표), `COVER_TARGET`(주제), `COVER_OWNER`(발표자)도 정했다

## 6. 분량 계획

- [ ] 목표 슬라이드 수에 맞춰 섹션별 슬라이드 배분표를 만들었다
- [ ] 각 섹션의 핵심 슬라이드(1슬라이드 = 1메시지)를 목록으로 뽑았다
- [ ] 항목이 많은 슬라이드는 미리 나눌 계획을 세웠다(항목 5\~6개를 넘으면 나눈다)
