# briefing: 발표 자료

**발표자가 말로 전하는 흐름이 먼저이고, 화면은 그 말을 받치는 문서**다. 슬라이드 제목만 이어 읽어도 발표의 이야기가 되고, 한 장이 말 한 토막에 맞는다. 기본 레이아웃은 `deck`(16:9 슬라이드)이다.

## 쓰는 자리

- 분기 실적, 프로젝트 성과 공유
- 사내 기술 발표, 세미나, 사례 발표
- 회사와 제품 소개(행사, 첫 미팅)
- 조사나 실험 결과를 팀 앞에서 발표

## 다른 종류와의 차이

proposal 이나 analysis 도 `LAYOUT=deck` 으로 슬라이드가 된다. 차이는 **흐름을 무엇이 정하느냐**다.

| | briefing | proposal, analysis 를 deck 으로 |
|---|---|---|
| 흐름의 주인 | 발표의 말(도입, 전개, 회수) | 문서의 절(요약, 배경, 제안 또는 발견, 결론) |
| 한 장의 단위 | 말 한 토막, 메시지 하나 | 절 하나를 1\~3장으로 나눈 것 |
| 읽는 방식 | 발표자와 함께 한 번 보고 넘긴다 | 발표 뒤에도 문서처럼 다시 읽힌다 |
| 성공 기준 | 청중이 발표 뒤 한 문장을 기억한다 | 결정(proposal)이나 사실 확인(analysis)이 된다 |

고르는 기준은 이렇다. 승인이나 계약을 받아야 하면 proposal, 확인한 사실을 기록해 공유하면 analysis, **말로 전하는 자리 자체가 목적**이면 briefing 이다. 제안 발표라도 청중이 결정권자이고 뒤에 문서로 다시 검토한다면 proposal 을 deck 으로 뽑는다.

## 이 폴더 구성

| 파일 | 담는 내용 |
|---|---|
| `kind.md` | 이 문서. 정체성, 다른 종류와의 차이, 레이아웃별 차이 |
| [structure.md](structure.md) | 권장 덱 흐름, 표지 변수, 결정 공란(@ASK), 호출 예시 |
| [inputs.md](inputs.md) | 작성 전에 준비할 재료 체크리스트 |
| [review.md](review.md) | 내용 검증 체크리스트(흐름, 메시지 단일성, 발표 맥락, 수치, 문장) |

문체의 베이스는 `brands/<brand>/voice.md`, 표현(슬라이드 조판, 컴포넌트, 표지)은 고른 레이아웃의 `layouts/<layout>/layout.md` 다. 이 폴더는 발표 흐름에서 달라지는 내용만 적는다.

## 레이아웃별 차이

| 레이아웃 | 언제 | 달라지는 점 |
|---|---|---|
| `deck`(기본) | 대면 발표, 화면 공유, 송부용 덱 | [structure.md](structure.md) 의 흐름을 슬라이드 한 장씩으로. 조판 규칙은 [layouts/deck/layout.md](../../layouts/deck/layout.md) |
| `a4` | 발표 원고나 배포용 유인물 | 슬라이드 하나가 짧은 절 하나가 된다. 슬라이드 제목이 절 제목, 발표 멘트가 본문 산문이 된다. 표지 라벨이 찍힌다 |
