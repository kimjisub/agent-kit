# brief: 내용과 어조 검증 체크리스트

표현 검증은 [a4 review.md](../../layouts/a4/review.md), 문체의 베이스는 `brands/<brand>/voice.md` 다. 아래는 brief 의 내용과 어조 항목이다.

## 계약과의 일치

- [ ] 결과물 목록이 계약서와 같은 번호, 같은 이름, 같은 개수다
- [ ] 일정이 계약서와 같고, 계약서에 없는 날짜를 새로 정하지 않았다
- [ ] 비용, 권리, 비밀 유지 같은 계약 조건을 반복하지 않았다
- [ ] 계약 밖 요구(추가 결과물, 수정 횟수 늘리기)를 넣지 않았다. 넣었다면 부탁이나 후속 거리로 표시했다
- [ ] 공고를 냈다면 공고의 결과물 이름과 맞는다

## 순서와 자리값

- [ ] 첫 쪽에 의뢰 범위와 일정이 있다
- [ ] 첫 쪽이 비어 보여도 요약 상자로 채우지 않았다
- [ ] "진행 방식", "우리가 드리는 것", 최종 결정자, 내부 문화 같은 작업자의 일을 바꾸지 않는 절이 없다
- [ ] 선택 사항(움직임 아이디어 등)이 앞자리에 있지 않다
- [ ] 다른 쪽을 가리키는 문장("n쪽에 정리했습니다")이 없다
- [ ] 같은 말(요약 표와 상세, 소개와 시그니처)이 두 번 나오지 않는다

## 방향

- [ ] 우리 시안과 우리 색이 없다(`anchoring` 이 "보여 주지 않는다"일 때)
- [ ] 제약이 단정형이다. "어렵다면 \~만이라도"가 없다
- [ ] 작업자에게 맡기는 것을 맡긴다고 적었다
- [ ] 바깥에 보여도 되는 정체성만 있다. 팀 내부 상징, 바뀔 수 있는 운영 숫자가 없다
- [ ] 업종 용어를 풀었거나 뺐다

## 결과물 상세

- [ ] 결과물마다 로고 자리를 비운 목업이 있다
- [ ] 규격 예시가 요구한 조합을 빠짐없이 적었다(형태 x 색 같은 표)
- [ ] 빈칸이 이름 붙은 회색 칸이고 밑줄이 아니다
- [ ] 설명 없이는 읽히지 않는 관행 용어(사용 비율, 명도 대비, 별색, 안전 영역)가 없다
- [ ] 진행 순서처럼 이어서 읽을 것은 문장, 나란한 독립 항목은 목록, 찾아볼 값은 표다

## 어조

- [ ] "\~해야 합니다", "\~해도 됩니다", "확인받기", "\~할 것"이 없다
- [ ] 요청이 "부탁드립니다", "\~면 좋겠습니다", "함께 정하겠습니다"로 쓰였다
- [ ] 마지막이 조율 환영과 감사로 닫히고, 후속 계약 이야기를 꺼내지 않았다
