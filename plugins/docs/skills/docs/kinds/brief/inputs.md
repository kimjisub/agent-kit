# brief: 작성 전 선행 재료

## 결정 공란

- [ ] [structure.md](structure.md#결정-공란) 의 결정 공란(contract-source, anchoring, fee-scale)을 사용자와 모두 정했다

## 정본 문서

- [ ] 서명한 계약서가 있으면 받아 결과물 목록, 번호, 일정, 비용 조건, 권리 귀속을 뽑았다
- [ ] 공고를 냈다면 공고 문구를 받아 결과물 이름과 태도를 맞출 준비를 했다
- [ ] 작업자와 나눈 대화(첫 인사, 일정 안내)에서 이미 전한 말을 알고 있다. 같은 말을 문서에 반복할지 정했다

## 방향

- [ ] 원하는 인상과 피하고 싶은 인상을 사용자의 말로 받았다
- [ ] 핵심 글자, 피할 색 같은 제약을 받았다
- [ ] 외부 레퍼런스를 사용자가 골랐거나 고른 갈래가 있다
- [ ] 회사를 떠올리게 하는 말(이름의 뜻, 가치)을 회사 문서에서 찾았고, 바깥에 보여도 되는 것만 골랐다

## 규격

- [ ] 결과물이 쓰일 자리(명함, 웹사이트, 앱 아이콘, 프로필 등)와 가장 작은 크기를 안다
- [ ] 파일 형식의 기준(계약서가 정했으면 그것)을 안다

## 대가

- [ ] 계약 금액에 맞는 작업량인지 사용자와 확인했다. 넘치는 요구는 우리가 하거나 후속으로 돌렸다
