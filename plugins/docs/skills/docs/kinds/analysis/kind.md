# analysis: 분석, 조사 보고서

대화, 조사, 실측으로 알아낸 것을 **구조적으로 다듬어 기록하고 공유**하는 문서다. "무엇을 어떤 근거로 알아냈는가"를 남긴다. 데이터, 시장, 사용자, 경쟁사를 조사하고 분석한 결과를 외부에 공유할 수 있는 형태로 굳힌다.

## 쓰는 자리

- 특정 시장의 규모와 성장률, 주요 참여자 조사
- SaaS 도입 전 후보 제품 비교와 사용 로그 분석
- 경쟁사 제품, 가격, 조직 현황 조사
- 운영 지표의 이상 원인 분석(유입 감소, 이탈 증가 등)
- AI 와 함께 탐색한 사실을 외부 공유용으로 정제

## 다른 종류와의 차이

| 종류 | 핵심 질문 | 목적 |
|---|---|---|
| **analysis** | "무엇을 확인했나?" | 사실과 근거를 기록하고 공유 |
| proposal | "맡겨 달라" | 설득, 제안 |
| quotation | "얼마인가?" | 금액과 조건 합의 |

조사 결과를 근거로 무엇을 하자고 설득하는 단계로 넘어가면 proposal 이다.

## 이 폴더 구성

| 파일 | 담는 내용 |
|---|---|
| `kind.md` | 이 문서. 정체성, 다른 종류와의 차이, 레이아웃별 차이 |
| [structure.md](structure.md) | 권장 본문 흐름, L1/L2/L3 깊이 가이드, 결정 공란, 절별 컴포넌트, 표지 변수, 호출 예시 |
| [inputs.md](inputs.md) | 작성 전에 준비할 재료와 입력 체크리스트 |
| [review.md](review.md) | 내용과 문체 검증 체크리스트(근거, 출처, 한계, 톤) |

문체의 베이스는 `brands/<brand>/voice.md`, 표현(컴포넌트, 쪽, 표지)은 고른 레이아웃의 `layouts/<layout>/layout.md` 다. 이 폴더는 analysis 에서 달라지는 내용만 적는다.

## 레이아웃별 차이

| 레이아웃 | 언제 | 달라지는 점 |
|---|---|---|
| `a4`(기본) | 읽고 보관하는 보고서 | [structure.md](structure.md) 의 흐름 그대로. 깊이 계층화는 본문과 부록으로 가른다 |
| `deck` | 발표로 공유하는 결과 보고 | 핵심 요약이 첫 슬라이드 한 장, 발견 하나가 슬라이드 한 장(수치 카드나 표 하나와 한 줄 결론)이 된다. 방법과 한계는 한두 장으로 줄이고, L2/L3 상세는 슬라이드가 아니라 a4 부록 문서로 따로 뽑는다 |

deck 의 슬라이드 규칙(한 장 한 메시지, 캔버스, 컴포넌트)은 `layouts/deck/layout.md` 에 있다.
