# analysis: 내용 구조 가이드

## 권장 본문 흐름

| 절 | 내용 | 쓰는 컴포넌트 |
|---|---|---|
| 1. 핵심 요약 | 결론을 첫머리에. 바쁜 독자는 여기만 읽어도 된다 | `summary`(라벨 "핵심 요약"), `metrics` |
| 2. 배경, 목적 | 무엇을 왜 분석했나 | 문단 |
| 3. 방법, 데이터 출처 | 어떻게 알아냈나(재현 가능하게) | 표, `note` |
| 4. 발견 사항 | 핵심 결과 | 표, 수치, `finding`, `metrics` |
| 5. 검증, 한계 | 어떻게 검증했고 무엇이 불확실한가 | `note`, 문단 |
| 6. 결론, 다음 단계 | 발견에서 도출한 결론과 시사점 | 문단, 목록 |
| 부록 | L2/L3 독자용 상세 | 표, `pre` |

### 절별 컴포넌트 배치

- `summary` 는 문서당 하나, 1절 첫머리에 둔다. 여러 절에 나눠 두지 않는다.
- `finding` 은 발견 사항 절에 모으고, 강조할 인사이트 한 건에 하나씩, 절당 2\~3개까지 둔다. 각 `finding` 은 근거 표나 수치를 가리킨다.
- `metrics` 는 요약과 발견 사항에서 핵심 수치를 보일 때 쓴다. 라벨에 기준 시점이나 "추정"을 붙인다.
- `chart` 는 추세, 분포, 비중이 발견 사항의 근거일 때 쓴다. 차트 중심의 데이터 리포트(지표 추이 보고, 캠페인 성과)도 이 종류로 쓰고, 절마다 차트 하나와 해설 한 줄을 짝으로 둔다. 그리는 법은 [a4 charts.md](../../layouts/a4/charts.md).
- `note` 는 해당 수치나 주장 바로 아래에 검증 근거, 표본, 한계를 적는다.

## 데이터 깊이 가이드

같은 분석이라도 **독자에 따라 담는 정보의 깊이를 달리한다.** 이 종류의 핵심이다. 독자를 먼저 파악하고 아래 레벨을 골라 본문을 구성한다.

이 종류는 독자와 깊이를 고정하지 않는다. 작성 전에 아래 결정 공란을 사용자와 해소한다(문법: [conventions.md](../../conventions.md#결정-공란ask)).

@ASK(target-audience): 이 분석 보고서를 누가 읽나요? [경영진, 의사결정자 | 협업 실무자 | 분석가, 검증자 | 혼합]
> 독자에 따라 깊이 레벨과 결론 위치가 달라집니다. 앞선 인터뷰에서 이미 정해졌으면 그 답을 씁니다.

@ASK(depth-level): 본문 기본 깊이는? [L1 요약형 | L2 실무형 | L3 재현형]
> 위 독자에서 자명하면 그대로 확정하고, 혼합 독자면 L1 본문에 L2/L3 부록을 붙이는 계층화로 갑니다.

| 깊이 | 대상 독자 | 담는 것 | 빼는 것 |
|---|---|---|---|
| **L1 요약형** | 경영진, 의사결정자 | 핵심 요약, 결론과 시사점, 지표 카드 몇 개 | 방법론, 원시 데이터, 검증 과정 |
| **L2 실무형** | 협업 실무자, PM, 운영 담당 | L1 + 발견 사항, 근거 표와 수치, 한계 | 재현 절차, 전체 덤프, 도구 상세 |
| **L3 재현형** | 분석가, 검증자 | L2 + 방법, 쿼리, 도구, 원시 데이터 샘플, 검증 로직, 재현 절차 | (생략 없음) |

### 깊이 선택 규칙

- 독자가 한 부류면 그 레벨에 맞춰 간결하게 쓴다.
- 독자가 섞여 있으면 **L1 을 첫 쪽(핵심 요약)에, L2/L3 를 뒤 절과 부록에** 둔다. L2/L3 내용을 본문 중간에 섞지 않는다.
- 부록을 두면 본문에서 "부록 A 참조"처럼 명시적으로 가리킨다.
- 수치와 주장에는 **출처와 검증 여부**를 함께 적는다. 검증 안 된 추정은 "추정"이라 표기한다.
- 데이터 품질 문제(이상치, 결측, 오류)는 숨기지 않고 "한계" 절에 드러낸다.

### 깊이별 부록 계층화 예시

```
본문 (L1 핵심 요약 + 발견 사항)
|-- 부록 A. 방법과 데이터 출처 (L2 독자용)
|-- 부록 B. 상세 데이터 표 (L2 독자용)
`-- 부록 C. 쿼리, 도구, 재현 절차 (L3 독자용)
```

## 수치 표기

- 지표 숫자에 천 단위 구분자(1,234)를 쓴다.
- 값에 단위를 붙이거나 라벨에 단위를 적는다.
- 추정은 "추정" 또는 "약 N" 으로 적고 실측과 섞지 않는다.

## 표지 변수

```bash
KIND=analysis [LAYOUT=a4] [BRAND=<brand>] <변수...> bash scripts/build.sh scaffold <문서 폴더>
```

표지 메타 라벨은 [kind.md](kind.md) 의 `labels` 가 정한다. 변수와 라벨의 짝은 이렇다.

| 변수 | 표지 라벨 | 예시 |
|---|---|---|
| `CATEGORY` | 카테고리 | 비우면 `ANALYSIS`. 한글을 곁들이려면 `ANALYSIS, 분석 보고서` |
| `DOC_TITLE` | 탭 제목 | `국내 B2B 협업툴 시장 분석 보고서` |
| `DOC_HEADER` | 러닝 헤더 | `B2B 협업툴 시장 분석` |
| `SUBTITLE` | 부제 | `시장 규모와 도입 동향` |
| `COVER_TITLE` | 메인 제목(`<br>` 가능) | `국내 B2B 협업툴<br>시장 분석 보고서` |
| `COVER_FROM` | 작성 | `전략기획팀`. 비우면 브랜드 기본값 |
| `COVER_TO` | 공유 | `경영진, 내부 공유` |
| `COVER_TARGET` | 분석대상 | `국내 B2B 협업툴 시장` |
| `COVER_PERIOD` | 기간 | `2026-05 ~ 2026-06` |
| `COVER_OWNER` | 작성자 | `홍길동`. 비우면 줄이 사라짐 |
| `COVER_CONFIDENTIAL` | 기밀 조항 본문 | 비우면 브랜드 기본값, 브랜드도 비면 상자가 사라짐 |

값을 비운 표지 줄은 표지에서 사라진다.

## 호출 예시

```bash
# 1) 표지를 포함한 빈 번들 생성
DOC_TITLE="국내 B2B 협업툴 시장 분석 보고서" \
SUBTITLE="시장 규모와 도입 동향" \
DOC_HEADER="B2B 협업툴 시장 분석" \
COVER_TITLE="국내 B2B 협업툴<br>시장 분석 보고서" \
COVER_TARGET="국내 B2B 협업툴 시장" \
COVER_TO="경영진, 내부 공유" \
COVER_PERIOD="2026-05 ~ 2026-06" \
KIND=analysis bash <skill-dir>/scripts/build.sh scaffold "/path/to/시장분석"

# 2) /path/to/시장분석/시장분석.html 의 본문 자리에 본문 HTML 을 직접 쓴다
#    깊이 레벨(L1/L2/L3)을 정한 뒤 권장 흐름대로 채운다

# 3) 완성된 html -> pdf
bash <skill-dir>/scripts/build.sh pdf "/path/to/시장분석"
```

회사 양식이 필요하면 `BRAND=<id>`, 발표용이면 `LAYOUT=deck` 을 붙인다. 컴포넌트 마크업은 [a4 layout.md](../../layouts/a4/layout.md#컴포넌트-카탈로그) 에 있다.
