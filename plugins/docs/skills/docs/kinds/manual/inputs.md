# manual: 작성 전 선행 재료

아래가 없으면 운영자가 따라 할 수 있는 설명서가 나오지 않는다. 작성 전에 확인하고, 빠진 것은 제품 담당자에게 먼저 묻는다.

## 결정 공란

- [ ] [structure.md](structure.md#결정-공란) 의 결정 공란(reader-level, support-contact, capture-source)을 사용자와 모두 정했다

## 제품

- [ ] 대상 제품의 이름과 버전이 정해졌다
- [ ] 제품이 하는 일을 한 문장으로 쓸 수 있다
- [ ] 실제 화면(또는 캡처)을 보고 버튼과 메뉴 이름을 확인했다

## 시작과 설정

- [ ] 켜는 방법과 끄는 방법을 순서대로 안다
- [ ] 최초 설정 항목과 각 기본값을 안다
- [ ] 운영자가 바꾸면 안 되는 설정을 안다
- [ ] 되돌릴 수 없는 동작(초기화, 삭제)을 파악했다

## 평소 운영

- [ ] 무인으로 도는 부분과 사람이 확인할 부분을 나눌 수 있다
- [ ] 확인 주기와 정상 상태의 기준(표시등 색, 수치 범위)을 안다

## 문제 대응

- [ ] 자주 나는 증상 목록과 각 원인, 조치를 확보했다(지원 이력, 개발자 인터뷰 등)
- [ ] 운영자가 할 수 있는 조치와 문의해야 하는 경우를 가를 수 있다
- [ ] 문의할 때 함께 보낼 정보(캡처, 발생 시각, 오류 문구)를 정했다

## 지원

- [ ] 문의처, 응답 시간, 지원 범위를 받았다(`support-contact`)

## 표지

- [ ] 제공, 대상 제품, 대상 독자, 버전 값이 정해졌다. 정하지 않은 것은 비워 두면 표지에서 사라진다
