# manual: 내용과 문체 검증 체크리스트

표현(컴포넌트, 표, 쪽 경계, 표지 렌더) 검증은 고른 레이아웃의 `layouts/<layout>/review.md` 다(a4 는 [a4 review.md](../../layouts/a4/review.md)). 문체의 베이스는 `brands/<brand>/voice.md` 다. 아래는 manual 의 내용과 톤 항목이다.

## 사용자 관점

- [ ] 빌드, 코드, 내부 구현 설명이 없다(`reader-level` 이 개발자여도 구현은 spec 으로 넘겼다)
- [ ] 버튼과 메뉴 이름이 화면 표기와 같고 굵게 쓰였다(예: **저장** 버튼)
- [ ] 전문 용어를 처음 쓸 때 풀었다

## 흐름

- [ ] 1절 첫 문장이 "무엇을 하는 프로그램인지"다
- [ ] `summary` 가 1절에 하나만 있다
- [ ] 켜기, 최초 설정, 화면, 설정, 평소 운영, 운영 도구, 문제 대응, 자주 묻는 질문, 문의 순서를 따른다(없는 절은 뺐다)
- [ ] 처음 쓰는 사람이 1절부터 순서대로 따라 하면 최초 설정까지 끝난다

## 절차

- [ ] 절차가 `step` 으로 쓰였고 한 단계에 한 동작이다
- [ ] 단계마다 "되었는지 확인하는 방법"(표시등, 화면 문구)이 있다
- [ ] 되돌릴 수 없는 동작 앞에 `warn` 이 있고 결과를 적었다
- [ ] `tip` 과 `warn` 을 구분해 썼다. `warn` 은 되돌릴 수 없거나 장애로 이어지는 곳에만 있다

## 화면과 설정

- [ ] 상태 표시와 수치에 정상 범위와 이상일 때의 뜻이 있다. `metrics` 라벨에 정상 범위가 있다
- [ ] 설정 표에 기본값 열이 있고, 항목마다 바꾸면 달라지는 것이 있다
- [ ] 바꾸면 안 되는 설정이 표시됐다
- [ ] 화면 캡처 아래에 무엇을 보라는지 한 줄이 있다

## 문제 대응

- [ ] 문제 대응 절이 있고, 표가 증상, 원인, 조치 3열이다
- [ ] 증상이 운영자가 보는 말로 적혔다
- [ ] 조치가 운영자가 할 수 있는 동작이다
- [ ] 조치로 해결되지 않을 때 문의 방법과 함께 보낼 정보가 있다

## 지원

- [ ] 문의처와 응답 시간이 `support-contact` 답대로 적혔다
- [ ] 결정 공란(`@ASK`)이 남은 채 본문을 쓰지 않았다

## 표지 값

- [ ] `CATEGORY` 가 `USER MANUAL` 이나 `USER MANUAL / ...` 형식이다
- [ ] 버전(`COVER_PERIOD`)이 제품 버전과 맞다

## 톤: 쉽고 짧게

manual 은 voice.md 기조에서 설득을 빼고 안내만 남긴다. 운영자가 한 번 읽고 따라 할 수 있어야 한다.

- [ ] 문장이 짧다. 한 문장에 한 동작이다
- [ ] 명령형이 아니라 `~합니다` 로 안내한다("누르십시오" 대신 "누릅니다")
- [ ] 제품을 자랑하는 문장이 없다
