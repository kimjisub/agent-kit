# manual: 사용 설명서

제품이나 프로그램을 **실제로 쓰는 사람(운영자)** 이 보고 따라 할 수 있게 쓰는 안내서다. "어떻게 켜고, 무엇을 보고, 문제가 생기면 어떻게 하나"가 본질이다.

## 쓰는 자리

- 납품하거나 배포하는 프로그램, 장비의 운영자용 사용법을 정리할 때
- 개발자가 아닌 담당자가 보고 스스로 운영하고 1차 대응까지 하게 할 때
- 예: 매장 재고 관리 프로그램 사용 설명서, 출입 관리 단말 운영 안내서, 사내 배포 도구 사용법

## 다른 종류와의 차이

| 종류 | 핵심 질문 | 목적 |
|---|---|---|
| **manual** | "어떻게 쓰고, 문제가 생기면 어떻게 하나?" | 사용 안내. 운영자가 따라 한다 |
| spec | "무엇을 어떤 형식으로 주고받나?" | 구현자를 위한 규격 |
| handbook | "우리는 어떻게 일하나?" | 조직 안의 규칙과 절차 |
| analysis | "무엇을 확인했나?" | 사실과 근거 기록 |

설치 담당 엔지니어용 내부 구현 설명은 manual 이 아니라 spec 이나 별도 기술 문서로 쓴다.

## 이 폴더 구성

| 파일 | 역할 |
|---|---|
| `kind.md` | 이 문서. 정체성, 다른 종류와의 차이, 레이아웃별 차이 |
| [structure.md](structure.md) | 작성 원칙, 권장 본문 흐름, 절별 컴포넌트와 표 패턴, 결정 공란, 표지 변수, 호출 예시 |
| [inputs.md](inputs.md) | 작성 전에 갖춰야 할 재료 체크리스트 |
| [review.md](review.md) | 내용과 문체 검증 체크리스트 |

문체의 베이스는 `brands/<brand>/voice.md`, 표현(컴포넌트, 쪽, 표지)은 고른 레이아웃의 `layouts/<layout>/layout.md` 다. 이 폴더는 manual 에서 달라지는 내용만 적는다.

## 레이아웃별 차이

| 레이아웃 | 언제 | 달라지는 점 |
|---|---|---|
| `a4`(기본) | 납품물로 인쇄하거나 PDF 로 건네는 설명서 | [structure.md](structure.md) 의 흐름 그대로. 절이 `h1` 이라 새 쪽에서 시작한다 |
| `web` | 운영자가 화면에 띄워 두고 필요한 대목을 찾아 읽는 설명서 | 절이 장이 되어 옆 목차에 뜬다. 흐름과 컴포넌트 이름은 같고, 문제 대응과 자주 묻는 질문 절을 목차에서 바로 찾게 절 제목을 짧게 쓴다. 인쇄하면 장마다 새 쪽으로 끊긴다 |

web 의 장 구성과 컴포넌트는 `layouts/web/layout.md` 에 있다. 거기에 없는 컴포넌트는 그 카탈로그의 같은 뜻 컴포넌트로 바꿔 쓴다.
