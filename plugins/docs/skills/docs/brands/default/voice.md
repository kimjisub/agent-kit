# 기본 문체 (brands/default)

모든 내용 종류가 상속하는 문체 기준입니다. 종류는 필요한 부분만 자기 `structure.md` 와 `review.md` 에서 덮어씁니다(견적서는 더 건조하게, 제안서는 더 설득적으로). 회사 브랜드를 따로 두면 그 브랜드의 `voice.md` 가 이 파일을 대신하고, 회사 용어집은 그 브랜드 폴더에 둡니다.

## 읽는 사람 우선

문서는 대개 필요한 한 대목을 찾으려고 열립니다. 결론을 앞에 두고 근거를 뒤에 붙이면 읽는 사람이 뒤를 읽을지 스스로 정합니다.

1. **결론 먼저.** 절과 상자마다 첫 문장에 결론을 씁니다.
2. **본문은 `~입니다`체.** 표 셀과 불릿의 짧은 항목은 명사형이나 `~한다`로 끝내도 됩니다. 한 문서 안에서 섞지 않습니다.
3. **동작과 대상과 수치로.** "상태가 흩어져 있다" 대신 "같은 값을 세 곳이 각자 들고 있다"로 씁니다.
4. **숫자에는 단위와 기준 시점과 출처.** "많음" 대신 "1,234건(2026-05 기준, 운영 DB)". 추정이면 추정이라고 씁니다.
5. **아는 것과 모르는 것을 가릅니다.** 확인하지 않은 것은 단정하지 않고, 불리한 사실도 숨기지 않습니다.
6. **주어와 목적어를 씁니다.** 줄여야 하면 문장을 압축하지 말고 곁가지 주제를 통째로 뺍니다.

## 문자: 키보드로 칠 수 있는 것만

- 쓰지 않습니다: 엠대시, 엔대시, 가운뎃점, 화살표 기호, 말줄임표 기호, 곡선 따옴표, 불릿 기호, 원문자, 이모지.
- 대신: 대시는 쉼표나 괄호로, 가운뎃점은 쉼표로, 화살표는 `->` 나 말로("490만에서 700만으로"), 따옴표는 곧은 따옴표로 씁니다.
- 예외는 코드 블록과 남의 원문을 그대로 옮기는 인용입니다.

## 뺄 것

- 의미 부풀리기("중요한 전환점", "근본적으로 바꾼다"). 논증한 범위 안에서만 주장합니다.
- 섹션 안내 문장("결론적으로", "주목할 점은"). 다음 내용으로 바로 넘어갑니다.
- 억지 삼단 나열과 항목 수 선언. 항목이 실제로 몇 개인지가 목록 길이를 정합니다.
- 같은 대상을 여러 이름으로 돌려 부르기. 한 개념은 한 단어로 부릅니다.
- 확신 부사와 형용사("명백히", "견고한", "혁신적인"). 근거를 대신 씁니다.
- "X 가 아니라 Y" 대구와 문단 끝 경구.
- 연결어미 뒤 쉼표와 명사구 연쇄("설정의 변경을 통한 성능의 개선" 대신 "설정을 바꿔 성능을 높인다").
- 편집 흔적. 고칠 때는 최종 상태만 남기고 "(수정)" 같은 표시를 두지 않습니다.

## 예

- 씁니다: "지난달 문의는 1,234건이고 그중 18% 가 재문의입니다."
- 안 씁니다: "문의가 매우 활발하며 고객의 관심이 뜨겁습니다." (형용사만 있고 근거가 없음)
- 씁니다: "이 추정은 표본이 12건이라 검증되지 않았습니다." (한계를 드러냄)
