# 규약: 결정 공란과 문서 폴더

## 결정 공란(@ASK)

명세가 일부러 비워 둔 결정입니다. "이 문서에서는 정해지지 않았고, 쓸 때 사용자와 정해야 한다"는 표시입니다. 명세를 쓰는 사람은 "물어볼 것"을 산문으로 풀지 않고 한 줄로 남깁니다.

```
@ASK(slot-id): 질문 [옵션A | 옵션B | 옵션C]
> 부연 설명(선택)
```

- `slot-id` 는 영문 kebab-case 입니다. 같은 id 는 한 번만 묻습니다.
- `[옵션]` 이 있으면 선택형, 없으면 자유 입력으로 묻습니다.
- 두는 곳: `kinds/<kind>/*.md`, `layouts/<layout>/*.md`, `brands/<brand>/*.md`. HTML 과 CSS 에는 두지 않습니다(거기는 표지 치환 자리 `__VAR__` 의 영역입니다).

처리 순서는 이렇습니다.

1. `bash scripts/build.sh ask <kind>` 로 목록을 받는다(`LAYOUT`, `BRAND` 를 주면 그 폴더도 본다).
2. 슬롯마다 사용자에게 묻는다. 목적과 독자 인터뷰에서 이미 답이 나온 슬롯은 그 값으로 정한다.
3. 모든 슬롯이 풀리기 전에는 본문을 쓰지 않는다.
4. 정한 값은 표지 변수와 본문에 반영한다.

표지에 들어갈 **값**이 비었으면 표지 변수로, 문서를 **어떻게 쓸지**가 비었으면 `@ASK` 로 둡니다.

## 문서 폴더

문서 하나는 폴더 하나입니다. 폴더 이름이 문서 이름이고 안의 파일 이름도 그것을 따릅니다.

```
<문서명>/
  draft.md          초안. 목적, 독자, 핵심 메시지, 흐름. 자유롭게 고친다
  <문서명>.html     정본. 표지(scaffold)와 본문(직접 작성). 고치는 곳은 여기
  <문서명>.pdf      결과. 직접 고치지 않는다
  assets/           그림과 캡처. src="assets/..." 로 건다
```

- 내용 방향이 바뀌면 `draft.md` 부터, 표현과 배치만 바뀌면 `.html` 만 고칩니다.
- PDF 는 언제나 `.html` 을 고쳐 `bash scripts/build.sh pdf <문서 폴더>` 로 다시 만듭니다.
- `scaffold <문서 폴더>` 가 폴더, `assets/`, `draft.md`(없을 때만), `<문서명>.html` 셸을 한 번에 만듭니다.
